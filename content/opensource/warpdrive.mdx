## 한눈에 보는 프로젝트

[WarpDrive](https://github.com/warp-drive-data/warp-drive)는 웹 애플리케이션에서 모델, 데이터 캐시, 반응형 업데이트를 다루기 위한 데이터 라이브러리입니다. Ember Data의 경험을 바탕으로 발전했지만, 공식 README는 특정 UI 프레임워크에 종속되지 않고 여러 프레임워크에서 사용할 수 있는 범용 데이터 레이어를 지향한다고 설명합니다.

프로젝트가 해결하려는 문제는 API 응답을 모델로 표현하고, 로딩·캐시·변경 상태를 UI와 일관되게 연결하는 일입니다. 애플리케이션마다 데이터 조회, 캐싱, 타입 정의를 별도로 구성하면 중복 코드가 늘어나기 때문에 WarpDrive는 재사용할 수 있는 모델과 캐시 인터페이스를 제공합니다.

## 이해에 필요한 핵심 개념

### 1. 모델과 타입 안전성

WarpDrive는 데이터 모델을 정의하고 이를 애플리케이션 코드에서 타입 안전하게 다룰 수 있도록 관련 API를 제공합니다. 저장소의 `packages/model/src/hooks.ts`는 기존 경로와의 호환성을 위해 레거시 모델 API를 재수출하는 예입니다.

```typescript
// packages/model/src/hooks.ts
export {
  instantiateRecord,
  teardownRecord,
  modelFor,
  buildSchema,
} from '@warp-drive/legacy/model';
```

이 코드는 새 구현을 직접 보여주는 예제라기보다 기존 모듈 경로를 유지하는 호환성 계층의 예시입니다. 따라서 이 파일만 보고 모델의 전체 생성·저장 흐름을 설명해서는 안 됩니다.

### 2. 캐시 인터페이스와 반응형 업데이트

저장소에는 캐시의 동작과 변경 유형을 정의하는 타입이 있으며, 핵심 캐시 구현은 별도 패키지에서 관리됩니다. UI 프레임워크와 데이터 계층을 분리하면 데이터 변경을 화면에 전달하는 방법을 프레임워크별 어댑터나 연동 계층에서 조정할 수 있습니다.

```typescript
// packages/core-types/src/cache.ts
export type * from '@warp-drive/core/types/cache';
```

이 예제 역시 타입 정의의 재수출입니다. 실제 캐시 상태가 어떻게 갱신되고 구독자에게 전달되는지는 핵심 패키지 구현과 공식 가이드에서 확인해야 합니다.

### 3. 어댑터와 API 연결

WarpDrive는 애플리케이션이 사용하는 API 형식에 맞춰 어댑터를 구성할 수 있습니다. 저장소의 JSON:API 어댑터 파일은 기존 레거시 구현을 재수출하는 구조를 보여줍니다.

```typescript
// packages/adapter/src/json-api.ts
export {
  JSONAPIAdapter as default,
} from '@warp-drive/legacy/adapter/json-api';
```

이 예제는 JSON:API 어댑터의 호환 경로를 보여주는 것이며, GraphQL이나 임의의 REST API를 같은 어댑터가 자동으로 처리한다는 뜻은 아닙니다. 실제 API 형식에 맞는 설정과 어댑터 사용법은 각 공식 가이드를 확인해야 합니다.

## 저장소 구조

저장소에서 확인되는 주요 영역은 다음과 같습니다.

- `packages/`: 모델, 어댑터, 캐시 타입, 빌드 설정 등 라이브러리 패키지
- `warp-drive-packages/`: 문서화와 실험적 기능 등 부가 패키지
- `docs-viewer/`: 문서 사이트의 소스
- `.github/workflows/`: 빌드, 테스트, 릴리스 등 자동화 설정

루트의 `package.json`은 pnpm과 Turborepo를 사용해 여러 패키지의 빌드와 검사를 관리합니다. 따라서 단일 패키지 설치와 전체 모노레포 개발 환경을 구분해서 이해하는 것이 좋습니다.

## 대안과 비교할 때의 차이

WarpDrive를 Redux나 Zustand와 단순히 일대일로 비교하는 것은 정확하지 않습니다. Redux와 Zustand는 주로 애플리케이션 상태를 관리하는 도구이고, WarpDrive는 서버 데이터의 모델링과 캐시, API 연동에 더 초점을 둡니다.

| 도구 | 주된 관심사 | 고려할 점 |
|---|---|---|
| Redux | 애플리케이션 상태와 이벤트 흐름 | 명시적인 상태 전이와 풍부한 미들웨어 생태계 |
| Zustand | 간단한 전역 상태 관리 | 서버 데이터 모델과 캐시는 별도 설계가 필요 |
| WarpDrive | 모델, API 데이터, 캐시, 반응형 변경 | 프로젝트의 데이터 모델과 프레임워크 연결 방식 학습 필요 |

따라서 기존 상태 관리 라이브러리를 무조건 대체하기보다는, 서버에서 가져오는 데이터의 모델과 캐시를 일관되게 다루어야 하는 애플리케이션에서 검토하는 편이 적절합니다.

## 라이선스와 도입 시 확인할 점

저장소의 `LICENSE.md`에는 MIT 라이선스가 명시되어 있습니다. 실제 도입 전에는 사용하려는 패키지의 라이선스와 버전, 프레임워크 호환성, 마이그레이션 가이드를 각각 확인해야 합니다.

특히 저장소가 Ember Data에서 발전한 이력이 있으므로, 프레임워크 독립성을 제공한다는 설명과 기존 Ember 애플리케이션의 호환 API를 구분해서 살펴보는 것이 좋습니다. 일부 모듈은 레거시 경로를 유지하기 위한 재수출일 수 있으므로, 새 프로젝트에서는 최신 공식 문서가 권장하는 import 경로를 우선해야 합니다.

## 한계와 추천 대상

**고려할 점**
- 모델, 캐시, 어댑터 등 데이터 레이어의 개념을 별도로 학습해야 합니다.
- 레거시 재수출 경로와 최신 패키지 경로가 함께 존재할 수 있어 버전별 문서 확인이 필요합니다.
- 프레임워크 독립성을 지향하더라도 실제 통합 방식과 지원 범위는 사용하는 프레임워크 및 패키지 버전에 따라 확인해야 합니다.

**검토할 만한 상황**
- 서버에서 가져오는 데이터의 모델과 캐시를 한 곳에서 관리하고 싶은 경우
- 타입 안전성과 반응형 데이터 변경을 함께 고려하는 웹 애플리케이션
- Ember Data 기반 프로젝트를 점진적으로 현대화하려는 팀

WarpDrive의 핵심은 범용 상태 관리 도구가 되는 것이 아니라, 웹 애플리케이션의 데이터 모델과 캐시를 일관되게 다루는 데 있습니다. 도입 여부는 프로젝트의 데이터 흐름과 프레임워크 구성에 맞춰 판단해야 합니다.
