## 로컬 배포의 필요성과 양자화의 역할

최근 바이오 의료 자연어 처리(BioNLP) 분야에서 대형 언어 모델(LLM)의 활용도가 높아지고 있습니다. 하지만 모델의 규모와 컴퓨팅 요구 사항이 커지면서, 민감한 환자 정보를 다루는 의료 환경에서는 클라우드에 모델을 올리기 어려운 경우가 많습니다. 데이터 보안과 개인정보 보호를 위해 로컬에서 직접 모델을 실행해야 하는 경우가 많기 때문입니다.

이때 고려할 수 있는 기술이 모델 양자화입니다. 양자화란 모델의 가중치(Weight)가 사용하는 숫자의 정밀도를 낮추는 작업입니다. 기존에는 32비트나 16비트 부동소수점으로 표현하던 가중치를 8비트나 4비트로 줄이죠. 이렇게 하면 모델이 차지하는 메모리 용량이 크게 줄어듭니다. 결과적으로 고성능 데이터센터용 GPU가 없더라도, VRAM이 충분한 소비자용 그래픽 카드나 로컬 서버에서 대형 모델을 돌려볼 수 있게 됩니다.

## 양자화가 바이오 NLP 성능에 미치는 영향

이 연구에서는 일반 목적의 LLM 12개와 바이오 의료 전문 LLM 4개를 대상으로 다양한 양자화 설정이 성능에 어떤 영향을 미치는지 살펴봅니다. 평가 작업은 이름 추출(NER), 관계 추출(RE), 다중 라벨 분류(MLC), 질문 답변(QA) 등 바이오 의료 문서를 다루는 주요 네 가지 작업입니다.

연구진은 Transformers와 BitsAndBytes 라이브러리를 이용해 4비트와 8비트 가중치 양자화(W4A16, W8A16) 실험을 진행했습니다. 그 결과, 양자화를 하면 GPU 메모리 사용량이 눈에 띄게 줄어드는 것을 확인할 수 있었습니다. 성능의 경우, 작업과 모델에 따라 차이가 있었지만 전반적으로 양자화 전과 비슷한 수준을 유지하는 경우가 많았습니다. 다만, 메모리를 줄이는 대신 응답 시간(Latency)이 길어지는 현상은 피할 수 없었습니다.

## 전문 바이오 의료 모델의 특수성

전문적인 바이오 의료 데이터를 학습한 모델이라고 해서 무조건 양자화에 강건한 것은 아닙니다. 연구 결과, ClinicalCamel-70B와 같은 전문 모델은 4비트로 낮춰도 성능 저하가 거의 없었습니다. 하지만 HuatuoGPT-o1-70B나 Llama3-Med42-70B 같은 모델의 경우, 8비트로 양자화했을 때 지시 사항 이행 능력이 떨어져서 반복적인 문장을 생성하거나 말이 안 되는 답변을 내놓는 경우가 있었습니다.

이처럼 모델 아키텍처나 학습 방식에 따라 양자화에 취약한 부분이 다를 수 있으므로, 특정 모델을 로컬에 올리기 전에 실제 작업에서 얼마나 성능이 떨어지는지 반드시 테스트해 봐야 합니다.

## 배포 환경에 따른 양자화 도구 선택

단순히 모델을 실행하는 것뿐만 아니라, 여러 사용자가 동시에 모델을 요청하는 서버 환경에서는 또 다른 고려 사항이 생깁니다. 연구진은 vLLM 같은 추론 엔진에서 널리 쓰이는 AWQ, GPTQ, FP8 체크포인트를 함께 평가했습니다.

서버 환경에서는 GPU 메모리를 모델 가중치뿐만 아니라 키-값 캐시(KV Cache)를 저장하는 데도 많이 쓰게 됩니다. 따라서 일반적인 양자화 실험과는 다른 결과가 나오기도 합니다. 실험 결과, 모든 작업에 있어서 무조건 가장 좋은 단일 양자화 방식은 없었습니다. 모델의 규모나 사용 중인 추론 엔진의 특성에 따라 AWQ, GPTQ, FP8 중 어느 것이 더 적합한지 평가해 봐야 합니다.

또한, 양자화를 한다고 해서 항상 무결한 답변만 나오는 것은 아닙니다. 전체 실험 결과에서 양자화 수준과 무관하게 일정 비율의 비정상적인 출력이나 반복 생성이 발생했습니다. 따라서 단순히 점수만 보지 말고, 모델이 실제 데이터를 출력할 때 유효한 형식인지도 함께 모니터링해야 합니다.
