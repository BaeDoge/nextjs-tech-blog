## 현상

재귀 함수 호출 시 `RecursionError: maximum recursion depth exceeded` 오류가 발생하며 프로그램이 종료됩니다.
기본 재귀 깊이 제한은 보통 1000 수준으로, 이를 초과하는 깊이로 호출하면 이 에러가 발생합니다.

```python
def recursive_function(n, total):
    if n < 1:
        return total
    else:
        return recursive_function(n - 1, total + n)

# 기본 제한(1000)을 초과하여 에러 재현
c = 1001
print(recursive_function(c, 0))
```

```text
Traceback (most recent call last):
  File "test.py", line 10, in <module>
    print(recursive_function(c, 0))
  ...
RecursionError: maximum recursion depth exceeded in comparison
```

![현상 스크린샷](/blogs/python-recursionerror-1.jpg)

## 원인

Python은 재귀 호출 시 스택 프레임을 생성하며, 이는 메모리 소모가 크고 스택 오버플로우 위험이 있어 CPython은 재귀 깊이를 제한합니다.
CPython 구현은 꼬리 재귀(Tail Recursion)를 자동으로 최적화하지 않으므로, 재귀가 반복될수록 호출 스택이 계속 쌓입니다.
이러한 설계적 제한으로 인해 임계점을 넘으면 `RecursionError`가 발생하여 실행을 중단시킵니다.

## 해결 방법

`sys` 모듈을 사용하여 재귀 제한 값을 명시적으로 증가시켜 에러를 우회할 수 있습니다.
이 방법은 재귀 함수의 로직을 변경하지 않고 제한만 늘리는 방식입니다.

```python
import sys

# 재귀 제한 확인 (기본값은 보통 1000)
print(sys.getrecursionlimit())

# 재귀 제한 증가 (경고: 스택 오버플로우 위험)
sys.setrecursionlimit(1500)

def recursive_function(n, total):
    if n < 1:
        return total
    else:
        return recursive_function(n - 1, total + n)

c = 1001
print(recursive_function(c, 0))
```

## 다른 해결 방법

재귀를 반복문으로 변환하는 것은 메모리 효율적이며 근본적인 해결책입니다.
함수형 언어의 꼬리 재귀와 유사한 형태를 반복문으로 구현하면 스택 오버플로우 걱정 없이 안전한 실행이 가능합니다.

```python
def iterative_function(n, total):
    while n >= 1:
        total += n
        n -= 1
    return total

c = 1001
print(iterative_function(c, 0))
```

## 추가 참고사항

재귀 제한 증가(`sys.setrecursionlimit`)는 스택 오버플로우로 인해 운영 체제 수준에서 프로그램이 강제 종료될 수 있으므로 위험합니다.
일반적으로 재귀가 필요한 트리 순회 등 특수한 경우를 제외하고는 반복문 사용을 권장합니다.
재귀를 사용할 때는 재귀 깊이가 제한 내에 있는지 반드시 확인하고, 필요 시 제한값을 동적으로 관리하는 것이 좋습니다.
