## 현상

Python의 `requests`로 HTTPS 주소에 접근할 때 다음과 같은 오류가 발생할 수 있습니다.

```text
requests.exceptions.SSLError:
[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed
```

일반적으로 서버 인증서의 체인을 검증할 신뢰할 수 있는 CA 인증서를 찾지 못했다는 의미입니다. 운영체제, Python, requests, 네트워크 프록시의 구성에 따라 실제 원인은 달라질 수 있습니다.

## 원인

대표적인 원인은 다음과 같습니다.

1. `requests`가 사용하는 CA 인증서 묶음이 오래되었거나 정상적으로 설치되지 않았습니다.
2. 회사 프록시가 HTTPS 인증서를 중간에서 교체하지만, 프록시의 사내 CA 인증서가 신뢰 목록에 등록되어 있지 않습니다.
3. 서버가 중간 인증서를 누락했거나, 서버 인증서가 만료·잘못 구성되어 있습니다.
4. 오래된 운영체제나 Python 환경에서 최신 TLS 및 루트 인증서 체계를 제대로 지원하지 못합니다.

`requests`는 기본적으로 `certifi` 패키지의 CA 인증서 묶음을 사용합니다. 따라서 브라우저에서는 연결되는데 Python에서만 실패한다면, 브라우저와 Python이 서로 다른 인증서 저장소를 사용하는지 확인해야 합니다.

## 해결 방법 1. requests의 CA 번들 확인

먼저 requests와 certifi가 실제로 참조하는 CA 파일 경로를 확인합니다.

```python
import requests
import certifi

print("requests CA bundle:", requests.certs.where())
print("certifi CA bundle:", certifi.where())
```

설치된 CA 묶음이 오래되었다면 해당 Python 환경에서 업데이트합니다.

```bash
python -m pip install --upgrade requests certifi
```

프로젝트 전체에서 동일한 CA 인증서를 사용해야 한다면 `REQUESTS_CA_BUNDLE` 환경 변수를 지정할 수 있습니다. 이 변수에는 조직에서 제공한 신뢰할 수 있는 CA 번들 경로를 설정합니다.

```python
import os
import requests

os.environ["REQUESTS_CA_BUNDLE"] = "/path/to/organization-ca-bundle.pem"
response = requests.get("https://google.com")
print(response.status_code)
```

`verify=False`는 서버 인증서 검증을 비활성화해 중간자 공격에 취약해집니다. 문제 해결 방법으로 사용하지 말고, 실제 CA 인증서를 지정해 검증을 유지해야 합니다.

## 추가 참고사항

<Steps>
<Step title="환경 진단">
`ssl.get_default_verify_paths()`를 호출하여 현재 Python이 참조하는 기본 인증서 경로를 확인합니다.
</Step>
<Step title="서버 인증서 확인">
브라우저에서도 같은 주소에 인증서 경고가 발생하는지 확인합니다. 브라우저와 Python의 결과가 다르면 Python의 CA bundle 또는 프록시 인증서 설정을 점검합니다.
</Step>
<Step title="pip 사용 환경 확인">
패키지 설치 중 발생한 오류라면 `pip --cert /path/to/ca-bundle.pem`처럼 신뢰할 CA 인증서 번들을 지정하는 방법을 우선 고려합니다.
</Step>
</Steps>

<Callout type="info" title="참고 사항">
에러 메시지 끝부분의 `_ssl.c` 뒤 숫자는 파이썬 빌드 버전에 따라 다르므로 무시해도 됩니다.
</Callout>

```bash
# Windows CMD
set REQUESTS_CA_BUNDLE=C:\certs\company-ca.pem
```

인증서 파일은 반드시 회사에서 제공한 신뢰할 수 있는 경로로 받아야 합니다. 서버 인증서를 임의로 내려받아 신뢰 목록에 넣는 것과 CA 인증서를 올바르게 설치하는 것은 서로 다른 작업입니다.

## pip 설치에서 같은 오류가 발생한다면

`pip`는 `requests`와 별도의 인증서 설정을 가질 수 있습니다. 사내 CA 번들을 사용해야 한다면 다음처럼 지정합니다.

```bash
python -m pip install --cert C:\certs\company-ca.pem package-name
```

또는 Windows CMD에서 환경 변수를 지정합니다.

```bash
set PIP_CERT=C:\certs\company-ca.pem
```

## 피해야 할 우회 방법

`requests.get(..., verify=False)` 또는 pip의 `--trusted-host`는 인증서 검증을 비활성화하거나 우회합니다. 연결은 성공할 수 있지만, 상대 서버가 진짜 서버인지 확인하지 않으므로 중간자 공격에 취약해집니다. 로컬에서 잠깐 확인하는 경우를 제외하면 사용하지 말고, 사내 CA나 올바른 서버 인증서 체인을 설정해야 합니다.

## 추가 점검

- `ssl.get_default_verify_paths()`로 Python 표준 SSL 모듈의 기본 인증서 경로를 확인합니다.
- 브라우저에서도 같은 주소에 인증서 경고가 발생한다면 서버의 인증서 체인과 만료 여부를 먼저 점검합니다.
- 운영체제가 오래되어 루트 인증서 업데이트를 받을 수 없다면 지원되는 OS와 Python 환경으로 이전하는 방안을 검토합니다.
