## 한눈에 보는 프로젝트와 해결하려는 문제

`meta/lexical`은 웹 기반의 텍스트 에디터를 구축하기 위한 확장 가능한 프레임워크입니다. 이 프로젝트는 특정 UI 라이브러리에 종속되지 않는 'Framework Agnostic' 철학을 바탕으로 설계되었습니다. 

기존의 많은 에디터 라이브러리들은 특정 프레임워크(예: React, Vue)에 강하게 결합되어 있거나, DOM을 직접 조작하는 과정에서 발생하는 성능 저하 및 상태 관리의 복잡성을 겪는 문제를 해결하고자 합니다. Lexical은 불변(Immutable) 상태 모델을 채택하여 상태 변화를 예측 가능하게 만들고, 플러그인 기반 아키텍처를 통해 필요한 기능만 선택적으로 추가할 수 있도록 지원합니다. 공식 저장소 [README.md](https://github.com/meta/lexical/blob/main/README.md)에 따르면, 이 프레임워크는 신뢰성, 접근성, 성능을 핵심 가치로 삼고 있습니다.

## 이해에 필요한 핵심 개념

Lexical을 이해하기 위해서는 다음의 핵심 아키텍처 요소를 파악해야 합니다.

1. **불변 상태 모델 (Immutable State Model)**: 에디터의 상태는 직접 변경되지 않으며, `editor.update()`를 통해 새로운 상태로 전환됩니다. 이는 타임 트래블 디버깅이나 실행 취소/다시 실행(Undo/Redo) 기능을 구현하는 데 필수적인 기반이 됩니다.
2. **`$` 접두사 함수**: `$`로 시작하는 함수(예: `$getRoot`, `$getSelection`)는 에디터의 업데이트 컨텍스트 내부에서만 실행되어야 함을 나타냅니다. 패키지 문서인 [packages/lexical-website/docs/faq.md](https://github.com/meta/lexical/blob/main/packages/lexical-website/docs/faq.md)에 설명된 바와 같이, 이는 React Hooks와 유사한 시그널 패턴으로 개발자에게 코드의 실행 범위를 명확히 인지시키는 역할을 합니다.
3. **플러그인 아키텍처**: 에디터의 핵심 기능은 최소화되어 있으며, 리스트, 테이블, 코드 하이라이트 등은 모두 플러그인 형태로 제공됩니다. 이는 번들 사이즈를 최적화하고 유지보수성을 높입니다.

## 저장소 구조와 실제 동작 흐름

저장소는 모노레포 구조로 관리되며, 핵심 패키지와 다양한 확장 패키지로 나뉩니다.

- `packages/lexical`: 에디터의 핵심 로직과 상태 관리 엔진이 포함된 패키지입니다.
- `packages/lexical-react`: React 환경에서 Lexical을 쉽게 사용하기 위한 바인딩을 제공합니다.
- `examples/`: `vanilla-js`, `react-rich` 등 다양한 환경에서의 구현 예제를 담고 있어 학습 경로를 제시합니다.
- `.changeset/`: 프로젝트의 버전 관리와 변경 사항 기록을 위한 폴더로, [CONTRIBUTING.md](https://github.com/meta/lexical/blob/main/CONTRIBUTING.md)에 따라 사용자 중심의 변경 로그를 관리합니다.

동작 흐름은 사용자가 에디터 인스턴스를 생성하고, 필요한 플러그인을 주입하면 에디터가 상태 변경을 수행하는 방식으로 이루어집니다. 이때 변경된 상태를 실제 DOM에 반영하는 재조정(Reconciliation) 과정은 `queueMicrotask`를 사용하여 비동기적으로 배치(Batch) 처리됩니다.

## 구체적인 예제로 보는 설계 선택

`examples/vanilla-js/src/main.ts`를 살펴보면, 프레임워크 독립적인 설계의 특징이 잘 드러납니다.

```typescript
const editor = buildEditorFromExtensions(
  AppExtension,
  configExtension(HMRExtension, {hot: import.meta.hot ?? null}),
);
editor.setRootElement(document.getElementById('lexical-editor'));
```

위 코드는 특정 프레임워크 없이도 에디터를 생성하고 DOM 요소에 마운트할 수 있음을 보여줍니다. `HMRExtension`은 개발 환경에서 HMR 업데이트를 수용하며, 에디터 인스턴스가 더 이상 필요하지 않을 때 `editor.dispose()`를 호출하도록 가이드하여 리소스 관리를 명시적으로 처리합니다. 이는 개발 생산성과 안정성을 고려한 설계 선택으로 볼 수 있습니다.

## 대안과 비교했을 때의 장단점

Lexical은 Slate.js나 Quill과 같은 기존 에디터 라이브러리와 비교됩니다.

- **장점**: 
    - **성능**: 비동기 배치 업데이트를 통해 DOM 조작을 최소화하여 성능을 최적화합니다.
    - **유연성**: 특정 UI 프레임워크에 종속되지 않아 향후 기술 스택 변경 시에도 에디터 코어를 유지할 수 있습니다.
    - **신뢰성**: 불변 상태 모델을 통해 상태 변화의 예측 가능성을 높였습니다.
- **단점**: 
    - **학습 곡선**: `$` 접두사 함수와 같은 독자적인 API 패턴을 익히는 데 시간이 필요합니다.
    - **초기 설정**: 플러그인 기반이므로, 아주 간단한 에디터를 만들 때도 여러 패키지를 설치하고 설정해야 하는 번거로움이 있을 수 있습니다.

## 한계와 추천 대상

Lexical은 다음과 같은 사용자에게 추천합니다.
- 고성능의 복잡한 텍스트 편집 기능을 구현해야 하는 팀
- React를 사용하지만, 향후 프레임워크 변경 가능성을 열어두고 싶은 프로젝트
- 웹 접근성을 고려하여 확장 가능한 에디터 엔진이 필요한 엔터프라이즈 서비스

반면, 단순히 간단한 텍스트 입력창(Textarea) 수준의 기능이 필요하거나, 설정의 간결함을 최우선으로 하는 경우에는 과도한 설계가 될 수 있습니다. 특히, 지원 브라우저 환경이 프로젝트의 요구사항과 일치하는지 공식 문서의 Browser Support 섹션을 반드시 검토해야 합니다.
