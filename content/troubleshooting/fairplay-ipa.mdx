## 한눈에 보는 프로젝트와 해결하려는 문제

`EthanArbuckle/fairplay-decrypt`는 Apple의 FairPlay DRM(Digital Rights Management)으로 보호된 iOS 앱(IPA)을 복호화하기 위한 개발 도구입니다. 이 프로젝트는 단순히 암호화된 파일을 푸는 것을 넘어, 탈옥된 기기에서 FairPlay 자격 증명(Credential)을 추출하는 과정과 이를 활용해 로컬 환경(macOS, Linux)에서 복호화를 수행하는 과정을 분리하여 설계되었습니다.

주요 목표는 사용자가 소유한 앱의 암호화 계층을 제거하여, 앱의 바이너리 구조를 분석하거나 연구할 수 있도록 돕는 것입니다. 이는 주로 보안 연구자나 앱 분석가들이 대상이며, 복호화 과정에서 Apple의 서버와 통신하지 않는 '오프라인' 방식을 취한다는 점이 특징입니다.

## 이해에 필요한 핵심 개념

이 프로젝트를 이해하기 위해서는 다음의 세 가지 핵심 개념이 필요합니다.

1. **FairPlay DRM 및 SINF/SUPF**: FairPlay는 앱의 Mach-O 바이너리를 암호화하는 기술입니다. `SINF`(SINF atom)와 `SUPF` 레코드는 암호화된 페이지의 키를 유도하는 데 필요한 데이터를 포함하고 있습니다. `core.py`의 `decrypt_binary` 함수는 이 레코드들을 해석하여 각 페이지별 복호화 키를 유도합니다.
2. **Credential(자격 증명)**: 복호화의 핵심 키를 생성하기 위한 16바이트 데이터입니다. `credential-retrieval/` 디렉토리 내의 도구들은 탈옥된 기기에서 `fairplayd` 프로세스와 상호작용하여 이 값을 추출합니다.
3. **Mach-O 복호화**: 암호화된 `arm64` 슬라이스를 찾아 `cryptid` 필드를 0으로 수정하고, 유도된 키를 사용하여 암호화된 페이지를 복구합니다.

## 저장소 구조와 실제 동작 흐름

저장소는 크게 복호화 로직을 담당하는 Python 모듈과 자격 증명 추출을 위한 C 기반 도구로 나뉩니다.

* `core.py`: 복호화의 핵심 엔진입니다. `derive_page_key`를 통해 페이지 키를 계산하고, `decrypt_binary`를 통해 실제 바이너리를 복호화합니다.
* `credential-retrieval/`: 탈옥된 기기에서 자격 증명을 추출하는 도구 모음입니다. `credential/` 내의 C 소스 코드와 `retrieve.py`를 통해 기기와의 통신 및 데이터 추출을 수행합니다.
* `decrypt.py`: 사용자가 직접 실행하는 엔트리 포인트입니다. IPA 경로와 자격 증명 파일을 인자로 받아 복호화 프로세스를 시작합니다.

동작 흐름은 다음과 같습니다:
1. 사용자가 `retrieve.py`를 실행하여 탈옥된 기기에서 `credential.bin`을 추출합니다.
2. `decrypt.py`를 호출하여 암호화된 IPA와 `credential.bin`을 전달합니다.
3. `core.py`가 IPA 내부의 `SINF`/`SUPF`를 파싱하고, 자격 증명을 사용하여 복호화 키를 생성한 뒤 바이너리를 복구합니다.

## 구체적인 예제로 보는 설계 선택

`core.py`의 `derive_page_key` 함수는 설계의 핵심을 보여줍니다.

```python
def derive_page_key(wrapped: bytes, absolute_index: int, work: bytes) -> bytes:
    # ... (생략)
    return struct.pack(">8H", *finish(_xor_int(finish(_xor_int(finish(a), b)), c)))
```

이 함수는 `finish`라는 내부 연산과 `_xor_int`를 반복적으로 수행합니다. 이는 Apple의 FairPlay 키 유도 알고리즘을 Python으로 재구현한 것입니다. 이 설계는 외부 라이브러리 의존성을 최소화하고, 복호화 과정을 투명하게 공개하여 연구자가 알고리즘의 동작을 직접 검증할 수 있게 합니다. 또한, `credential-retrieval`에서 C 코드를 사용하여 `fairplayd`와 상호작용하는 방식은, 블랙박스 형태의 DRM을 분석하기 위한 정교한 접근 방식을 보여줍니다.

## 대안과 비교했을 때의 장단점

이 프로젝트는 기기에서 직접 복호화된 바이너리를 추출하는 방식과 달리, 자격 증명 추출과 복호화 과정을 분리한 오프라인 방식을 채택합니다.

* **장점**: PC 환경에서 복호화를 수행하므로 기기 리소스 사용을 최소화할 수 있으며, 복호화 로직이 Python으로 구현되어 있어 알고리즘 분석 및 검증이 용이합니다.
* **단점**: 탈옥된 기기 환경이 필수적이며, 시스템 프로세스인 `fairplayd`와 상호작용하기 위한 환경 설정이 필요합니다.

## 보안·라이선스·도입 시 확인할 점

* **보안**: 이 도구는 탈옥된 환경에서 시스템 프로세스인 `fairplayd`와 상호작용하므로, 신뢰할 수 있는 개발 환경에서만 사용해야 합니다.
* **라이선스**: 프로젝트는 `GPL-3.0` 라이선스를 따릅니다. 이는 수정된 버전을 배포할 경우 소스 코드를 공개해야 함을 의미합니다.
* **도입 시 확인**: `README.md`에 명시된 대로 `Python 3.9+` 환경이 필요하며, macOS 환경에서는 `make` 명령어를 실행하기 위해 `Xcode`와 `ldid` 도구가 설치되어 있어야 합니다.

## 한계와 추천 대상

이 프로젝트는 **iOS 앱 보안 연구자**와 **리버스 엔지니어링 학습자**에게 가장 적합합니다. FairPlay가 어떻게 키를 유도하고 바이너리를 암호화하는지 그 원리를 파악하고자 하는 이들에게는 훌륭한 학습 자료가 됩니다.

**한계**:
* 탈옥되지 않은 순정 기기에서는 사용할 수 없습니다.
* Apple의 DRM 업데이트가 발생할 경우, 자격 증명 추출 로직이나 키 유도 알고리즘이 호환되지 않을 수 있습니다.
* `credential-retrieval`의 C 코드는 특정 iOS 버전의 `fairplayd` 구조에 의존적일 수 있으므로, 최신 OS 버전에서는 추가적인 분석이 필요할 수 있습니다.
