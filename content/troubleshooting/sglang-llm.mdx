## 프로젝트 개요

SGLang은 대규모 언어 모델(LLM), 비전-언어 모델(VLM), 디퓨전 모델의 추론과 서빙을 위한 오픈소스 프레임워크입니다. 공식 README는 에이전트 워크로드, 대규모 모델 서빙, 강화학습(RL) 롤아웃을 주요 사용 영역으로 소개합니다.

이 글에서는 모델 추론 엔진인 SGLang과 모델 앞단에서 요청을 라우팅하거나 인증·관측을 처리하는 별도 게이트웨이 제품을 구분합니다. SGLang의 핵심 기능을 'WASM 게이트웨이'나 '커스텀 라우팅 언어'로 설명하는 것은 현재 공식 저장소 구조와 맞지 않습니다.

## 어떤 문제를 해결하나요?

LLM을 실제 서비스에 배포하려면 단순히 모델 가중치를 로드하는 것 외에도 다수의 동시 요청 처리, 모델별 생성 옵션 관리, 출력 형식 제약, GPU 자원 활용, 프롬프트 및 KV 캐시 관리 등 여러 과제가 있습니다.

SGLang은 모델 추론 실행과 요청 처리를 위한 서버를 제공하고, Python 패키지와 실행 도구를 통해 모델을 띄울 수 있도록 합니다. 공식 문서는 OpenAI 호환 API를 이용해 서버에 요청을 전송하는 방식도 안내합니다.

## 주요 기능

### 1. LLM과 멀티모달 모델 서빙

SGLang 저장소는 텍스트 기반 LLM뿐 아니라 비전-언어 모델과 디퓨전 모델을 위한 추론 경로도 포함합니다. 현재 지원 하드웨어는 NVIDIA·AMD GPU, TPU, Intel GPU/CPU, Apple Silicon, Huawei Ascend 등으로 넓어지고 있습니다. 다만 모델과 연산별 지원 범위는 하드웨어별 가이드 및 릴리스에 따라 다를 수 있으므로 실제 배포 전 확인해야 합니다.

### 2. 구조화 출력(Structured Outputs)

SGLang은 생성 결과를 JSON Schema, 정규식(Regex), EBNF 문법으로 제한하는 구조화 출력 기능을 제공합니다. 이때 문법 제약을 처리하는 백엔드로 XGrammar, Outlines, Llguidance를 지원하며, 공식 문서는 별도 지정이 없을 때 XGrammar를 기본 백엔드로 안내합니다.

예를 들어 OpenAI 호환 API에 JSON Schema를 전달하면, 모델의 출력이 지정한 구조를 따르도록 제약할 수 있습니다. 다만 형식 제약은 출력의 문법적 구조를 관리하는 기능이지, 내용의 사실성이나 의미적 정확성을 보장하는 기능은 아닙니다.

### 3. OpenAI 호환 API

서버를 실행한 뒤 OpenAI Python SDK의 `base_url`을 SGLang 서버 주소로 지정해 요청할 수 있습니다. 기존 OpenAI 호환 클라이언트 코드를 재사용하기 쉬운 점이 장점입니다.

~~~python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:30000/v1",
    api_key="EMPTY",
)

response = client.chat.completions.create(
    model="your-served-model",
    messages=[
        {"role": "user", "content": "SGLang의 역할을 한 문장으로 설명해 주세요."}
    ],
)

print(response.choices[0].message.content)
~~~

실제 모델 이름과 서버 주소는 실행 환경에서 지정한 값으로 바꿔야 합니다. 이 코드는 API 호출 형태를 보여주는 예제이며, 모델을 자동으로 내려받거나 서버를 시작하지는 않습니다.

## 설치와 실행 흐름

공식 README는 Docker 이미지 사용 또는 Python 환경에서의 설치를 안내합니다. 실행 환경의 GPU, 드라이버, CUDA 및 모델 요구 사항에 따라 적합한 설치 방법이 달라지므로, 실제 설치 전 공식 Quickstart와 하드웨어별 가이드를 확인해야 합니다.

일반적인 흐름은 다음과 같습니다.

1. 지원 하드웨어와 모델 조합을 확인합니다.
2. 공식 이미지 또는 Python 환경에 SGLang을 설치합니다.
3. 모델 경로와 서버 옵션을 지정해 추론 서버를 실행합니다.
4. OpenAI 호환 API 또는 SGLang 클라이언트로 요청을 보내 결과를 확인합니다.
5. 실제 서비스에서는 동시 요청, 캐시 사용량, GPU 메모리, 지연 시간과 처리량을 측정해 설정을 조정합니다.

## 도입할 때 확인할 점

- 모델별 지원 여부와 권장 실행 옵션은 공식 Cookbook 및 하드웨어별 문서에서 확인합니다.
- 구조화 출력이 필요한 경우 JSON Schema, Regex, EBNF 중 요구 사항에 맞는 제약을 선택합니다.
- OpenAI 호환 API를 제공한다고 해서 모든 OpenAI API 기능이 동일하게 지원된다고 가정하지 말고, 사용하는 엔드포인트와 옵션을 검증합니다.
- 대규모 운영에서는 배치 크기, 병렬화, KV 캐시, GPU 메모리 사용량, 장애 복구 및 스케일아웃 전략을 별도로 검증해야 합니다.

## 정리

SGLang은 특정 WASM 미들웨어를 핵심으로 하는 API 게이트웨이가 아니라, LLM과 멀티모달 모델의 추론·서빙을 위한 프레임워크입니다. 구조화 출력과 OpenAI 호환 API 등 애플리케이션 연결에 유용한 기능도 제공하지만, 실제 성능과 하드웨어 지원은 모델 및 배포 조건에 따라 확인해야 합니다.
