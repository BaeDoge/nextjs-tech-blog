## 현상

조건에 맞는 행만 추출한 뒤 열 값을 변환하거나 새 값을 할당하려면, 먼저 수정 결과를 원본에 반영할지 아니면 독립된 결과로 사용할지 결정해야 합니다.

~~~~python
import pandas as pd

df = pd.DataFrame({
    "my_col": [1, None, 3, 4],
    "name": ["A", "B", "C", "D"],
})

filtered = df[df["my_col"].notna()]
~~~~

필터 결과를 이후 작업에서 독립된 DataFrame으로 취급하려는 경우, 복사 여부를 암묵적인 인덱싱 동작에 맡기지 않는 편이 안전합니다.

## 원인

Pandas의 인덱싱은 버전과 선택 방식에 따라 원본 데이터와 메모리를 공유할 수 있습니다. 특히 필터링과 열 선택을 연속해서 수행하는 chained assignment는 원본을 수정하려는 것인지, 중간 결과만 수정하려는 것인지 모호해집니다.

반대로 필터링 결과를 별도 변수에 저장한 뒤 그 변수만 수정하는 작업은 원본 수정과 목적이 다릅니다. 두 상황을 구분하지 않고 copy()나 loc을 기계적으로 적용하면 코드의 의도가 오히려 불분명해질 수 있습니다.

## 해결 방법 1. 필터 결과를 독립적으로 가공하기

필터링한 데이터만 별도로 보관하거나 가공하려면 copy()를 명시합니다.

~~~~python
mask = df["my_col"].notna()
filtered = df.loc[mask].copy()

filtered["my_col"] = pd.to_numeric(filtered["my_col"])
filtered["name"] = filtered["name"].str.lower()
~~~~

이제 filtered는 원본과 독립된 작업용 DataFrame입니다. filtered의 값을 수정해도 원본 df는 변경되지 않습니다.

## 해결 방법 2. 원본 DataFrame의 특정 행을 수정하기

필터 조건에 해당하는 원본 행을 직접 수정하려면 조건과 열을 하나의 loc 할당으로 지정합니다.

~~~~python
mask = df["my_col"].notna()
df.loc[mask, "my_col"] = pd.to_numeric(df.loc[mask, "my_col"])
~~~~

이 코드는 원본 df의 my_col 열을 직접 변경합니다. 별도의 필터 DataFrame을 만든 다음 그 객체를 수정하는 방식과 목적이 다릅니다.

## pandas 3.0에서 주의할 점

- ``.copy()`는 독립된 DataFrame을 만들기 위한 선택입니다. Copy-on-Write를 사용하는 버전에서는 실제 데이터 복사가 쓰기 시점까지 지연될 수 있으므로, 항상 즉시 전체 메모리를 복제한다고 단정할 수는 없습니다.
- 이 경고는 실행을 중단시키는 예외는 아니지만, 수정 대상이 원본 DataFrame인지 필터링된 결과인지 의도를 확인해야 하는 신호입니다. Pandas 2.x에서는 뷰/복사본 동작의 모호성으로 경고가 발생할 수 있습니다. Pandas 3.0부터 Copy-on-Write가 기본이며, 필터링 결과에 대한 변경은 원본 DataFrame으로 전파되지 않습니다. 필터링한 결과를 독립적으로 사용하려면 `.copy()`를 명시하고, 원본을 수정하려면 원본 객체에 `df.loc[조건, 열] = 값` 형태로 직접 할당합니다.

pandas 2.x 환경에서도 버전에 따른 차이를 줄이려면 원본 수정은 loc, 독립된 결과 생성은 copy()로 의도를 명확히 구분하는 것이 좋습니다.
