## 한눈에 보는 프로젝트와 해결하려는 문제

`OpenHFT/Chronicle-Queue`는 자바 애플리케이션에서 극도로 낮은 지연 시간(Low-latency)을 유지하면서도 모든 메시지를 디스크에 영속적으로 저장하기 위해 설계된 라이브러리입니다. 일반적인 메시지 큐 시스템이 네트워크 통신이나 가비지 컬렉션(GC)으로 인한 지연 시간 변동(Jitter)을 겪는 것과 달리, 이 프로젝트는 메모리 매핑 파일(Memory-mapped files)을 직접 조작하여 GC 영향을 최소화하고 하드웨어 성능을 최대한 활용하는 것을 목표로 합니다.

주요 사용자는 금융권의 고빈도 매매 시스템(HFT), 실시간 데이터 피드 처리, 혹은 대규모 로그의 즉각적인 영속화가 필요한 엔지니어링 팀입니다. 이 프로젝트는 단순한 라이브러리를 넘어, 고성능 시스템 구축을 위한 인프라 도구로 분류할 수 있습니다.

## 이해에 필요한 핵심 개념

`Chronicle-Queue`를 이해하기 위해서는 다음 세 가지 개념이 필수적입니다.

1. **Memory-Mapped Files (MMap):** 운영체제의 가상 메모리 기능을 활용하여 디스크 파일을 메모리처럼 직접 접근합니다. 이를 통해 파일 입출력 시 발생하는 시스템 콜과 커널-사용자 영역 간의 데이터 복사를 줄입니다.
2. **Roll Cycles:** 큐는 무한히 커질 수 없으므로, 시간 단위(예: `HOURLY`, `DAILY`)에 따라 파일을 자동으로 분할하여 관리합니다. 이는 파일 시스템의 부하를 분산하고 오래된 데이터를 삭제(Retention)하기 쉽게 만듭니다.
3. **Wire Types:** 데이터를 직렬화하는 방식입니다. `Chronicle-Wire`를 통해 바이너리 형식이나 텍스트(YAML/JSON) 형식을 선택할 수 있으며, 성능을 위해 주로 바이너리 형식을 사용합니다.

## 저장소 구조와 실제 동작 흐름

저장소는 `src/main/java`를 중심으로 핵심 로직이 구현되어 있으며, `docs/antora`를 통해 상세한 기술 문서가 관리됩니다.

- `src/main/java/net/openhft/chronicle/queue/`: 큐의 핵심 인터페이스와 구현체가 위치합니다.
- `bin/`: 큐 파일 관련 유틸리티 스크립트들이 포함되어 있습니다.
- `docs/`: `Antora` 기반의 문서화 체계가 구축되어 있어, 설정(Configuration), 성능(Performance) 등 각 모듈별로 상세한 가이드를 제공합니다.

동작 흐름은 사용자가 `ChronicleQueue.singleBuilder()`를 통해 큐 인스턴스를 생성하고, `ExcerptAppender`를 통해 데이터를 기록하며, `ExcerptTailer`를 통해 데이터를 읽는 방식으로 진행됩니다. 모든 데이터는 즉시 메모리 매핑된 영역에 기록되므로, 프로세스가 비정상 종료되어도 디스크에는 데이터가 남아있게 됩니다.

## 구체적인 예제로 보는 설계 선택

`src/test/java/net/openhft/chronicle/queue/example/QueueExamples1.java`에서 제공하는 예제는 이 라이브러리의 직관적인 API 설계를 잘 보여줍니다.

```java
ChronicleQueue queue = ChronicleQueue.single("./myQueueDir");
Printer printer = queue.methodWriter(Printer.class);
printer.print("hello world");
```

위 코드는 `methodWriter`를 사용하여 인터페이스 기반의 통신을 가능하게 합니다. 이는 사용자가 직접 바이트를 직렬화하는 복잡한 과정 없이, 일반적인 자바 인터페이스 호출만으로 큐에 데이터를 기록할 수 있게 설계되었음을 의미합니다. 이러한 설계는 개발 생산성을 높이는 동시에, 내부적으로는 `Chronicle-Wire`를 통해 효율적인 직렬화를 수행하여 성능 손실을 방지합니다.

## 대안과 비교했을 때의 장단점

`Chronicle-Queue`는 Kafka나 RabbitMQ와 같은 네트워크 기반 메시지 브로커와는 지향점이 다릅니다.

- **장점:** 네트워크 호출이 없는 로컬 프로세스 간 통신(IPC)에서 압도적인 성능을 보입니다. GC를 유발하지 않는 객체 재사용 설계로 지연 시간이 매우 안정적입니다.
- **장점:** 디스크 영속성을 기본으로 하므로 별도의 설정 없이도 데이터 유실을 방지할 수 있습니다.
- **단점:** 기본적으로 로컬 파일 시스템 기반이므로, 여러 서버에 걸친 분산 환경을 구성하려면 별도의 복제 솔루션이 필요합니다. 또한, 네트워크 브로커가 제공하는 복잡한 라우팅 기능은 부족할 수 있습니다.

## 보안·라이선스·도입 시 확인할 점

- **라이선스:** `Apache-2.0` 라이선스를 따르며, 상업적 이용이 가능합니다. `pom.xml`에서 확인할 수 있듯이 `chronicle-core`, `chronicle-bytes` 등 여러 모듈로 구성되어 있어 의존성 관리에 주의가 필요합니다.
- **보안:** 파일 시스템에 직접 데이터를 쓰기 때문에, 큐 파일이 저장되는 디렉터리에 대한 OS 수준의 접근 제어(권한 설정)가 보안의 핵심입니다.
- **도입 시:** 프로젝트의 `docs/` 폴더 내에 포함된 다양한 `adoc` 문서를 통해 설정 및 운영 가이드를 확인해야 합니다.

## 한계와 추천 대상

`Chronicle-Queue`는 다음과 같은 경우에 강력하게 추천합니다.
- 마이크로초 단위의 지연 시간이 비즈니스 성패를 결정하는 경우.
- 대량의 데이터를 로컬 디스크에 영속적으로 남겨야 하는 경우.
- 자바 애플리케이션 내에서 GC 튜닝만으로 해결되지 않는 지연 시간 문제를 겪는 경우.

반면, 단순한 비동기 작업 처리나 분산 시스템에서의 메시지 브로커가 필요한 경우에는 Kafka와 같은 범용 메시징 시스템이 더 적합할 수 있습니다. 또한, 운영체제의 파일 시스템 캐시와 메모리 매핑에 대한 이해가 부족할 경우, 큐 파일 관리나 디스크 용량 설정에서 어려움을 겪을 수 있으므로 충분한 사전 학습이 필요합니다.
