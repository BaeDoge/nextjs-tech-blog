## 현상

Python에서 HTTPS 주소에 연결하거나 패키지를 설치할 때 인증서 검증에 실패하면 다음과 같은 오류가 발생할 수 있습니다.

```text
requests.exceptions.SSLError: [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed
```

pip에서는 다음과 비슷한 메시지가 나타날 수 있습니다.

```text
ERROR: Could not fetch URL ... There was a problem confirming the ssl certificate
```

## 원인

HTTPS 연결에서 클라이언트는 서버가 제공한 인증서 체인을 신뢰할 수 있는 CA(인증 기관) 목록과 대조합니다. 인증서가 만료되었거나, 중간 인증서가 누락되었거나, 클라이언트가 해당 CA를 신뢰하지 않으면 검증이 실패합니다.

`requests`는 기본적으로 `certifi` 패키지가 제공하는 CA 번들을 사용합니다. pip의 인증서 처리 방식은 pip 버전과 Python 버전에 따라 다릅니다. pip 24.2 이상은 Python 3.10 이상에서 시스템 인증서 저장소와 `certifi` 인증서를 함께 사용하는 방식이 기본입니다.

회사나 기관의 HTTPS 프록시가 TLS 트래픽을 검사하는 경우에는 조직의 자체 CA가 필요할 수 있습니다. 이때 `certifi`만 업데이트해도 조직의 CA가 자동으로 추가되지는 않습니다.

## 해결 방법

먼저 어떤 도구에서 실패하는지 구분하고 Python과 pip 버전, CA 번들 경로를 확인합니다.

```bash
python --version
python -m pip --version
python -m pip install --upgrade certifi
```

`requests`가 사용하는 CA 번들을 확인하고 HTTPS 연결을 시험할 수 있습니다.

```python
import certifi
import requests

print("CA bundle:", certifi.where())
response = requests.get("https://pypi.org", timeout=15)
response.raise_for_status()
print("HTTP status:", response.status_code)
```

조직에서 제공한 CA 번들을 사용해야 한다면 `verify` 인자에 해당 파일 경로를 지정합니다.

```python
import requests

response = requests.get(
    "https://internal.example.com",
    verify="/path/to/organization-ca-bundle.pem",
    timeout=15,
)
response.raise_for_status()
```

pip에는 `--cert` 옵션으로 CA 번들 경로를 지정할 수 있습니다.

```bash
python -m pip install some-package --cert /path/to/organization-ca-bundle.pem
```

반복해서 사용하는 환경이라면 `REQUESTS_CA_BUNDLE` 또는 `PIP_CERT` 환경 변수를 설정할 수 있습니다. 인증서 파일은 조직의 관리자나 신뢰할 수 있는 보안 담당자가 제공한 CA 번들을 사용해야 합니다.

## 다른 해결 방법

Python 3.10 이상과 pip 24.2 이상을 사용할 수 있는 환경이라면 pip는 기본적으로 시스템 인증서 저장소도 함께 사용합니다. 오래된 pip를 사용하고 있다면 프로젝트의 호환성을 확인한 뒤 업데이트하고, 조직의 루트 CA 인증서가 운영체제 신뢰 저장소에 설치되어 있는지 확인합니다.

```bash
python -m pip install --upgrade pip
python -m pip check
```

인증서 검증을 완전히 비활성화하는 `requests.get(..., verify=False)`나 pip의 `--trusted-host`는 근본 해결책이 아닙니다. 서버 신원 확인을 약화해 중간자 공격에 노출될 수 있으므로 일반적인 해결 방법으로 사용하지 말고, 올바른 CA 인증서를 구성해야 합니다.

## 추가 참고사항

- `ssl.get_default_verify_paths()`로 Python 표준 SSL 모듈이 참조하는 기본 CA 경로를 확인할 수 있습니다.
- 브라우저에서도 같은 주소에 인증서 경고가 발생한다면 서버의 인증서 체인과 만료 여부를 점검해야 합니다.
- 오래된 운영체제의 루트 인증서를 업데이트할 수 없다면 지원되는 운영체제와 Python 환경으로 이전하는 방안을 검토합니다.
- 서버 인증서 자체가 만료되었거나 체인이 잘못된 경우에는 클라이언트 설정이 아니라 서버 운영자가 인증서 구성을 수정해야 합니다.
