## 현상

Python 스크립트 실행 또는 `pip install` 명령 수행 시 HTTPS 연결 중 SSL 인증서 검증 오류가 발생한다.
에러 메시지는 주로 다음과 같이 나타난다.

```
[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: unable to get local issuer certificate (_ssl.c:1129)
```

특히 Windows 환경에서 AWS 연결 스크립트 실행이나 패키지 설치 시 빈번하게 관찰된다.
`requests` 라이브러리를 사용하여 외부 API에 접근할 때도 동일한 오류가 발생한다.

```python
import requests
response = requests.get('https://pypi.org')
```

![현상 스크린샷](/blogs/ssl-certificate-verify-failed-152526-1.png)

## 원인

HTTPS 연결에서 클라이언트는 서버가 보낸 인증서 체인을 신뢰할 수 있는 CA(인증 기관) 목록과 대조합니다. 이 검증에 실패하면 `CERTIFICATE_VERIFY_FAILED`가 발생합니다.

`requests`는 기본적으로 `certifi` 패키지가 제공하는 CA 번들을 사용합니다. 반면 `pip`의 인증서 처리 방식은 버전과 Python 버전에 따라 다릅니다. pip 24.2 이상은 Python 3.10 이상에서 시스템 인증서와 `certifi` 인증서를 함께 사용합니다. 그보다 오래된 조합에서는 기본 인증서 저장소가 다를 수 있습니다.

회사 프록시가 HTTPS 트래픽을 검사하는 경우에는 조직의 자체 CA 인증서가 필요할 수 있습니다. 이때 `certifi`만 업데이트해도 조직의 CA가 추가되는 것은 아니므로, 오류 환경과 인증서 체인을 구분해서 확인해야 합니다.

## 해결 방법

먼저 Python과 pip 버전을 확인하고, 인증서가 오래되었거나 누락된 경우 사용하는 도구의 CA 번들을 업데이트합니다.

```bash
python --version
python -m pip --version
python -m pip install --upgrade certifi
```

`requests`에서 CA 번들 경로를 확인하려면 다음과 같이 실행합니다. `requests`는 기본적으로 이 번들을 사용하므로, 이 확인만으로 회사 내부 CA 문제가 해결되는 것은 아닙니다.

```python
import certifi
import requests

print("CA bundle:", certifi.where())
response = requests.get("https://pypi.org", timeout=15)
print("HTTP status:", response.status_code)
```

조직에서 제공한 CA 번들을 사용해야 하는 환경이라면 `verify`에 해당 파일 경로를 지정합니다.

```python
import requests

response = requests.get(
    "https://pypi.org",
    verify="/path/to/organization-ca-bundle.pem",
    timeout=15,
)
print(response.status_code)
```

pip에는 `--cert` 옵션으로 CA 번들을 지정할 수 있습니다.

```bash
python -m pip install selenium --cert /path/to/organization-ca-bundle.pem
```

프로젝트나 실행 환경에서 반복적으로 사용해야 한다면 `REQUESTS_CA_BUNDLE` 또는 `PIP_CERT` 환경 변수를 설정할 수 있습니다. 인증서 파일은 조직의 관리자나 신뢰할 수 있는 보안 담당자가 제공한 CA 번들을 사용해야 합니다.

## 다른 해결 방법

Python 3.10 이상과 pip 24.2 이상을 사용할 수 있는 환경이라면 pip는 시스템 인증서 저장소도 기본 검증에 사용합니다. 오래된 pip를 사용 중이라면 호환성을 확인한 뒤 업데이트하고, 조직에서 관리하는 루트 CA 인증서가 운영체제의 신뢰 저장소에 설치되어 있는지 확인합니다.

```bash
python -m pip install --upgrade pip
```

`verify=False`나 `--trusted-host`로 인증서 검증을 우회하는 방법은 문제를 해결하지 않고 서버 신원을 확인하는 보호 기능을 약화합니다. 중간자 공격에 노출될 수 있으므로 해결책으로 사용하지 말고, 올바른 CA 인증서를 구성해야 합니다.

## 추가 참고사항

인증서 오류가 발생하면 먼저 실패한 도구가 `requests`인지 `pip`인지 구분하고, 사용 중인 Python·pip 버전과 CA 번들 경로를 확인합니다. 조직 내부 프록시의 자체 CA가 원인이라면 해당 CA를 신뢰할 수 있는 저장소나 별도 CA 번들에 추가해야 합니다. 서버 인증서 자체가 만료되었거나 체인이 잘못된 경우에는 서버 운영자가 인증서 구성을 수정해야 합니다.
