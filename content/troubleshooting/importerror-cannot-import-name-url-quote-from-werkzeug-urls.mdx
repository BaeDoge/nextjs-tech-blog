## 현상

Flask 2.2.2 환경에서 애플리케이션을 실행하거나 테스트를 수집할 때 `werkzeug.urls` 모듈에서 `url_quote`를 가져오지 못해 다음 오류가 발생할 수 있습니다.

<Callout type="warning" title="오류 상황">
ImportError: cannot import name 'url_quote' from 'werkzeug.urls'
</Callout>

재현 환경의 한 예시는 다음과 같습니다.

```text
Python 3.10.11
Flask==2.2.2
Werkzeug==3.0.0
```

## 원인

Flask 2.2.2는 `werkzeug.urls.url_quote`를 사용하지만, Werkzeug 3.0.0에서 이전에 deprecated된 URL 유틸리티가 제거되었습니다. Flask 2.2.2의 의존성 조건에는 Werkzeug 3.0 미만이라는 상한이 없으므로, 패키지 설치 과정에서 호환되지 않는 Werkzeug 3.x가 선택될 수 있습니다.

이 문제는 단순히 `url_quote` 함수를 직접 추가해서 해결할 오류가 아니라, Flask와 Werkzeug의 버전 조합을 맞춰야 하는 의존성 호환 문제입니다.

## 해결 방법

### Flask 2.2.2를 당장 유지해야 하는 경우

레거시 애플리케이션을 즉시 업그레이드할 수 없다면 `Werkzeug`를 3.0 미만으로 제한합니다.

```text
# requirements.txt
Flask==2.2.2
Werkzeug>=2.2.2,<3.0
```

의존성을 다시 설치하고 충돌이 남아 있는지 확인합니다.

```bash
python -m pip install -r requirements.txt
python -m pip check
```

### Flask를 업그레이드할 수 있는 경우

장기적으로는 Flask와 Werkzeug를 함께 지원되는 버전 계열로 업데이트하는 편이 좋습니다. 다음 명령은 두 패키지를 함께 업그레이드합니다.

```bash
python -m pip install --upgrade "Flask>=3.1,<4" "Werkzeug>=3.1,<4"
python -m pip check
```

업데이트 후에는 애플리케이션 테스트를 실행하고, 검증한 정확한 버전을 `requirements.txt`, constraints 파일 또는 lock 파일에 고정해 배포 환경에서도 같은 조합을 사용하도록 합니다.

## 다른 해결 방법

임시로 한 패키지만 내리는 것보다, 프로젝트가 사용하는 Flask 확장(extensions)까지 포함해 전체 의존성 충돌을 확인해야 합니다. 설치된 버전은 다음과 같이 조회할 수 있습니다.

```bash
python -m pip show Flask Werkzeug
python -m pip check
```

`url_quote`를 직접 monkeypatch하거나 Flask 내부 파일을 수정하는 방식은 권장하지 않습니다. 이후 업데이트에서 다시 깨질 수 있고, 라이브러리의 지원되지 않는 내부 구현에 의존하게 됩니다.

## 추가 참고사항

Werkzeug 3.0.0은 이전 버전에서 deprecated된 API를 제거했습니다. Flask도 버전별로 요구하는 Werkzeug 최소 버전이 다르므로, Flask와 Werkzeug를 독립적으로 무작정 최신화하기보다 공식 의존성 조건과 잠금 파일을 함께 확인해야 합니다.

<Steps>
<Step title="설치된 버전 확인">
`python -m pip show Flask Werkzeug`로 현재 설치 버전을 확인합니다.
</Step>
<Step title="호환 범위 조정">
레거시 Flask를 유지한다면 Werkzeug 버전을 제한하고, 업그레이드할 수 있다면 두 패키지를 함께 갱신합니다.
</Step>
<Step title="의존성 검증">
`python -m pip check`와 애플리케이션 테스트를 실행한 뒤 검증된 버전을 lock 파일에 고정합니다.
</Step>
</Steps>
