## 현상

일부 오래된 패키지나 애플리케이션을 실행할 때 다음과 같은 오류가 발생할 수 있습니다.

~~~text
ModuleNotFoundError: No module named 'pkg_resources'
~~~

최근 Python 환경에서는 가상 환경에 Setuptools가 기본 설치되지 않을 수 있으며, Setuptools 최신 버전에서는 `pkg_resources`가 더 이상 제공되지 않습니다.

## 원인

두 가지 변경 사항을 구분해야 합니다.

1. **Python 3.12부터** `venv`는 Setuptools를 기본 의존성으로 설치하지 않습니다. 따라서 새 가상 환경에서 `pkg_resources`를 당연히 사용할 수 있다고 가정하면 안 됩니다.
2. **Setuptools 82.0.0부터** `pkg_resources` 패키지가 제거되었습니다. 따라서 최신 Setuptools를 설치해도 이 모듈은 복구되지 않습니다.

오류가 발생한 라이브러리나 애플리케이션이 실행 시점에 `pkg_resources`를 import하고 있다면, 해당 의존성이 이전 Setuptools API에 묶여 있는지 확인해야 합니다.

## 권장 해결 방법: 표준 라이브러리로 마이그레이션

패키지 메타데이터나 진입점 정보를 조회하려는 코드라면 `importlib.metadata`, 패키지 리소스를 읽으려는 코드라면 `importlib.resources`로 옮기는 것이 권장됩니다.

~~~python
# 배포 패키지의 설치 버전 조회
from importlib.metadata import version

print(version("requests"))
~~~

~~~python
# 패키지 내부 리소스 파일 읽기
from importlib.resources import files

text = files("your_package").joinpath("data.txt").read_text(
    encoding="utf-8"
)
~~~

위 예제의 `your_package`는 실제 프로젝트의 패키지 이름으로 바꿔야 합니다.

## 임시 호환 방법: 구형 의존성이 반드시 필요한 경우

당장 코드를 변경할 수 없는 레거시 패키지라면, 해당 패키지가 지원하는 범위에서 Setuptools 82 미만 버전을 임시로 고정할 수 있습니다.

~~~bash
python -m pip install "setuptools<82"
~~~

이 방법은 구형 의존성을 위한 임시 호환 조치입니다. 장기적으로는 해당 패키지를 업데이트하거나 `pkg_resources` 사용을 제거하는 것이 좋습니다.

## 가상 환경에서 확인하기

~~~bash
python --version
python -m pip show setuptools
python -c "import pkg_resources; print(pkg_resources.__file__)"
~~~

Python 3.12 이상에서는 Setuptools가 자동으로 설치되지 않을 수 있습니다. 또한 Setuptools 82 이상이라면 `pkg_resources`가 제거된 것이므로, 단순 재설치 대신 의존성의 마이그레이션 가능 여부를 확인해야 합니다.

## 피해야 할 복구 방법

- `curl ... -O | python` 형태로 설치 스크립트를 파이프하는 명령은 파일 저장 옵션과 표준 출력 동작이 맞지 않아 올바른 설치 방식이 아닙니다.
- 시스템 Python에 무작정 `sudo pip install`을 실행하거나 OS가 관리하는 pip를 제거하지 마세요.
- `setuptools`를 최신 버전으로 올리면 `pkg_resources`가 돌아온다고 가정하지 마세요.
