## 한눈에 보는 프로젝트와 해결하려는 문제

Kibana는 Elasticsearch의 데이터를 탐색, 분석, 시각화하는 대시보드 도구이다. 단순히 데이터를 보여주는 것을 넘어, 사용자가 대규모 로그, 메트릭, 보안 이벤트 등을 실시간으로 모니터링하고 관리할 수 있도록 돕는 역할을 한다. 이 프로젝트는 데이터 분석가와 엔지니어가 복잡한 쿼리 언어를 직접 다루지 않고도 직관적인 UI를 통해 인사이트를 도출할 수 있게 하는 데 목적이 있다.

주요 사용자층은 시스템 운영자, 데이터 분석가, 보안 관제 담당자이며, 프로젝트 유형은 대규모 웹 애플리케이션 및 개발 플랫폼이다. `package.json`에 명시된 바와 같이, Kibana는 Elasticsearch와 긴밀하게 통합되어 동작하며, 데이터 시각화와 대시보드 구성에 최적화된 기능을 제공한다.

## 이해에 필요한 핵심 개념

Kibana를 이해하기 위해서는 다음의 핵심 개념을 파악해야 한다.

1. **Elasticsearch와의 버전 호환성**: Kibana는 Elasticsearch와 버전이 밀접하게 연동된다. `README.md`에 따르면, 메이저 버전은 반드시 엄격히 일치해야 하며(Major Versions: Must strictly match), Kibana의 패치 버전이 앞서거나(Kibana Patch Ahead) Kibana의 마이너 버전이 뒤처지는 경우(Kibana Minor Behind) 등의 예외적인 호환 규칙을 지원한다. 이는 데이터 구조와 API의 안정성을 보장하기 위한 설계이다.
2. **플러그인 아키텍처**: Kibana는 핵심 기능 위에 다양한 플러그인을 얹는 구조로 설계되었다. `src/platform/test/examples/config.js`와 같은 설정 파일은 테스트 환경에서 플러그인을 동적으로 로드하는 방식을 보여준다.
3. **Saved Objects**: Kibana에서 생성한 대시보드, 시각화, 검색 설정 등을 저장하는 메커니즘이다. 이는 사용자의 작업 상태를 영구적으로 보존하고 공유할 수 있게 한다.

## 저장소 구조와 실제 동작 흐름

저장소는 매우 방대한 규모를 자랑하며, 크게 핵심 플랫폼, 테스트 도구, CI/CD 및 설정 스크립트로 구성된다.

- `src/platform/`: Kibana의 플랫폼 코드가 위치한다. 여기에는 테스트 인프라와 플러그인 로딩 시스템이 포함된다.
- `.agents/`: 파일 경로 목록에서 확인되듯 가이드라인, 스크립트, 훅 파일 등이 위치하는 공간이다.
- `.buildkite/`: CI/CD 파이프라인 설정이 포함되어 있으며, 특히 `ftr-manifests` 폴더를 통해 다양한 환경에 대한 기능 테스트(Functional Test Runner, FTR) 구성을 관리한다.

동작 흐름은 사용자가 `pnpm start`를 실행하면 `scripts/kibana`를 통해 서버가 구동되고, 설정된 플러그인들이 로드되어 브라우저 인터페이스를 제공하는 방식이다.

## 구체적인 예제로 보는 설계 선택

`src/platform/test/examples/config.js` 파일을 보면 Kibana가 어떻게 테스트 환경을 구성하는지 알 수 있다.

```javascript
export default async function ({ readConfigFile }) {
  const functionalConfig = await readConfigFile(require.resolve('../functional/config.base.js'));

  return {
    testConfigCategory: ScoutTestRunConfigCategory.UI_TEST,
    // ...
    kbnTestServer: {
      ...functionalConfig.get('kbnTestServer'),
      serverArgs: [
        ...functionalConfig.get('kbnTestServer.serverArgs'),
        '--env.name=development',
        '--telemetry.optIn=false',
        ...findTestPluginPaths(resolve(REPO_ROOT, 'examples')),
      ],
    },
  };
}
```

이 코드는 `functionalConfig`를 기반으로 테스트 환경을 확장한다. 특히 `findTestPluginPaths`를 사용하여 `examples` 폴더 내의 플러그인을 자동으로 탐색하고 로드하는 설계는, 개발자가 새로운 기능을 추가할 때 기존 설정을 최소한으로 수정하게 하여 확장성을 높인다.

## 대안과 비교했을 때의 장단점

Kibana는 Elasticsearch 생태계 내에서 독보적인 위치를 차지한다.

- **장점**: Elasticsearch와의 긴밀한 통합, 방대한 시각화 라이브러리, 엔터프라이즈급 권한 관리 기능.
- **단점**: Elasticsearch 이외의 데이터 소스를 활용하기에는 제약이 따른다. Grafana와 비교했을 때, Grafana는 다중 데이터 소스 연동에 더 유연하지만, Kibana는 Elastic Stack 내에서의 데이터 처리 성능과 기능적 깊이가 뛰어나다.

## 한계와 추천 대상

Kibana는 대규모 Elastic Stack을 운영하는 조직에 가장 적합하다. 반면, 가벼운 대시보드 도구가 필요한 소규모 프로젝트나 Elasticsearch를 사용하지 않는 환경에서는 과도한 설정과 리소스가 요구될 수 있다.

- **추천 대상**: Elastic Stack을 이미 사용 중이거나, 강력한 로그 분석 및 시각화 도구가 필요한 엔터프라이즈 환경.
- **확인할 점**: 도입 전 `CONTRIBUTING.md`와 `README.md`를 통해 개발 환경 구성 방법을 숙지하고, 현재 사용 중인 Elasticsearch 버전과의 호환성을 검토할 것.
