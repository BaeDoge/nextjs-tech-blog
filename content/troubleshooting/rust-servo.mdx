## 한눈에 보는 프로젝트와 해결하려는 문제

Servo는 실행 가능한 웹 브라우저 엔진 프로젝트입니다. 이 프로젝트는 기존의 거대하고 복잡한 C++ 기반 브라우저 엔진(Chromium의 Blink, WebKit 등)이 안고 있는 메모리 안전성 문제와 병렬 처리의 복잡성을 해결하기 위해 Rust 언어로 설계되었습니다.

Servo가 해결하려는 핵심 문제는 두 가지입니다. 첫째, 웹 표준을 준수하면서도 메모리 안전성을 확보하는 것입니다. C++ 기반 엔진에서는 Use-After-Free와 같은 메모리 오류가 보안 취약점으로 이어지기 쉬운데, Rust의 컴파일 타임 소유권 검사(Ownership)와 타입 시스템을 통해 이를 원천적으로 차단하고자 합니다. 둘째, 임베딩 친화적인 경량 아키텍처를 제공하는 것입니다. Servo는 단일 거대한 브라우저 실행을 넘어, 개발자가 자신의 데스크톱 애플리케이션이나 모바일 앱에 웹 렌더링 기능을 손쉽게 통합할 수 있는 '웹 엔진'으로서의 역할을 수행합니다. 이를 위해 불필요한 UI 레이어를 분리하고, `servoshell`과 같은 경량 포트를 통해 엔진의 핵심 기능만 테스트하고 활용하도록 설계되었습니다.

## 이해에 필요한 핵심 개념

Servo의 아키텍처를 이해하기 위해서는 다음 두 가지 핵심 개념이 필요합니다.

첫째, **Rust 기반 메모리 안전성**입니다. Servo는 DOM(Document Object Model) 객체의 수명 관리를 위해 Rust의 강력한 타입 시스템과 소유권 모델을 활용합니다. 기존 브라우저들이 JavaScript와 네이티브 코드 간 객체 참조를 관리하기 위해 참조 카운팅을 사용하며 이로 인한 순환 참조 문제를 겪는 반면, Servo는 Rust의 컴파일 타임 검사를 통해 메모리 오류를 사전에 방지합니다. 이는 `components/script/docs/JS-Servos-only-GC.md` 문서에서 설명하듯, 크로스-언어 데이터 구조의 안전성을 확보하는 핵심 메커니즘입니다.

둘째, **임베딩 친화적 설계**입니다. Servo는 브라우저 전체를 실행하는 것이 아니라, 특정 애플리케이션 내에서 웹 콘텐츠를 렌더링하는 라이브러리 형태로 활용될 수 있도록 설계되었습니다. 이는 `ports/servoshell`과 같은 포트를 통해 엔진의 핵심 기능만 테스트하고 활용하도록 하며, 불필요한 UI 레이어를 분리하여 개발자가 필요한 기능만 선택적으로 사용할 수 있게 합니다.

## 저장소 구조와 실제 동작 흐름

Servo의 저장소는 모듈화된 컴포넌트 구조를 취하고 있으며, 각 컴포넌트는 명확한 책임과 연결 관계를 가집니다.

- `components/`: 엔진의 핵심 기능을 담당하는 모듈들이 위치합니다. `components/constellation`은 브라우징 컨텍스트와 세션 히스토리 등을 관리하며, `components/script`는 자바스크립트 엔진과의 상호작용을 담당합니다.
- `ports/`: 엔진을 실제 환경에서 실행하기 위한 포트가 포함되어 있습니다. `ports/servoshell`은 엔진의 핵심 기능을 테스트하고 활용하기 위한 경량 브라우저 셸입니다.
- `mach`: 프로젝트 빌드, 테스트, 개발 환경 설정을 관리하는 파이썬 기반의 도구입니다. `mach`를 통해 개발자는 빌드(`mach build`)나 부트스트랩(`mach bootstrap`)을 수행합니다.

동작 흐름은 `ports/servoshell`에서 시작하여 `components/constellation`을 통해 브라우징 컨텍스트가 생성되고, 이후 각 컴포넌트가 협력하여 웹 페이지를 파싱, 레이아웃, 렌더링하는 과정을 거칩니다.

## 구체적인 예제로 보는 설계 선택

Servo는 복잡한 웹 표준을 구현하기 위해 모듈화된 파서와 처리기를 사용합니다. 예를 들어, `components/webvtt/src/lib.rs`는 WebVTT 자막 파일을 처리하는 로직을 담고 있습니다.

```rust
pub trait WebVttParserSink<Context> {
    fn consume_cue(&self, cx: &mut Context, cue: WebVttCue);
}
```

이 코드는 `WebVttParserSink` 트레이트를 통해 파싱 결과를 외부로 전달하는 방식을 사용합니다. 파서와 소비자 간의 결합도를 낮추고 유연성을 높임으로써, 다양한 환경에서 엔진을 임베딩할 때 필요한 데이터 전달 방식을 개발자가 정의할 수 있도록 설계되었습니다. 또한 `components/xpath/src/parser.rs`의 테스트 코드에서는 `DummyNamespaceResolver`와 같은 구조를 통해 파서가 의존성 주입을 활용하여 네임스페이스를 처리하는 방식을 보여주며, 이는 엔진의 각 컴포넌트가 독립적으로 테스트 가능하도록 설계되었음을 시사합니다.

## 대안과 비교했을 때의 장단점

Servo는 Chromium(Blink)이나 WebKit과 비교했을 때 다음과 같은 특징을 가집니다.

- **장점**: Rust를 사용하여 메모리 안전성이 매우 높으며, 현대적인 병렬 처리 아키텍처를 통해 멀티코어 환경에서 효율적인 렌더링이 가능합니다. 또한, 임베딩을 목적으로 설계되어 불필요한 기능들을 제거하고 가볍게 구성할 수 있습니다.
- **단점**: Chromium이나 WebKit에 비해 생태계가 작고, 웹 호환성(Web Compatibility) 측면에서 모든 최신 웹 API를 완벽하게 지원하는 데 시간이 걸릴 수 있습니다. 또한, Rust 생태계의 특성상 빌드 시간이 길어질 수 있다는 점이 개발 생산성에 영향을 줄 수 있습니다.

## 보안·라이선스·도입 시 확인할 점

- **보안**: `SECURITY.md`에 명시된 대로 보안 취약점은 GitHub 보안 리포트를 통해 제출해야 합니다. Rust의 메모리 안전성 덕분에 메모리 관련 취약점은 현저히 낮지만, 웹 엔진 특성상 복잡한 파싱 로직에서의 논리적 결함은 여전히 주의해야 합니다.
- **라이선스**: `LICENSE` 파일에 따라 MPL-2.0(Mozilla Public License 2.0)을 따릅니다. 이는 파생물이 MPL-2.0으로 유지되도록 할 뿐 기존 파일의 소스 공개를 강제하지 않습니다. 즉, Servo 코드를 수정하여 배포할 경우 수정된 파일은 MPL-2.0 라이선스를 유지해야 하지만, Servo 코드를 포함하는 전체 애플리케이션의 소스 코드를 공개할 의무는 없습니다.
- **도입 시 확인**: 현재 프로젝트가 지원하는 플랫폼(macOS, Linux, Windows, Android, OpenHarmony)이 도입하려는 환경과 일치하는지 확인해야 합니다.

## 한계와 추천 대상

Servo는 다음과 같은 사용자에게 추천합니다.

- **임베딩 목적의 개발자**: 자신의 데스크톱 애플리케이션이나 모바일 앱에 가벼운 웹 뷰를 내장하고자 하는 개발자에게 적합합니다.
- **Rust 생태계 기여자**: 고성능 브라우저 엔진의 내부 구조를 학습하고 Rust의 고급 기능을 활용한 대규모 프로젝트에 기여하고 싶은 개발자에게 훌륭한 학습 자료가 됩니다.

반면, 일반적인 웹 브라우저 사용자나 매우 높은 웹 호환성이 요구되는 복잡한 웹 애플리케이션을 개발하는 경우에는 기존의 성숙한 엔진(Chromium 등)을 사용하는 것이 더 나은 선택일 수 있습니다. Servo는 여전히 발전 중인 엔진이므로, 최신 웹 표준 지원 범위가 프로젝트의 요구사항을 충족하는지 사전에 철저히 검증해야 합니다.
