## 현상

Linux에서 `pip` 또는 `pip3` 명령을 실행할 때 다음과 같은 오류가 발생할 수 있습니다.

```text
Traceback (most recent call last):
  File "/usr/bin/pip3", line 9, in <module>
    from pip import main
ImportError: cannot import name 'main' from 'pip'
```

이 오류는 시스템 패키지 관리자가 설치한 `pip3` 실행 스크립트와 실제 import되는 pip 패키지 버전이 서로 맞지 않을 때 발생할 수 있습니다.

## 원인

오래된 `pip3` 실행 스크립트는 내부 함수 `pip.main`을 import하는 형태로 만들어진 경우가 있습니다. pip 10.0 이후 내부 구조가 바뀌면서 해당 진입점이 제거되었고, 스크립트만 예전 버전으로 남아 있거나 Python이 다른 위치의 pip 패키지를 import하면 실행 스크립트와 모듈이 맞지 않아 오류가 발생합니다.

특히 `/usr/bin/pip3`가 apt 같은 운영체제 패키지 관리자로 설치되었다면, `sudo pip install --upgrade pip`로 시스템 pip를 직접 덮어쓰는 것은 패키지 관리 상태를 더 꼬이게 만들 수 있습니다.

## 해결 방법

먼저 어떤 Python과 pip가 실행되는지 확인합니다.

```bash
which python3
which pip3
python3 --version
python3 -m pip --version
```

`python3 -m pip`가 정상 동작한다면 `pip3` 실행 스크립트 대신 해당 명령을 사용합니다.

```bash
python3 -m pip install numpy
```

시스템 pip 자체가 손상되었고 Debian/Ubuntu 계열에서 apt로 관리하는 패키지라면, pip를 직접 제거하거나 `get-pip.py`로 덮어쓰기보다 배포판 패키지 관리자를 통해 복구합니다.

```bash
sudo apt update
sudo apt install --reinstall python3-pip
```

배포판별 패키지 이름과 관리 방법은 다를 수 있으므로, 사용하는 Linux 배포판의 공식 패키지 관리 문서를 따릅니다.

## 다른 해결 방법

프로젝트 의존성 설치에는 시스템 pip를 변경하지 말고 가상환경을 사용하는 것이 좋습니다.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install numpy
```

가상환경 안에서는 `python -m pip`가 해당 가상환경의 Python에 연결된 pip를 호출하므로, 시스템 pip와 분리해 관리할 수 있습니다.

## 추가 참고사항

- 시스템 Python의 pip를 `sudo pip install --upgrade pip`로 직접 교체하지 않습니다.
- `get-pip.py`는 시스템 패키지 관리자가 소유한 Python 환경을 덮어쓰는 용도로 사용하지 않습니다.
- `python -m pip --version`과 `python -c "import sys; print(sys.executable)"`를 함께 확인하면 실행 중인 Python과 pip가 같은 환경인지 진단할 수 있습니다.
- 오래된 시스템 스크립트가 남아 있다면 운영체제 패키지 관리자로 재설치하거나, 프로젝트 단위 가상환경을 사용하는 것이 안전합니다.
