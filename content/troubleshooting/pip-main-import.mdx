## 현상

`pip` 또는 `pip3` 명령을 실행할 때 다음과 같은 오류가 발생할 수 있습니다.

~~~text
ImportError: cannot import name 'main' from 'pip'
~~~

특히 운영체제 패키지 관리자가 설치한 오래된 `pip` 실행 스크립트가, 별도로 업그레이드된 pip 패키지와 맞지 않을 때 나타날 수 있습니다.

## 원인

pip 10부터 내부 API가 변경되면서 예전 실행 스크립트에서 사용하던 `pip.main()` 진입점이 제거되었습니다. 그런데 기존 `pip` 또는 `pip3` 스크립트가 계속 `from pip import main`을 호출하면, 설치된 pip 버전과 실행 스크립트 사이에 불일치가 발생합니다.

## 해결 방법

### 1. 우선 Python 모듈 방식으로 pip 실행

실행 스크립트 대신 현재 Python 인터프리터가 설치한 pip 모듈을 호출합니다.

~~~bash
python3 -m pip --version
python3 -m pip install numpy
~~~

Windows에서는 대상 인터프리터를 분명히 하기 위해 `py -m pip` 또는 가상 환경의 `python -m pip`를 사용할 수 있습니다.

### 2. 가상 환경 사용 권장

시스템 Python에 직접 패키지를 설치하거나 운영체제에서 관리하는 pip를 제거하는 대신, 프로젝트별 가상 환경을 사용하는 편이 안전합니다.

~~~bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install numpy
~~~

Windows CMD에서는 다음과 같이 활성화합니다.

~~~bat
.venv\Scripts\activate.bat
python -m pip install --upgrade pip
~~~

### 3. 시스템 pip 자체가 손상된 경우

Ubuntu나 Debian처럼 운영체제 패키지 관리자가 Python과 pip를 관리하는 환경에서는 `sudo pip uninstall`로 시스템 패키지를 제거하지 마세요. 배포판의 패키지 관리자로 해당 패키지를 복구하거나 재설치하고, 애플리케이션 패키지는 가상 환경에 설치하는 것이 안전합니다.

## 확인 사항

- `python --version`과 `python3 --version`이 서로 다른 인터프리터를 가리키는지 확인합니다.
- `python -m pip --version`으로 pip가 어느 Python 경로에 설치되어 있는지 확인합니다.
- 프로젝트가 가상 환경을 사용한다면 활성화한 뒤 그 환경의 `python -m pip`를 실행합니다.
