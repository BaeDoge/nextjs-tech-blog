## 현상

Pandas DataFrame의 열을 슬라이싱한 객체에 스칼라 값을 곱하거나 할당할 때 `SettingWithCopyWarning`이 발생한다.
다음과 같이 슬라이싱된 DataFrame의 열에 직접 연산을 시도하면 경고가 출력된다.

```python
df_slice = df[['quantity']]
df_slice['quantity'] *= -1
```

출력되는 경고 메시지는 다음과 같다.

```
SettingWithCopyWarning: 
A value is trying to be set on a copy of a slice from a DataFrame.
Try using .loc[row_indexer,col_indexer] = value instead
```

이 경고는 연산이 원본 데이터에 영향을 주지 않거나, 의도치 않은 복사본에서 동작하고 있음을 나타낸다.

![현상 스크린샷](/blogs/pandas-dataframe-settingwithcopywarning-091857-1.jpg)

## 원인

이 경고는 DataFrame의 슬라이싱 결과인 '뷰(view)'와 '복사본(copy)'의 구분이 모호할 때 발생한다.
Pandas는 메모리 효율을 위해 슬라이싱 시 원본을 참조하는 뷰를 반환하는 경우가 많다.
하지만 특정 조건(예: 다중 인덱싱, 필터링 등)에서는 내부적으로 복사본을 생성하기도 한다.
사용자가 슬라이싱된 객체에 할당 연산을 수행할 때, Pandas는 이것이 원본의 열을 수정하는 것인지, 아니면 복사본의 열을 수정하는 것인지 명확하지 않은 경우가 있다.
이러한 불명확한 상태에서의 할당 연산은 예기치 않은 결과를 초래할 수 있으므로 Pandas가 경고를 출력한다.

## 해결 방법

경고를 방지하고 원본 DataFrame의 열을 명확하게 수정하려면 슬라이싱 시 `.copy()` 메서드를 사용하여 명시적으로 복사본을 생성해야 한다.
이렇게 하면 현재 작업 중인 객체가 원본과 독립적인 복사본임이 명확해져 경고가 발생하지 않는다.

```python
df_slice = df[['quantity']].copy()
df_slice['quantity'] *= -1
```

또는 `.loc` 인덱서를 사용하여 원본 DataFrame의 열을 직접 수정하는 방법도 있다.
`.loc`은 명시적으로 원본 데이터의 위치를 지정하므로, Pandas가 복사본이 아닌 원본을 수정한다고 판단한다.

```python
df.loc[:, 'quantity'] *= -1
```

이 방법은 `SettingWithCopyWarning`을 발생시키지 않으며, 의도한 대로 원본 데이터가 수정된다.

## 다른 해결 방법

만약 현재 작업 중인 DataFrame이 이미 복사본임을 인지하고 있고, 경고가 원본 데이터 변경에 영향을 미치지 않음을 확신한다면, 경고를 무시할 수 있다.
하지만 이는 권장되지 않으며, 코드의 의도를 명확히 하는 것이 좋다.
또한, DataFrame을 생성하거나 슬라이싱할 때 `.copy()` 메서드를 명시적으로 사용하여 복사본임을 명확히 할 수도 있다.

```python
df_copy = df[['quantity']].copy()
df_copy['quantity'] *= -1
```

이 경우 `df_copy`는 독립적인 복사본이므로 원본에 영향을 주지 않으며, 경고도 발생하지 않는다.

## 추가 참고사항

<Callout type="info" title="참고 사항">
Pandas 2.0부터는 `Copy-on-Write` 기능이 도입되어 이 경고의 발생 여부와 처리 방식이 달라질 수 있다.
</Callout>

- `.loc`을 사용하는 것이 가장 표준적이고 안전한 해결 방법이다.
- `iterrows()`를 사용하여 루프를 돌며 개별 셀을 수정하는 것은 성능상 비효율적이며, 이 문제의 근본 해결책이 아니다.
- DataFrame 슬라이싱 시 `.copy()`를 명시적으로 호출하면 복사본임을 명확히 하여 경고 발생을 피할 수 있다.
- 이 경고는 에러가 아니므로 프로그램 실행을 중단시키지 않지만, 데이터 무결성을 위해 주의가 필요하다.
