## 현상

DataFrame에서 조건에 맞는 행만 선택한 다음, 다시 열을 선택해 값을 할당하면 SettingWithCopyWarning이 나타날 수 있습니다.

~~~~python
import pandas as pd

df = pd.DataFrame({
    "quantity": [2, -1, 5],
    "enabled": [True, True, False],
})

# 두 번 인덱싱하는 chained assignment
df["quantity"][df["enabled"]] = 0
~~~~

이 코드는 먼저 df["quantity"]로 Series를 선택하고, 그 결과에 다시 조건을 적용해 값을 변경합니다. 원본 DataFrame까지 수정하려는 의도가 코드 한 줄에 명확하게 표현되지 않는 것이 문제입니다.

## 원인

Pandas 2.x의 기본 동작에서는 인덱싱 결과가 원본 데이터를 공유하는지 여부가 연산에 따라 달라질 수 있었습니다. chained assignment는 중간에 만들어진 Series나 DataFrame을 수정하기 때문에 원본까지 변경되는지 보장하기 어렵고, 이때 SettingWithCopyWarning이 발생할 수 있습니다.

모든 슬라이싱 결과가 같은 방식으로 경고를 발생시키는 것은 아닙니다. 별도 변수에 필터 결과를 저장한 뒤 수정하는 코드와, 한 문장에서 연속 인덱싱을 하는 코드는 구분해야 합니다.

## 해결 방법 1. 원본 DataFrame을 수정하려는 경우

원본을 변경하는 것이 목적이라면 조건과 열을 하나의 loc 할당으로 표현합니다.

~~~~python
mask = df["enabled"]
df.loc[mask, "quantity"] = 0
~~~~

이 코드는 원본 DataFrame의 enabled가 참인 행에서 quantity 열을 직접 수정합니다. Pandas 공식 문서에서도 chained assignment 대신 loc을 사용하도록 안내합니다.

## 해결 방법 2. 독립된 DataFrame을 만들려는 경우

필터링한 결과만 별도로 가공하고 원본은 유지하려면 copy()를 명시합니다.

~~~~python
selected = df.loc[df["enabled"], ["quantity"]].copy()
selected["quantity"] = 0
~~~~

이 경우 selected는 별도의 작업 대상입니다. selected의 값을 변경해도 원본 df의 값은 바뀌지 않습니다.

## pandas 버전에 따른 차이

- **pandas 2.x:** Copy-on-Write가 기본으로 강제되지 않았습니다. 실행 설정과 인덱싱 방식에 따라 chained assignment에서 SettingWithCopyWarning이 나타날 수 있습니다. pandas 2.2에서는 Copy-on-Write 경고 모드를 사용해 마이그레이션을 점검할 수 있었습니다.
- **pandas 3.0 이상:** Copy-on-Write가 기본이자 유일한 동작 방식입니다. chained assignment로 원본을 수정할 수 없으며, 이 경우 ChainedAssignmentError 경고가 발생합니다. 원본을 수정하려면 반드시 하나의 loc 할당을 사용해야 합니다.

<Callout type="info" title="참고 사항">
Pandas 2.x에서는 Copy-on-Write(CoW)를 선택적으로 활성화할 수 있습니다. Pandas 3.0부터는 CoW가 기본이자 유일한 동작 방식이며, chained assignment로 원본 DataFrame을 수정할 수 없습니다. 원본을 바꾸려면 `df.loc[행 조건, 열] = 값`처럼 한 번의 인덱싱으로 직접 할당해야 합니다.
</Callout>

## 추가 참고사항

- copy()는 독립된 작업용 데이터를 만들 때 사용합니다. 원본을 수정하려는 목적이라면 copy()로 우회하지 말고 loc으로 직접 할당해야 합니다.
- 경고를 무시하거나 전역 옵션으로 숨기는 방식은 원본 변경 여부를 명확하게 해 주지 않습니다.
- 기존 코드가 pandas 2.x에서 우연히 동작했더라도 pandas 3.x에서는 chained assignment 결과가 원본에 반영되지 않을 수 있으므로 버전 업그레이드 전에 점검해야 합니다.
