## 현상

VS Code의 PowerShell 터미널에서 가상환경을 활성화하려고 하면 다음과 같은 보안 오류가 발생합니다.

```powershell
PS C:\Users\hpoddar\Desktop\WebDev\ReactComplete\DjangoReact\ArticlesApp\APIProject> ..\venv\scripts\activate    
..\venv\scripts\activate : File C:\Users\hpoddar\Desktop\WebDev\ReactComplete\DjangoReact\ArticlesApp\venv\scripts\Activate.ps1 cannot be loaded because running 
scripts is disabled on this system.
At line:1 char:1
+ ..\venv\scripts\activate
+ ~~~~~~~~~~~~~~~~~~~~~~~~
    + CategoryInfo          : SecurityError: (:) [], PSSecurityException
    + FullyQualifiedId : UnauthorizedAccess
```

![현상 스크린샷](/blogs/vs-code-powershell-activate-ps1-1.png)

## 원인

Windows PowerShell의 기본 실행 정책(Execution Policy)이 `Restricted`로 설정되어 있기 때문입니다. 이 정책은 개별 명령은 허용하지만 스크립트 파일(.ps1)의 실행은 차단합니다. 가상환경의 `Activate.ps1`은 스크립트이므로, 현재 사용자의 실행 정책이 이를 허용하지 않으면 보안 예외(PSSecurityException)가 발생합니다.

## 해결 방법

먼저 현재 세션에 적용되는 실행 정책과 각 범위의 설정을 확인합니다. `CurrentUser` 범위는 관리자 권한 없이 현재 사용자에게만 적용되지만, 조직의 Group Policy가 설정되어 있으면 해당 정책이 우선할 수 있습니다.

```powershell
# 현재 적용 정책과 우선순위 확인
Get-ExecutionPolicy -List

# 현재 사용자 범위의 로컬 스크립트 실행 허용
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

# 변경 후 현재 적용 정책 확인
Get-ExecutionPolicy
```

![해결 방법 스크린샷](/blogs/vs-code-powershell-activate-ps1-2.png)

## 다른 해결 방법

PowerShell 정책 변경이 조직의 Group Policy에 의해 제한되었거나 변경을 원하지 않는 경우, VS Code의 터미널 프로필을 명령 프롬프트(cmd.exe)로 바꾸어 `.bat` 활성화 스크립트를 사용할 수 있습니다. 조직의 보안 정책을 우회하지 말고 관리자 지침을 따르세요.

```powershell
# VS Code 터미널 상단 드롭다운 메뉴에서 'Select Default Profile' 선택
# 목록에서 'Command Prompt'를 선택하여 기본 터미널 프로필로 지정
```

## 추가 참고사항

가상환경 활성화가 실패하는 다른 원인으로는 프로젝트 루트가 아닌 위치에서 실행하거나 활성화 스크립트가 존재하지 않는 경우가 있습니다. PowerShell에서는 `.venv\\Scripts\\Activate.ps1`, 명령 프롬프트에서는 `.venv\\Scripts\\activate.bat`을 실행해야 합니다. 터미널 환경에 맞는 스크립트를 선택하고, 활성화 후 `python -c "import sys; print(sys.executable)"`로 실제 인터프리터 경로를 확인합니다. 활성화 성공 여부는 프롬프트 앞에 `(.venv)` 표시나 `python -c "import sys; print(sys.executable)"` 명령으로 가상환경 경로를 확인하여 검증할 수 있습니다.
