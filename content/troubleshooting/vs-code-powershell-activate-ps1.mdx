## 현상

VS Code의 PowerShell 터미널에서 가상환경을 활성화하려고 하면 다음과 같은 보안 오류가 발생합니다.

```powershell
PS C:\Users\hpoddar\Desktop\WebDev\ReactComplete\DjangoReact\ArticlesApp\APIProject> ..\venv\scripts\activate    
..\venv\scripts\activate : File C:\Users\hpoddar\Desktop\WebDev\ReactComplete\DjangoReact\ArticlesApp\venv\scripts\Activate.ps1 cannot be loaded because running 
scripts is disabled on this system.
At line:1 char:1
+ ..\venv\scripts\activate
+ ~~~~~~~~~~~~~~~~~~~~~~~~
    + CategoryInfo          : SecurityError: (:) [], PSSecurityException
    + FullyQualifiedId : UnauthorizedAccess
```

![현상 스크린샷](/blogs/vs-code-powershell-activate-ps1-1.png)

## 원인

Windows PowerShell의 기본 실행 정책(Execution Policy)이 `Restricted`로 설정되어 있기 때문입니다. 이 정책은 개별 명령은 허용하지만 스크립트 파일(.ps1)의 실행은 차단합니다. 가상환경의 `Activate.ps1`은 스크립트이므로, 현재 사용자의 실행 정책이 이를 허용하지 않으면 보안 예외(PSSecurityException)가 발생합니다.

## 해결 방법

현재 사용자의 PowerShell 실행 정책을 `RemoteSigned`로 변경하여 로컬 스크립트의 실행을 허용합니다. 이 방법은 관리자 권한 없이 현재 계정에만 적용됩니다.

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

![해결 방법 스크린샷](/blogs/vs-code-powershell-activate-ps1-2.png)

## 다른 해결 방법

PowerShell의 실행 정책 변경이 불가능하거나 원치 않는 경우, VS Code 터미널의 기본 프로필을 PowerShell 대신 명령 프롬프트(cmd.exe)로 변경할 수 있습니다. 명령 프롬프트는 `.bat` 스크립트를 사용하므로 해당 실행 정책 제한을 받지 않습니다.

```powershell
# VS Code 터미널 상단 드롭다운 메뉴에서 'Select Default Profile' 선택
# 목록에서 'Command Prompt'를 선택하여 기본 터미널 프로필로 지정
```

## 추가 참고사항

가상환경 활성화가 실패하는 다른 원인으로는 프로젝트 루트 폴더에 있지 않거나, 활성화 스크립트가 존재하지 않는 경우(.venv 폴더 미생성)가 있습니다. PowerShell에서는 `Activate.ps1`을, 명령 프롬프트에서는 `activate.bat`을 실행해야 하며, 터미널 환경에 맞는 스크립트를 선택해야 합니다. 활성화 성공 여부는 프롬프트 앞에 `(.venv)` 표시나 `python -c "import sys; print(sys.executable)"` 명령으로 가상환경 경로를 확인하여 검증할 수 있습니다.
