## 현상

`sys.path`에 포함되지 않은 파일 시스템의 절대 경로에 있는 모듈을 임포트하려고 할 때 `ModuleNotFoundError`가 발생한다.
일반적인 `import` 구문은 모듈명이나 `sys.path` 내의 경로로 동작하므로, 임의의 위치에 있는 파일을 직접 로드할 수 없다.
예를 들어 `/path/to/file.py`에 있는 `MyClass`를 로드하려 할 때 다음처럼 접근하면 에러가 발생한다.

```python
import importlib.util
spec = importlib.util.spec_from_file_location("module.name", "/path/to/file.py")
foo = importlib.util.module_from_spec(spec)
# foo.MyClass()  <- 호출 시 AttributeError 발생 가능
```

## 원인

파이썬 인터프리터는 모듈을 찾을 때 `sys.modules` 및 `sys.path`를 조회하여 표준화된 방식으로 모듈을 로드한다.
절대 경로가 단순히 파일 경로일 뿐, 파이썬은 이를 모듈 이름이나 `sys.path` 경로로 자동 인식하지 못한다.
따라서 파일 객체 자체를 모듈 로딩 시스템이 인식할 수 있도록 스펙(Spec)을 생성하고 모듈 객체를 `sys.modules`에 명시적으로 등록해야 한다.
이 과정이 생략되면 인터프리터는 해당 파일을 로드할 수 없는 상태로 둔다.

## 해결 방법

`importlib.util.spec_from_file_location()`으로 파일 경로에서 모듈 스펙을 만들고, `module_from_spec()`과 `exec_module()`을 사용해 모듈 객체를 생성하고 실행합니다. 아래 예시는 파일이 존재하고 Python 소스 파일로 로드 가능한지 확인하고, 실행 도중 오류가 발생하면 `sys.modules`에 임시 등록한 항목을 정리합니다.

```python
import importlib.util
import sys
from pathlib import Path

module_name = "custom_plugin"  # 충돌하지 않는 고유한 이름 사용
file_path = Path("/path/to/file.py")

spec = importlib.util.spec_from_file_location(module_name, file_path)
if spec is None or spec.loader is None:
    raise ImportError(f"모듈을 로드할 수 없습니다: {file_path}")

if module_name in sys.modules:
    raise ImportError(f"이미 등록된 모듈 이름입니다: {module_name}")

module = importlib.util.module_from_spec(spec)
sys.modules[module_name] = module
try:
    spec.loader.exec_module(module)
except Exception:
    sys.modules.pop(module_name, None)
    raise

instance = module.MyClass()
```

이 방식은 파일의 코드를 실제로 실행합니다. 따라서 경로를 신뢰할 수 있는지 확인하고, 외부 입력으로 전달된 임의 파일 경로를 그대로 로드하지 않아야 합니다.

## 다른 해결 방법

파일을 모듈로 등록하거나 재사용할 필요 없이 스크립트를 실행하고 전역 변수 사전만 가져오면 되는 경우에는 `runpy.run_path()`를 사용할 수 있습니다. 이는 `import`와 완전히 같은 동작은 아니므로, 모듈 캐시나 패키지 하위 모듈 기능이 필요한 상황에서는 위의 `importlib` 방식을 사용합니다.

```python
import runpy

namespace = runpy.run_path("/path/to/file.py")
MyClass = namespace["MyClass"]
instance = MyClass()
```

`SourceFileLoader.load_module()`은 레거시 API로 Python 3.4부터 `exec_module()` 방식으로 대체되었으며 Python 3.15에서 제거되었습니다. `imp.load_source()`는 Python 3.4부터 폐기 예정(deprecated)이었고 Python 3.12에서 `imp` 모듈이 제거되면서 사용할 수 없게 되었습니다. 신규 코드에서는 두 API를 사용하지 않는 것이 좋습니다.

```python
# 레거시 예시: 신규 코드에서 사용하지 마세요.
# from importlib.machinery import SourceFileLoader
# module = SourceFileLoader("custom_plugin", "/path/to/file.py").load_module()
```

## 추가 참고사항

<Callout type="warning" title="경로와 모듈명 주의">
`importlib` 함수에 전달하는 첫 번째 인자인 모듈명("module.name")은 실제 파일의 디렉토리 구조와 일치하지 않아도 된다. 다만 `sys.modules`에 등록될 키가 되므로 충돌이 발생하지 않도록 고유한 이름을 선택해야 한다.
</Callout>

모듈이 같은 이름으로 여러 번 로드되지 않도록 주의해야 한다.
이미 `sys.modules`에 해당 키가 존재하면 `module_from_spec`으로 새로 만든 객체가 덮어씌워질 수 있으므로, 로딩 전 키 존재 여부를 확인하는 것이 안전하다.
