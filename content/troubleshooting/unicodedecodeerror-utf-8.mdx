## 현상

Python 3.5.2 환경에서 이미지 파일(`.jpg`)을 텍스트 파일로 읽어오는 과정에서 에러가 발생합니다.
에러는 파일의 첫 바이트(0xff)가 utf-8 코딩 규칙에 맞지 않아 발생하였습니다.

```python
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff in position 0: invalid start byte
```

재현 코드:

```python
# tools/process.py 의 일부
contents = open(path).read()
```

## 원인

`open()` 함수는 기본적으로 텍스트 모드(`'r'`)로 파일을 열며, 이를 위해 바이트 시퀀스를 문자열로 디코딩하려 합니다.
일반적으로 UTF-8 인코딩을 사용하므로, JPEG 이미지와 같은 바이너리 데이터의 첫 바이트인 `0xff`는 유효한 UTF-8 시작 바이트가 아닙니다.
따라서 Python은 이를 문자열로 변환하는 디코딩 단계에서 `UnicodeDecodeError`를 발생시킵니다.

## 해결 방법

파일 내용을 문자열이 아닌 바이트 객체(`bytes`)로 읽어야 하므로, `open()` 함수의 모드 파라미터를 `'rb'`(바이너리 읽기 모드)로 변경합니다.

수정 전:

```python
contents = open(path).read()
```

수정 후:

```python
with open(path, 'rb') as f:
    contents = f.read()
```

## 다른 해결 방법

파일의 인코딩이 UTF-8이 아니거나, 텍스트 파일임에도 인코딩이 명시되지 않은 경우 발생할 수 있습니다.
이 경우 `open()` 함수에 `encoding` 파라미터를 명시하여 해당 인코딩을 지정하여 해결할 수 있습니다.

예시:

```python
with open(path, 'r', encoding='euc-kr') as f:
    contents = f.read()
```

하지만 현상에서 나타난 `0xff` 바이트 오류는 이미지가 바이너리 파일임을 명시하므로, 위 해결 방법보다는 바이너리 모드 사용이 근본적인 해결책입니다.

## 추가 참고사항

텍스트 파일을 읽을 때 `UnicodeDecodeError`가 발생하면 파일의 인코딩을 확인하거나 `encoding` 파라미터를 설정해야 합니다.
`open()` 함수의 디폴트 동작이 환경이나 OS에 따라 다를 수 있으므로, 텍스트 파일 처리 시 `encoding` 명시 및 바이너리 파일 처리 시 `'rb'` 모드 사용을 권장합니다.
