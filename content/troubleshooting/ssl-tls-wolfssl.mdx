## 한눈에 보는 프로젝트와 해결하려는 문제

wolfSSL은 임베디드 장치, IoT 기기, 그리고 클라우드 환경에서 보안 통신을 구현하기 위해 설계된 라이브러리입니다. 과거 CyaSSL로 알려졌던 이 프로젝트는 ANSI C로 작성되어 이식성이 뛰어나며, OpenSSL 대비 훨씬 작은 메모리 풋프린트(일반적으로 20~100kB)를 제공하는 것을 목표로 합니다.

이 프로젝트는 라이브러리 형태로 제공되며, TLS 1.3 및 DTLS 1.3과 같은 최신 보안 표준을 지원합니다. 특히 리소스가 극도로 제한된 환경에서도 암호화 통신을 가능하게 함으로써, 보안이 취약할 수 있는 IoT 기기의 보안성을 강화하는 문제를 해결합니다.

## 이해에 필요한 핵심 개념

wolfSSL을 이해하기 위해서는 다음 세 가지 핵심 개념을 파악해야 합니다.

1. **wolfCrypt**: wolfSSL의 기반이 되는 암호화 라이브러리입니다. FIPS 140-2 및 140-3 인증을 받은 암호화 모듈을 포함하며, 라이브러리의 모든 보안 연산을 담당합니다.
2. **OpenSSL 호환성 API**: 기존 OpenSSL 기반 애플리케이션을 wolfSSL로 쉽게 이식할 수 있도록 돕는 호환 계층입니다. 이를 통해 개발자는 기존 코드를 크게 수정하지 않고도 라이브러리를 교체할 수 있습니다.
3. **Crypto Callback (CryptoCB)**: 하드웨어 가속기나 보안 요소(Secure Element)를 활용하기 위한 인터페이스입니다. 암호화 연산을 CPU가 아닌 전용 하드웨어로 오프로드하여 성능을 높이고 키를 안전하게 격리합니다.

## 저장소 구조와 실제 동작 흐름

저장소는 방대한 이식성과 테스트 환경을 반영하는 구조를 가집니다.

- `wolfcrypt/`: 암호화 알고리즘 구현체들이 위치하며, 하드웨어 포팅 계층이 포함되어 있습니다.
- `IDE/`: PlatformIO, STM32 등 다양한 개발 환경에서의 빌드 예제를 제공합니다.
- `tests/`: Zephyr RTOS 환경에서의 테스트 및 포팅 코드가 포함되어 있습니다.

사용자는 `configure` 스크립트나 `CMake`를 통해 자신의 환경에 맞는 기능을 활성화(Enable)하거나 비활성화(Disable)하여 라이브러리를 빌드합니다. 이후 애플리케이션은 `wolfssl/` 헤더 파일을 포함하여 API를 호출하고, `wolfSSL_Init()`으로 초기화한 뒤 세션을 생성하는 흐름을 따릅니다.

## 구체적인 예제로 보는 설계 선택

`zephyr/tests/wolfssl_condvar/src/main.c` 파일은 wolfSSL이 RTOS 환경에서 스레드 동기화를 어떻게 처리하는지 잘 보여줍니다.

```c
    /* Yield so the consumer generally reaches wolfSSL_CondWait() first. The
     * handshake must still be correct if it does not, because the consumer
     * re-checks the predicate under the lock before each wait. */
    k_msleep(50);

    (void)wolfSSL_CondStart(&g_cond);
    g_predicate = 1;
    (void)wolfSSL_CondSignal(&g_cond);
    (void)wolfSSL_CondEnd(&g_cond);
```

이 코드는 POSIX 스레드 환경이 아닌 RTOS 환경에서도 일관된 동기화 동작을 보장하기 위해, wolfSSL이 자체적인 추상화 계층(`CondStart`, `CondWait`, `CondEnd`)을 설계했음을 보여줍니다. 이는 다양한 OS 환경으로 이식할 때 하드웨어/OS 종속성을 최소화하려는 라이브러리의 설계 철학을 반영합니다.

## 대안과 비교했을 때의 장단점

OpenSSL과 비교했을 때 wolfSSL의 가장 큰 장점은 **크기와 이식성**입니다.

| 비교 항목 | wolfSSL | OpenSSL |
| :--- | :--- | :--- |
| **풋프린트** | 매우 작음 (20~100kB) | 상대적으로 큼 |
| **목적** | 임베디드, RTOS, IoT | 범용 서버, 데스크톱 |
| **라이선스** | GPLv3 (상용 라이선스 별도) | OpenSSL License |

wolfSSL은 리소스가 제한된 환경에서 압도적인 효율을 보이지만, 범용 OS 환경에서 OpenSSL이 제공하는 방대한 생태계와 도구 지원을 모두 대체하기에는 한계가 있을 수 있습니다.

## 보안·라이선스·도입 시 확인할 점

- **라이선스**: GPLv3를 따르므로, 상용 제품에 포함할 경우 라이선스 의무를 준수하거나 별도의 상용 라이선스를 구매해야 합니다. `CONTRIBUTING.md`에 명시된 바와 같이, 기여를 위해서는 기여자 계약(Contributor Agreement)을 체결해야 합니다.
- **보안**: `SECURITY.md`와 공식 disclosure 정책을 준수해야 하며, 취약점 발견 시 공개적인 이슈 제기 대신 `support@wolfssl.com`으로 비공개 보고해야 합니다.
- **인증**: FIPS 140-2/3 인증이 필요한 프로젝트라면 관련 FAQ를 반드시 확인해야 합니다.

## 한계와 추천 대상

**추천 대상**:
- 메모리 제약이 심한 임베디드 시스템 개발자
- RTOS(Zephyr, FreeRTOS 등) 기반의 IoT 기기 제조사
- OpenSSL의 무거운 의존성을 피하고 싶은 경량 애플리케이션 개발자

**한계**:
- 범용 데스크톱 애플리케이션에서는 OpenSSL의 방대한 기능을 모두 대체하기 어려울 수 있습니다.
- GPLv3 라이선스 제약으로 인해 소스 코드 공개를 원치 않는 상용 프로젝트는 반드시 상용 라이선스 정책을 검토해야 합니다.

도입 전, 프로젝트의 빌드 시스템(`CMake` 또는 `configure`)이 타겟 하드웨어의 컴파일러와 호환되는지 `IDE/` 폴더 내의 예제를 통해 먼저 검증하는 것을 권장합니다.
