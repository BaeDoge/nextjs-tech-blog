## 프로젝트의 역할

PostHog FOSS는 PostHog 메인 저장소에서 독점 코드와 기능을 제외해 동기화하는 공개 저장소입니다. 이 저장소는 자동으로 업데이트되는 읽기 전용 미러이므로, 이슈 제기나 코드 변경 PR은 FOSS 미러가 아니라 PostHog의 메인 저장소에 제출해야 합니다.

PostHog는 제품 분석을 중심으로 세션 리플레이, 오류 추적, 로그, 트레이싱, 기능 플래그, 실험, 설문과 데이터 파이프라인 등을 하나의 플랫폼에서 제공하는 제품 개발 도구입니다. 최근 README에서는 제품 이벤트와 운영 데이터를 개발자와 AI 에이전트가 함께 질의하고 활용하는 제품 컨텍스트 플랫폼으로 설명합니다.

## 주요 기능 영역

- **제품 분석 및 웹 분석**: 사용자 행동, 전환, 세션, 핵심 지표를 분석합니다.
- **세션 리플레이와 히트맵**: 실제 사용자 세션과 화면 상호작용을 확인해 UX 문제를 파악합니다.
- **옵저버빌리티**: 오류, 로그, 분산 트레이스를 분석합니다.
- **기능 플래그와 실험**: 기능 출시 범위를 제어하고 변경의 효과를 측정합니다.
- **데이터 웨어하우스 및 파이프라인**: 여러 데이터 소스를 연결하고 변환·전달합니다.
- **AI 관련 기능**: LLM 애플리케이션의 추적과 평가, MCP 기반 연동 등 최신 기능을 제공합니다. 일부 기능은 베타 또는 유료 플랜과 관련될 수 있으므로 현재 제품 문서를 확인해야 합니다.

## 자체 호스팅과 운영 범위

PostHog 공식 README는 자체 호스팅을 고급 사용자용 선택지로 안내하고 있으며, 취미·소규모 배포(hobby deploy)는 Linux와 Docker 기반의 단일 명령 설치 경로를 제공합니다. README에서는 오픈소스 자체 호스팅 배포가 월 약 10만 이벤트 규모까지 확장될 수 있다고 설명하고, 그보다 큰 규모라면 PostHog Cloud로 이전하는 방안을 권장합니다.

이 수치는 엄격한 기술적 제한이나 성능 보장이 아니라 공식 문서의 운영 권장 수준입니다. 실제 처리량은 이벤트 형태, 보존 기간, 동시 접속, 리소스 설정과 인프라 구성에 따라 달라집니다. 운영 환경에 도입하기 전에는 배포 가이드와 하드웨어 요구 사항, 백업 및 업그레이드 방식을 함께 검토해야 합니다.

## 저장소 구조를 읽을 때 주의할 점

FOSS 저장소는 메인 프로젝트의 일부를 공개 범위에 맞춰 자동 동기화하는 미러입니다. 따라서 단일 파일이나 폴더만 보고 제품 전체의 아키텍처를 설명하거나, 특정 경로가 항상 유지된다고 단정하지 않는 편이 좋습니다. 내부 구성은 활발하게 바뀌므로 현재 브랜치의 README와 공식 개발 문서를 기준으로 확인해야 합니다.

## 라이선스

PostHog FOSS 저장소의 LICENSE 파일은 MIT License를 표시합니다. 반면 메인 저장소는 `ee` 디렉터리 등 별도 라이선스가 적용되는 영역이 있을 수 있으므로, 메인 저장소의 전체 코드가 모두 동일한 조건이라고 확대 해석해서는 안 됩니다.

## 어떤 팀에 적합할까?

PostHog는 제품 사용 행태와 오류·성능 데이터를 함께 분석하고 싶은 제품·개발 조직에서 검토할 수 있습니다. 자체 호스팅은 데이터와 인프라를 직접 관리할 수 있다는 장점이 있지만, 업그레이드·백업·모니터링·확장도 직접 책임져야 합니다. 운영 인력이 부족하거나 높은 가용성이 필요한 경우에는 관리형 클라우드 옵션과 총 운영 비용을 비교하는 것이 좋습니다.
