## 현상

파이썬에서 `pickle.dump`로 직렬화한 파일을 `pickle.load`로 역직렬화할 때 다음과 같은 오류가 발생한다.

<Callout type="warning" title="오류 상황">

```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0x80 in position 0: invalid start byte
```

</Callout>

예상되는 실패 코드는 다음과 같다.

```python
import pickle

# 파일 모드 오류 발생 지점
f = open('sample_classifier.pickle', encoding="utf8")
cl = pickle.load(f)    
f.close()
```

![현상 스크린샷](/blogs/python-pickle-unicodedecodeerror-1.png)

## 원인

`pickle` 모듈은 객체를 바이트 스트림(binary stream)으로 직렬화한다. 
따라서 `pickle.dump` 실행 시 파일은 `'wb'(바이너리 쓰기)` 모드로 열어야 한다.
반대로 파일을 읽을 때는 인코딩을 적용하는 텍스트 모드 `'r'`이 아닌, 바이너리 모드 `'rb'`로 열어야 한다.
`encoding="utf8"`을 지정하면 파이썬은 원시 바이트를 UTF-8 텍스트로 변환하려고 시도하지만, pickle의 바이트 시퀀스는 유효한 UTF-8 문자가 아니기 때문에 변환이 실패한다.

## 해결 방법

파일 열기 모드와 인코딩 설정을 수정하여 바이너리 모드로 처리한다.

**수정 전 (오류 발생):**

```python
f = open('sample_classifier.pickle', encoding="utf8")
```

**수정 후 (정상 동작):**

```python
import pickle

# 'rb'(read binary) 모드로 변경하고 인코딩 제거
with open('sample_classifier.pickle', 'rb') as f:
    cl = pickle.load(f)    
```

<Steps title="수정 절차">
<Step title="파일 열기 모드 변경">
`open` 함수의 모드 인자를 `'r'`에서 `'rb'`로 변경한다.
</Step>
<Step title="인코딩 제거">
바이너리 모드에서는 `encoding` 매개변수를 지정하지 않는다.
</Step>
</Steps>

## 다른 해결 방법

Python 2 환경에서 생성된 pickle 파일을 Python 3에서 읽을 때는 바이너리 모드를 유지하면서 `encoding`을 지정할 수 있습니다. `latin1`은 0~255 바이트를 일대일로 문자에 대응시키므로 Python 2의 일부 8비트 문자열 데이터를 복원할 때 사용됩니다.

```python
import pickle

with open("legacy_python2.pickle", "rb") as f:
    obj = pickle.load(f, encoding="latin1")
```

원본 데이터가 텍스트 문자열이 아니라 바이트로 보존되어야 한다면 `encoding="bytes"`를 검토할 수 있습니다. 어떤 옵션이 맞는지는 pickle을 만든 Python 버전과 객체 타입에 따라 달라집니다.

```python
import pickle

with open("legacy_python2.pickle", "rb") as f:
    obj = pickle.load(f, encoding="bytes")
```

일반적인 새 Python 3 pickle에는 별도 `encoding` 옵션이 필요하지 않습니다.

## 추가 참고사항

`pickle` 파일을 읽을 때는 반드시 바이너리 모드(`rb`)를 사용합니다. 다만 Python 2에서 생성한 pickle을 Python 3에서 읽을 때는 저장 당시의 문자열 데이터에 따라 `encoding="latin1"` 또는 `encoding="bytes"`가 필요할 수 있습니다. 예를 들어 Python 2에서 저장한 NumPy 배열이나 `datetime` 객체는 `latin1`로 읽어야 하는 경우가 있습니다.

**보안 주의:** pickle은 역직렬화 과정에서 임의의 코드를 실행할 수 있습니다. 출처와 무결성을 신뢰할 수 없는 파일은 절대로 `pickle.load()`로 열지 마세요. 외부에서 전달받는 데이터에는 JSON 등 안전한 데이터 형식을 고려합니다.
<Callout type="info" title="인코딩 참고">
텍스트 파일의 인코딩이 UTF-8과 다른 경우(예: CP949), `encoding` 매개변수를 정확히 지정해야 `UnicodeDecodeError`를 피할 수 있다.
</Callout>
