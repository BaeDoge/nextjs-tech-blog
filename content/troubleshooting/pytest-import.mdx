## 현상

가상환경에서 일반 Python 인터프리터로는 프로젝트 모듈을 import할 수 있지만, `pytest`를 실행하면 테스트 수집 단계에서 `ImportError`가 발생할 수 있습니다.

```python
>>> from rc import ns
```

반면 `pytest` 실행 시 다음과 같이 테스트 모듈 내부의 import가 실패합니다.

```text
ImportError while importing test module ...
ModuleNotFoundError: No module named 'rc'
```

![현상 스크린샷](/blogs/pytest-import-1.png)

## 원인

이 문제를 모두 `.pth` 파일이나 `tests/__init__.py` 하나의 문제로 단정할 수는 없습니다. 일반 Python 실행과 pytest 실행의 차이는 다음 항목에서 생길 수 있습니다.

1. **실행 인터프리터 불일치**: `pytest` 실행 파일이 다른 가상환경의 Python을 가리키는 경우입니다. 일반 `python`과 `pytest`가 서로 다른 환경에서 실행되면 설치된 패키지와 `sys.path`가 달라집니다.
2. **pytest import mode**: pytest의 기본 `prepend` 모드는 테스트 모듈이 있는 디렉터리 또는 패키지의 상위 경로를 `sys.path` 앞에 추가합니다. 이 과정에서 동일한 이름의 패키지가 프로젝트 루트나 설치된 패키지와 충돌할 수 있습니다.
3. **패키지 구조와 `__init__.py`**: 테스트 폴더에 `__init__.py`가 있으면 pytest가 패키지 경로를 구성하는 방식이 달라집니다. 이 파일을 추가하거나 삭제하면 import 경로와 모듈 이름이 달라지므로, 무조건 삭제하는 것이 정답은 아닙니다.
4. **프로젝트 경로 등록 방식**: `.pth`, `PYTHONPATH`, editable install 설정이 서로 다른 프로젝트 경로를 가리키면 의도하지 않은 패키지가 import될 수 있습니다.

`.pth` 파일은 Python 인터프리터가 시작될 때 처리되므로 pytest에서만 작동하는 기능은 아닙니다. 먼저 실제로 어떤 Python과 pytest가 실행되는지 확인해야 합니다.

## 해결 방법

### 1. 같은 가상환경의 Python으로 pytest 실행

`pytest` 실행 파일이 다른 환경을 가리키는 문제를 피하려면 다음처럼 현재 Python 인터프리터를 통해 실행합니다.

```bash
python -c "import sys; print(sys.executable)"
python -m pytest --version
python -m pytest
```

### 2. 프로젝트를 editable install로 등록

패키지 프로젝트라면 저장소 루트에 올바른 `pyproject.toml` 또는 패키징 설정을 두고 개발 모드로 설치하는 방법을 권장합니다.

```bash
python -m pip install -e .
python -m pytest
```

이 방식은 매번 `.pth` 파일을 직접 편집하거나 테스트 코드에서 임의로 경로를 추가하는 방법보다 재현성이 높습니다.

## 다른 해결 방법

프로젝트 구조와 테스트 간 import 관계에 따라 pytest의 import mode를 바꿀 수 있습니다. `importlib` 모드는 테스트 모듈을 import할 때 `sys.path`를 변경하지 않습니다.

`pyproject.toml`에 다음과 같이 설정할 수 있습니다.

```toml
[tool.pytest.ini_options]
addopts = ["--import-mode=importlib"]
```

또는 일회성으로 실행할 수 있습니다.

```bash
python -m pytest --import-mode=importlib
```

단, `importlib` 모드에서는 테스트 모듈끼리 서로 직접 import하거나 `tests` 디렉터리의 유틸리티 모듈을 import하는 방식이 제한됩니다. 공통 fixture는 `conftest.py`로 옮기고, 여러 테스트가 사용하는 일반 유틸리티는 애플리케이션 패키지나 별도 지원 패키지에 두는 편이 좋습니다.

`PYTHONPATH`를 지정해야 한다면 테스트 실행 명령에 필요한 프로젝트 경로만 명시합니다. Windows에서는 경로 구분자가 운영체제에 따라 다르므로 셸에 맞게 설정해야 합니다.

```bash
PYTHONPATH=src python -m pytest
```

`tests/__init__.py`는 패키지 구조를 만들거나 동일한 이름의 테스트 모듈을 구분하는 데 필요할 수 있습니다. 실제 import 충돌이 이 파일 때문에 발생하는 것이 확인된 경우에만 구조를 바꾸고, 삭제 전후에 `sys.path`와 import되는 모듈의 `__file__` 경로를 비교해야 합니다.

## 추가 참고사항

문제를 재현할 때는 다음 정보를 함께 확인하면 원인을 좁히기 쉽습니다.

```python
import sys
import rc

print("Python:", sys.executable)
print("rc module:", rc.__file__)
print("sys.path:")
for item in sys.path:
    print(" ", item)
```

일반 Python과 pytest 실행에서 `sys.executable`, `rc.__file__`, `sys.path`가 어떻게 달라지는지 비교합니다.
