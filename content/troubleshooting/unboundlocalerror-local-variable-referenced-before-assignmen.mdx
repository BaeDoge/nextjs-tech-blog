## 현상

함수 내부의 조건문이 False로 평가되어 변수 할당문이 실행되지 않으면, `return` 구문에서 정의되지 않은 지역 변수를 참조하게 되어 에러가 발생한다.

<Callout type="warning" title="오류 상황">
UnboundLocalError: local variable 'T' referenced before assignment
</Callout>

다음 코드는 첫 번째 호출에서는 조건이 만족하여 정상 실행되지만, 두 번째 호출에서는 조건이 불만족하여 변수 `T`가 생성되지 않아 에러를 발생시킨다. 외부의 `tfile` 객체는 함수 바깥에서 열려 있다.

```python
tfile = open("/home/path/to/file",'r')

def temp_sky(lreq, breq):
    for line in tfile:
        data = line.split()
        # 조건이 만족하지 않으면 T = data[2]가 실행되지 않음
        if abs(float(data[0]) - lreq) <= 0.1 and abs(float(data[1]) - breq) <= 0.1:
            T = data[2]
    return T

print(temp_sky(60, 60))
print(temp_sky(10, -10))  # UnboundLocalError 발생
```

## 원인

파이썬은 함수 본문에 변수에 값을 할당하는 구문(예: `T = ...`)이 하나라도 있으면, 해당 변수를 **지역 변수**로 취급하여 바이트코드를 생성한다.

이러한 스코프 결정은 함수가 컴파일(바이트코드 생성)되는 시점에 이루어진다. 따라서 조건문 실패로 인해 `T = data[2]` 구문이 실행되지 않으면, `T`는 아직 값이 할당되지 않은 지역 변수로 인식된 채로 남아 있다.

함수 실행이 `return T`에 도달했을 때, 아직 초기화되지 않은 지역 변수 `T`를 읽으려 하므로 `UnboundLocalError`가 발생한다.

## 해결 방법

조건문 외부에서 변수를 먼저 기본값(예: `None`)으로 초기화하여, 조건이 만족하든 하지 않든 변수 `T`가 항상 존재하도록 한다.

```python
def temp_sky(lreq, breq):
    T = None  # 변수를 먼저 초기화하여 할당되지 않을 수 있는 상태 방지
    for line in tfile:
        data = line.split()
        if abs(float(data[0]) - lreq) <= 0.1 and abs(float(data[1]) - breq) <= 0.1:
            T = data[2]
    return T
```

## 다른 해결 방법

`return` 구문에서 변수를 직접 참조하지 않고, 조건문 실패 시 반환할 값을 명시적으로 처리하는 방법이다.

<Compare>
<ComparePanel title="변수 초기화 (기존)" tone="good">
변수를 미리 선언하여 스코프 문제를 해결하지만, 반환값이 None일 때 의도치 않은 동작이 발생할 수 있다.
</ComparePanel>
<ComparePanel title="조건부 반환 (제안)" tone="good">
변수 할당 없이 조건이 만족할 때만 반환하므로, 초기화 문제를 근본적으로 피할 수 있다.
</ComparePanel>
</Compare>

```python
def temp_sky(lreq, breq):
    for line in tfile:
        data = line.split()
        if abs(float(data[0]) - lreq) <= 0.1 and abs(float(data[1]) - breq) <= 0.1:
            return data[2]  # 조건 만족 시 즉시 반환
    return None  # 조건을 만족하지 않으면 None 반환
```

## 추가 참고사항

함수 내에서 변수에 값을 할당하면 자동으로 지역 변수가 되므로, 외부 전역 변수를 수정하려는 의도가 아니라면 `global`이나 `nonlocal`을 사용할 필요가 없다.

실무에서는 전역 상태 의존을 피하고, 함수 인자로 값을 전달하거나 반환값을 활용하는 순수 함수(Pure Function) 구조를 권장한다.

<Steps>
<Step title="에러 확인">함수 내에서 할당문이 실행되지 않는 조건이 있는지 확인합니다.</Step>
<Step title="초기화 위치 변경">변수 선언을 조건문 외부로 빼거나 기본값을 설정하여 미할당 상태를 방지합니다.</Step>
<Step title="반환 구조 개선">조건이 만족할 때 즉시 반환하도록 하여 변수 스코프 문제를 근본적으로 피합니다.</Step>
</Steps>
