## 한눈에 보는 프로젝트와 해결하려는 문제

`public-apis/public-apis`는 개발자들이 프로젝트에 즉시 활용할 수 있는 다양한 무료 API를 한곳에 모아놓은 **링크 컬렉션(Link Collection)** 저장소입니다. 현대 소프트웨어 개발에서 외부 데이터를 가져오는 API 활용은 필수적이지만, 어떤 API가 무료인지, 인증 방식은 무엇인지, CORS(Cross-Origin Resource Sharing)를 지원하는지 등을 일일이 찾는 것은 상당한 비용이 발생합니다.

이 프로젝트는 이러한 탐색 비용을 줄이기 위해 전 세계의 공개 API를 카테고리별로 정리하여 제공하는 것을 목표로 합니다. 단순히 목록을 나열하는 것에 그치지 않고, 커뮤니티의 기여를 통해 데이터의 최신성과 정확성을 유지하려는 구조를 가지고 있습니다.

## 이해에 필요한 핵심 개념

이 프로젝트를 깊이 있게 이해하기 위해서는 다음 세 가지 핵심 개념을 파악해야 합니다.

1.  **API 큐레이션(Curation)**: 단순히 모든 API를 수집하는 것이 아니라, 특정 기준(무료 접근성, 인증 방식, HTTPS 지원 여부 등)에 따라 선별된 정보를 제공합니다. `CONTRIBUTING.md`를 보면, 유료 솔루션을 홍보하기 위한 마케팅 목적의 Pull Request는 거부한다는 명확한 가이드라인을 통해 데이터의 순수성을 유지하고 있습니다.
2.  **데이터 규격화(Standardization)**: 수집된 API 정보는 마크다운(Markdown) 테이블 형식을 따릅니다. `Auth`(인증 방식), `HTTPS`, `CORS`와 같은 속성을 정해진 값(`OAuth`, `apiKey`, `Yes`, `No` 등)으로 입력하도록 강제하여, 사용자가 목록을 읽을 때 일관된 정보를 얻을 수 있도록 설계되었습니다.
3.  **무결성 검증(Integrity Validation)**: 링크 컬렉션의 가장 큰 숙제는 '깨진 링크(Broken Link)'를 관리하는 것입니다. 이 프로젝트는 Python 스크립트를 활용하여 등록된 API 문서 링크가 여전히 유효한지, 중복된 링크는 없는지 검사하는 도구를 포함하고 있습니다.

## 저장소 구조와 실제 동작 흐름

저장소는 크게 사용자에게 정보를 전달하는 **문서(Documentation)** 영역과 데이터의 품질을 관리하는 **스크립트(Scripts)** 영역으로 나뉩니다.

*   **문서 영역**: 프로젝트의 메인 화면인 `README.md`가 핵심입니다. 이곳에 모든 API 목록이 테이블 형태로 나열되어 있으며, 사용자는 이 문서를 통해 필요한 API를 탐색합니다.
*   **스크립트 영역**: `scripts/` 디렉토리 내에는 데이터의 품질을 유지하기 위한 도구들이 포함되어 있습니다.
    *   `scripts/validate/links.py`: 링크의 유효성을 검사하는 핵심 로직이 담겨 있습니다.
    *   `scripts/validate/format.py`: 데이터의 형식이 규격에 맞는지 확인하는 역할을 수행할 것으로 추정됩니다.
    *   `scripts/tests/`: 작성된 검증 스크립트들이 의도대로 동작하는지 확인하는 테스트 코드가 위치합니다.

**데이터 관리 흐름**은 다음과 같습니다.
1.  **기여(Contribution)**: 사용자가 새로운 API를 발견하면 `CONTRIBUTING.md`의 규격에 맞춰 마크다운 테이블 행을 작성하여 Pull Request(PR)를 보냅니다.
2.  **검증(Validation)**: PR이 생성되면, 프로젝트에 포함된 검증 스크립트들이 실행됩니다. `scripts/validate/links.py`는 정규표현식을 사용하여 텍스트 내의 URL을 추출하고, 해당 URL들이 실제로 접속 가능한지 확인합니다.
3.  **승인(Approval)**: 링크가 정상이고 형식이 올바르다면 관리자에 의해 병합(Merge)됩니다.

## 구체적인 예제로 보는 설계 선택

`scripts/validate/links.py` 파일의 구현을 통해 이 프로젝트가 데이터 신뢰성을 어떻게 관리하려 하는지 분석할 수 있습니다.

이 스크립트에는 링크의 중복을 체크하는 `check_duplicate_links` 함수와 링크의 작동 여부를 확인하는 `check_if_link_is_working` 함수가 존재합니다. 특히 `check_if_link_is_working` 함수는 단순히 HTTP 상태 코드를 확인하는 것을 넘어, 외부 서비스의 차단 메커니즘을 고려하려는 시도가 보입니다.

예를 들어, `fake_user_agent` 함수는 다음과 같이 다양한 브라우저의 User-Agent를 리스트로 관리합니다.

```python
def fake_user_agent() -> str:
    """Faking user agent as some hosting services block not-whitelisted UA."""

    user_agents = [
        'Mozilla/5.0 (Windows NT 6.2) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/28.0.1467.0 Safari/537.36',
        'Mozilla/5.0 (Macintosh; Intel Mac OS X 10_13_6) AppleWebKit/605.1.15 (KHTML, like Gecko)',
        'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/80.0.3987.132 Safari/537.36',
        'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/97.0.4692.71 Safari/537.36',
    ]
    # ... (중략)
```

이는 특정 호스팅 서비스가 봇(Bot)의 접근을 차단할 경우, 검증 스크립트가 정상적인 API 링크임에도 불구하고 '작동하지 않음'으로 오판하는 것을 방지하기 위한 설계 선택입니다.

다만, `has_cloudflare_protection` 함수를 살펴보면 Cloudflare와 같은 보안 서비스의 보호 여부를 감지하려는 의도는 확인되나, 현재 제공된 코드상에서는 `return False`만을 반환하고 있습니다. 이는 해당 기능이 아직 구현되지 않았거나, 현재 단계에서는 단순한 스텁(Stub) 형태로 존재함을 의미합니다. 즉, 설계 의도는 명확하지만 실제 구현은 지속적으로 보완되어야 하는 단계에 있다고 해석할 수 있습니다.

## 대안과 비교했을 때의 장단점

API 목록을 찾는 방법에는 이 프로젝트 외에도 여러 대안이 있습니다.

| 비교 기준 | `public-apis` (본 프로젝트) | 검색 엔진/직접 검색 | 유료 API 마켓플레이스 (RapidAPI 등) |
| :--- | :--- | :--- | :--- |
| **접근성** | 매우 높음 (한곳에 모여 있음) | 낮음 (파편화됨) | 높음 (통합 인터페이스) |
| **비용** | 무료 중심 (Free-tier 강조) | 다양함 | 유료 모델 위주 |
| **데이터 신뢰도** | 커뮤니티 검증 기반 | 검색 결과에 의존 | 플랫폼 자체 검증 |
| **최신성** | 기여자에 따라 가변적 | 실시간 반영 | 플랫폼 관리자에 의해 관리 |

**장점:**
*   **비용 효율성**: '무료'와 'Free tier'를 최우선 가치로 두기 때문에, 예산이 제한된 개인 개발자나 학생들에게 최적의 출발점을 제공합니다.
*   **커뮤니티 기반 확장성**: 전 세계 개발자들이 참여하여 목록을 확장하므로, 특정 분야에 국한되지 않는 방대한 데이터를 보유할 수 있습니다.

**단점:**
*   **검증의 지연**: 커뮤니티 기반이므로, API 서비스가 중단되었을 때 이를 즉시 감지하여 목록에서 제거하는 속도가 플랫폼 기반 서비스보다 느릴 수 있습니다.
*   **정보의 파편화**: 마크다운 테이블 형식이므로, 프로그래밍 방식으로 실시간 데이터를 가져오기보다는 '참조용 문서'로서의 성격이 강합니다.

## 보안·라이선스·도입 시 확인할 점

**라이선스**
이 프로젝트는 **MIT License**를 따릅니다. 이는 매우 관대한 라이선스로, 저작권 고지만 유지한다면 상업적 이용, 수정, 배포가 자유롭습니다. 따라서 이 목록을 자신의 서비스나 앱의 데이터 소스로 활용하는 데 법적 제약이 거의 없습니다.

**보안 및 주의사항**
*   **기여 시 주의사항**: 프로젝트의 검증 스크립트(`scripts/validate/links.py`)는 외부 URL에 직접 HTTP 요청을 보내는 구조입니다. 따라서 이 스크립트를 로컬 환경에서 직접 실행하는 기여자는, 검증 대상이 되는 링크가 악성 사이트일 경우 보안 리스크가 발생할 수 있음을 인지해야 합니다.
*   **API 자체의 보안**: 이 저장소는 API의 '목록'을 제공할 뿐, 해당 API의 보안성을 보증하지 않습니다. `Auth` 필드에 `apiKey`나 `OAuth`가 명시되어 있더라도, 실제 사용 시에는 해당 API 제공업체의 보안 가이드라인을 반드시 준수해야 합니다.

## 한계와 추천 대상

**한계**
1.  **구현의 미완성**: 앞서 언급했듯, 검증 스크립트 중 일부 기능(예: Cloudflare 감지)이 미완성 상태로 남아 있을 수 있습니다.
2.  **수동 관리의 한계**: 자동화된 봇이 아닌 사람의 기여에 의존하므로, 데이터의 최신성이 완벽하게 보장되지 않습니다.

**추천 대상**
*   **신규 프로젝트를 시작하는 개발자**: 어떤 데이터를 활용할 수 있을지 아이디어가 필요할 때 가장 빠르게 영감을 얻을 수 있습니다.
*   **사이드 프로젝트 운영자**: 비용 부담 없이 활용 가능한 API를 찾는 데 최적화되어 있습니다.
*   **오픈소스 기여자**: API 정보를 정리하고 커뮤니티에 기여하는 프로세스를 경험해보고 싶은 분들에게 좋은 연습장이 됩니다.
