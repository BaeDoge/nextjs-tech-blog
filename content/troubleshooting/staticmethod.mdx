## 현상

클래스 본문에서 `@staticmethod`로 선언한 메서드를 딕셔너리에 바로 저장한 뒤, 클래스 생성 후 딕셔너리를 통해 호출하면 Python 3.9 이하에서 `TypeError`가 발생할 수 있습니다.

```python
class A:
    @staticmethod
    def open_func():
        return 123

    @staticmethod
    def process_func():
        return 456

    switch = {
        1: open_func,
        2: process_func,
    }

print(A.switch[1]())
```

Python 3.9 이하에서의 오류 메시지는 다음과 같습니다.

```text
TypeError: 'staticmethod' object is not callable
```

## 원인

클래스 본문에서 `open_func`라는 이름을 직접 참조하면, 클래스가 만들어지기 전이므로 `A.open_func`처럼 클래스 속성에 접근하는 디스크립터 처리가 일어나지 않습니다. 이때 딕셔너리에는 실제 함수가 아니라 `staticmethod` 래퍼 객체가 저장됩니다.

Python 3.9 이하에서는 이 래퍼 객체를 직접 호출할 수 없어 `TypeError`가 발생합니다. 다만 이 동작은 버전에 따라 달라졌습니다. **Python 3.10부터 `staticmethod` 객체 자체가 일반 함수처럼 호출 가능해졌으므로**, 위 코드는 Python 3.10 이상에서 같은 오류를 재현하지 않습니다.

## 해결 방법

가장 명확하고 버전 간 호환성이 좋은 방법은 클래스 정의가 끝난 뒤 클래스 속성으로 메서드에 접근해 딕셔너리를 만드는 것입니다.

```python
class A:
    @staticmethod
    def open_func():
        return 123

    @staticmethod
    def process_func():
        return 456

A.switch = {
    1: A.open_func,
    2: A.process_func,
}

print(A.switch[1]())  # 123
```

클래스 속성인 `A.open_func`로 접근하면 디스크립터가 원래 함수 객체를 반환하므로 Python 3.9 이하에서도 호출할 수 있습니다.

## 다른 해결 방법

클래스 본문 안에서 딕셔너리를 정의해야 한다면 `staticmethod` 객체의 `__func__` 속성으로 원래 함수 객체를 꺼낼 수 있습니다.

```python
class A:
    @staticmethod
    def open_func():
        return 123

    @staticmethod
    def process_func():
        return 456

    switch = {
        1: open_func.__func__,
        2: process_func.__func__,
    }

print(A.switch[1]())  # 123
```

`__func__`는 `staticmethod` 래퍼가 감싸고 있는 함수입니다. 클래스 내부에서 원래 함수가 꼭 필요할 때 사용할 수 있지만, 일반적으로는 클래스 생성 후 `A.open_func`에 접근하는 첫 번째 해결 방법이 더 읽기 쉽습니다.

## 추가 참고사항

- 정적 메서드는 `self`나 `cls`를 자동으로 받지 않습니다. 인스턴스 상태에 접근할 필요가 없는 기능에 사용합니다.
- Python 3.10 이상에서는 `staticmethod` 객체가 호출 가능하도록 바뀌었으므로, 오래된 오류 사례를 현재 Python에서 재현하려면 버전을 명시해야 합니다.
- 메서드 디스패치 테이블을 만들 때는 문자열 키와 `getattr()`를 이용하거나, 클래스 생성 이후 허용된 함수만 딕셔너리에 등록하는 방식도 사용할 수 있습니다.
