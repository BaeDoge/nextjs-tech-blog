## 현상

리스트를 set의 원소로 추가하거나 dict의 키로 사용하면 다음 오류가 발생합니다.

~~~python
items = [1, 2, 3]
values = {items}
# TypeError: unhashable type: 'list'
~~~

리스트는 내용을 변경할 수 있는 mutable 객체이므로 기본적으로 해시할 수 없습니다.

## 원인

set과 dict는 객체의 해시 값을 기준으로 저장 위치를 결정합니다. 객체를 저장한 뒤 해시 값이 바뀌면 기존 저장 위치를 찾지 못해 자료구조의 동작이 깨질 수 있습니다.

따라서 Python의 해시 가능 객체는 객체가 살아 있는 동안 해시 값이 안정적이어야 합니다. 일반적인 리스트는 원소를 추가하거나 제거할 수 있으므로 이 조건을 만족하지 않습니다.

## 해결 방법

### 1. 내용을 변경할 필요가 없다면 tuple 사용

리스트의 원소를 변경하지 않고 키로 사용하려는 경우에는 튜플로 변환합니다.

~~~python
items = [1, 2, 3]
key = tuple(items)

values = {key}
lookup = {key: "data"}

print((1, 2, 3) in values)  # True
print(lookup[(1, 2, 3)])    # data
~~~

튜플의 원소도 모두 해시 가능해야 합니다. 튜플 안에 리스트나 딕셔너리처럼 해시할 수 없는 객체가 들어 있으면 튜플 역시 해시할 수 없습니다.

### 2. 사용자 정의 객체가 필요하다면 불변 상태로 설계

리스트를 상속해 __hash__ = tuple.__hash__를 지정하거나, hash(tuple(self))를 반환하도록 구현하는 방식은 안전한 해결책이 아닙니다. 리스트 내용이 바뀌면 해시 값도 달라질 수 있기 때문입니다.

다음과 같이 불변 데이터만 보관하는 객체를 키로 사용하는 편이 안전합니다.

~~~python
from dataclasses import dataclass

@dataclass(frozen=True)
class ItemKey:
    values: tuple[int, ...]

key = ItemKey((1, 2, 3))
values = {key}
~~~

frozen=True는 인스턴스의 필드를 재할당하지 못하도록 합니다. 필드 안에 들어가는 값도 해시 가능한 불변 값으로 구성해야 합니다.

## 피해야 할 구현

~~~python
class HashableList(list):
    def __hash__(self):
        return hash(tuple(self))

items = HashableList([1, 2])
values = {items}
items.append(3)  # 저장 후 해시 기준이 바뀔 수 있음
~~~

이 구현은 집합에 넣은 뒤 리스트를 변경할 수 있으므로, 원소 검색이나 삭제가 기대대로 동작하지 않을 수 있습니다. mutable 객체에 해시 메서드만 추가하는 방식은 사용하지 않는 것이 좋습니다.

## 추가 참고사항

- 중복 제거만 필요하다면 데이터가 해시 가능한지 확인한 뒤 set이나 drop_duplicates()를 사용하세요.
- 리스트 형태의 값을 키로 사용해야 한다면, 해당 리스트를 튜플로 변환하는 방식이 적절한지 먼저 검토하세요.
- 사용자 정의 클래스에서 __eq__를 구현하면 Python은 기본적으로 __hash__를 비활성화합니다. 동등성 비교와 해시 규칙을 함께 설계해야 합니다.
