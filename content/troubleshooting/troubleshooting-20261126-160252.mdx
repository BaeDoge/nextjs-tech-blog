## 현상

`list` 객체는 내용을 변경할 수 있는 가변 자료형이므로 `set`의 원소나 `dict`의 키로 사용할 수 없다. 단순히 `__hash__`를 구현해 해시 가능하게 만드는 것도 안전한 해결책이 아니다. 해시 컬렉션에 저장된 객체의 해시 값은 저장된 동안 변하지 않아야 하기 때문이다.

```python
class X(list):
    __hash__ = tuple.__hash__

x1 = X()
s = {x1}  # TypeError: unhashable type: 'X'
```

## 원인

`list`는 가변 자료형이므로 기본적으로 `__hash__ = None`으로 설정되어 있다. `tuple`은 불변 객체라 해시 가능하지만, 리스트를 튜플로 변환해 해시 값을 계산하는 메서드를 리스트 서브클래스에 추가하더라도 원본 리스트의 가변성은 사라지지 않는다.

예를 들어 리스트 내용을 바꾼 뒤 해시 값을 다시 계산하면 이전과 달라질 수 있다. 이미 `set`이나 `dict`에 저장된 키의 해시 값이 바뀌면 내부 저장 위치와 조회 결과가 일치하지 않을 수 있다. 따라서 값 기반 동등성(`__eq__`)을 유지하는 가변 객체에는 일반적으로 `__hash__`를 구현하지 않는 것이 안전하다.

<Callout type="warning" title="오류 상황">
TypeError: unhashable type: 'X'
</Callout>

## 해결 방법

가변 리스트를 직접 해시하려 하지 말고, 해시 컬렉션에 넣을 시점의 내용을 불변 튜플로 복사해 키로 사용한다. 이 방법은 리스트 원본이 나중에 변경되어도 이미 저장한 튜플 키의 해시 값이 바뀌지 않는다는 장점이 있다. 단, 튜플의 모든 원소도 해시 가능해야 한다.

```python
items = [1, 2, 3]
key = tuple(items)

seen = {key}
lookup = {key: "처리 완료"}

# 원본 리스트를 바꿔도 기존 튜플 키는 변하지 않는다.
items.append(4)
print(key)  # (1, 2, 3)
```

## 다른 해결 방법

리스트 원소가 리스트처럼 다시 가변 객체인 경우에는 단순히 `tuple(items)`로 변환해도 해시할 수 없다. 중첩 구조라면 각 하위 값을 재귀적으로 불변 구조로 변환하거나, 데이터 모델에 맞는 별도의 불변 키를 설계해야 한다. 모든 값을 무조건 문자열로 바꾸는 방식은 서로 다른 값을 같은 문자열로 표현할 가능성이 있으므로 일반적인 해결책으로 사용하지 않는 것이 좋다.

## 추가 참고사항

해시 컬렉션의 키는 저장된 동안 해시 값이 안정적으로 유지되어야 한다. `list`나 `dict`처럼 값이 바뀔 수 있는 객체는 직접 키로 사용하지 말고, 필요한 시점에 불변 표현으로 변환하는 편이 안전하다.
`pandas` 등에서 `drop_duplicates`를 사용할 때 `unhashable type` 오류가 발생하면, 대상 컬럼의 데이터가 리스트 형태인지 확인하고 `tuple`로 변환하는 것이 해결책이 될 수 있다.

```python
# pandas 예시: 리스트 컬럼을 튜플로 변환하여 중복 제거 가능
df['Like_Tuple'] = df['Like'].map(tuple)
df.drop_duplicates(['Like_Tuple'])
```
