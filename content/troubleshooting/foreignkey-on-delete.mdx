## 현상

Django 2.0 이상 환경에서 `python manage.py makemigrations` 명령을 실행 시 다음과 같은 에러가 발생합니다.

```python
Traceback (most recent call last):
  ...
TypeError: __init__() missing 1 required positional argument: 'on_delete'
```

에러는 자식 테이블(`Article`)에서 부모 테이블(`Categorie`)과의 관계를 정의하는 과정에서 발생하며, 기존에 데이터가 입력된 테이블 구조를 변경하거나 새로운 외래 키 관계를 추가할 때 주로 나타납니다.

## 원인

Django 2.0부터 `ForeignKey` 및 `OneToOneField` 필드는 관계 설정 시 `on_delete` 동작을 반드시 명시하도록 변경되었습니다. 이전 버전에서는 기본값이 암시적으로 적용되었으나, 데이터 무결성과 삭제 행위를 명확히 하기 위해 필수 인자로 지정되었습니다. 인자가 누락되면 Django는 모델 초기화 과정에서 필수 인자가 부족함을 인식하여 TypeError를 출력합니다.

## 해결 방법

외래 키 필드에 `on_delete` 인자를 추가하여 삭제 시 행동을 정의해야 합니다. 일반적인 경우 데이터의 무결성을 위해 `CASCADE`를 사용하는 것이 권장됩니다.

수정 전 코드:

```python
class Article(models.Model):
    # ... 다른 필드들 ...
    categorie = models.ForeignKey('Categorie')
```

수정 후 코드:

```python
class Article(models.Model):
    # ... 다른 필드들 ...
    categorie = models.ForeignKey(
        'Categorie',
        on_delete=models.CASCADE,
    )
```

필요에 따라 다른 삭제 동작을 선택할 수 있으며, 이후 `makemigrations`를 다시 실행하면 마이그레이션 파일이 정상 생성됩니다.

## 다른 해결 방법

데이터 삭제와 관련된 특별한 규칙이 없고 외래 키 참조가 끊어지더라도 관련 레코드를 유지하려는 경우 `on_delete`에 `DO_NOTHING`을 설정할 수 있습니다.

```python
class Article(models.Model):
    # ... 다른 필드들 ...
    categorie = models.ForeignKey(
        'Categorie',
        on_delete=models.DO_NOTHING,
    )
```

이 경우 부모 레코드를 삭제할 때 Django는 자식 레코드에 어떠한 조치도 취하지 않으며, 이는 데이터베이스의 외래 키 제약 조건에 따라 오류가 발생할 수 있으므로 주의가 필요합니다.

## 추가 참고사항

`on_delete` 인자는 `ForeignKey`뿐만 아니라 `OneToOneField`에서도 동일하게 필수입니다. 사용 가능한 값은 `CASCADE`, `PROTECT`, `SET_NULL`, `SET_DEFAULT`, `RESTRICT`, `DO_NOTHING` 등이 있으며, Django 공식 문서에서 각 동작의 상세한 차이점을 확인할 수 있습니다. `ManyToManyField`의 경우 `through` 모델을 사용하지 않는 한 `on_delete` 인자를 직접 받지 않으며, 관련 모델들의 삭제 동작은 개별 외래 키 필드에서 정의됩니다.
