## 현상

Python 함수가 종료 조건에 도달하기 전에 자신을 너무 깊게 호출하면 다음 오류가 발생합니다.

```text
RecursionError: maximum recursion depth exceeded
```

간단한 재현 예시는 다음과 같습니다.

```python
def countdown(n):
    if n <= 0:
        return
    countdown(n - 1)

countdown(2000)
```

## 원인

Python은 인터프리터가 과도하게 깊은 호출을 계속하지 않도록 재귀 호출 깊이에 제한을 둡니다. 현재 프로세스에서 사용하는 제한은 `sys.getrecursionlimit()`으로 확인할 수 있습니다.

```python
import sys
print(sys.getrecursionlimit())
```

기본 제한이 흔히 1,000으로 보이더라도 플랫폼, Python 빌드, 실행 환경에 따라 달라질 수 있습니다. 또한 종료 조건이 잘못되었거나 입력 크기에 비해 재귀 알고리즘을 사용하면 제한을 넘을 수 있습니다.

## 해결 방법

가장 먼저 재귀가 꼭 필요한지 확인합니다. 단순히 카운터를 줄이거나 누적값을 계산하는 재귀는 반복문으로 바꾸면 호출 스택을 사용하지 않습니다.

```python
def countdown_iterative(n):
    while n > 0:
        n -= 1

countdown_iterative(2000)
```

트리나 그래프 탐색처럼 재귀 구조가 자연스러운 경우에는 명시적 스택이나 큐를 사용해 반복형 DFS/BFS로 변환할 수 있습니다.

## 다른 해결 방법

알고리즘 구조상 더 깊은 재귀가 반드시 필요하다면 `sys.setrecursionlimit()`으로 제한을 조정할 수 있습니다. 단, 제한을 무작정 크게 설정하면 Python 또는 운영체제의 스택 자원을 초과해 프로세스가 비정상 종료될 수 있습니다. 반복문으로 바꿀 수 없는 경우에만 실행 환경을 확인하고 신중하게 사용해야 합니다.

```python
import sys

current_limit = sys.getrecursionlimit()
print("현재 재귀 제한:", current_limit)

# 필요한 깊이를 충분히 검토한 뒤 합리적인 값으로 설정
sys.setrecursionlimit(2000)
```

재귀 호출 수가 입력 크기에 비례하는 알고리즘이라면, 제한을 올리기 전에 동적 계획법, 메모이제이션, 반복형 DFS 등으로 호출 깊이를 줄일 수 있는지도 검토합니다.

## 추가 참고사항

- 재귀 함수에는 반드시 종료 조건이 있어야 하며, 각 호출에서 종료 조건에 가까워지는지 확인합니다.
- `sys.getrecursionlimit()`은 현재 제한을 보여 줄 뿐, 그 깊이까지 안전하게 호출할 수 있다는 보장은 아닙니다.
- 깊은 트리 탐색은 반복형 DFS/BFS를 고려합니다. 특히 트리 높이가 수천 이상일 수 있다면 재귀 방식에 의존하지 않는 편이 안전합니다.
