## 현상

Windows 10에서 `pip install jupyter`를 통해 주피터를 설치한 후 `jupyter notebook` 명령어를 실행하면 다음과 같은 오류가 발생합니다.

```text
'jupyter' is not recognized as an internal or external command, operable program or batch file.
```

이 오류는 운영체제의 명령 프롬프트(명령 프롬프트 또는 PowerShell)가 `jupyter` 실행 파일을 시스템 경로에서 찾을 수 없을 때 발생합니다.

![현상 스크린샷](/blogs/windows-jupyter-not-recognized-1.png)

## 원인

파이썬 패키지를 `pip install`로 설치하면 실행 파일(스크립트)은 일반적으로 파이썬 설치 경로 내의 `Scripts` 폴더(또는 가상환경의 `Scripts` 폴더)에 생성됩니다.

하지만 이 폴더가 운영체제의 환경 변수인 `PATH`에 포함되어 있지 않거나, PowerShell의 실행 정책 제한 등으로 인해 시스템이 해당 실행 파일을 찾지 못합니다.

사용자 레벨 설치 시 시스템 전체 PATH와의 충돌이 발생하거나, PATH 설정이 반영되지 않은 터미널을 사용 중일 수도 있습니다.

## 해결 방법

`PATH` 환경 변수를 설정하는 대신, 파이썬 모듈로 직접 실행하는 방법을 사용합니다.

1. 명령 프롬프트에서 다음 명령어를 실행합니다.

```bash
python -m notebook
```

이 명령은 `jupyter` 실행 파일을 직접 호출하는 것이 아니라, 파이썬 인터프리터를 통해 `notebook` 모듈을 실행하도록 지시합니다.

가상환경을 사용 중이라면, 먼저 가상환경을 활성화한 후 위 명령어를 실행해야 합니다.

```bash
# 가상환경 활성화 예시 (PowerShell)
.venv\Scripts\Activate.ps1
# 그 후 실행
python -m notebook
```

![해결 방법 스크린샷](/blogs/windows-jupyter-not-recognized-2.png)

## 다른 해결 방법

가상환경의 스크립트 폴더를 직접 실행 경로를 통해 호출하거나, 가상환경 자체를 재구축하는 방법을 사용할 수 있습니다.

1. 가상환경 내 `Scripts` 폴더의 실행 파일을 직접 실행합니다.

```bash
.venv\Scripts\jupyter.exe notebook
```

2. 기존 가상환경이 손상되었거나 경로가 변경된 경우, 가상환경을 다시 생성하는 것이 안전합니다.

```bash
# 기존 가상환경 삭제 후 재생성
rm -r .venv
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install jupyter
```

3. Windows PowerShell에서 실행 정책으로 인해 스크립트가 로드되지 않는 경우, 다음 명령으로 정책을 변경합니다.

```bash
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

## 추가 참고사항

`jupyter` 명령어 대신 `python -m notebook`을 사용하면 PATH 설정에 의존하지 않고 안정적으로 실행할 수 있습니다.

`pip install jupyter` 설치 시 나오는 로그에서 설치 경로(`Script folder`)를 확인하여 해당 폴더를 시스템 PATH에 추가하는 방법도 있지만, 모듈 실행 방식이 더 간편합니다.

아나콘다(Anaconda)를 사용하여 설치한 경우, 설치 과정에서 환경 변수가 자동으로 설정되어 별도 설정 없이 `jupyter notebook` 명령어를 바로 실행할 수 있습니다.

`python -m notebook` 실행 시 `ModuleNotFoundError`가 발생하면, 현재 활성화된 파이썬 환경에 주피터가 설치되지 않은 것이므로 `pip install jupyter`를 다시 실행해야 합니다.
