## 현상

중첩 함수에서 바깥 함수의 변수를 읽고 값을 증가시키려 하면 UnboundLocalError가 발생할 수 있습니다.

~~~python
def make_counter():
    counter = 0

    def increment():
        counter += 1
        return counter

    return increment

next_count = make_counter()
next_count()
~~~

오류 메시지는 Python 버전에 따라 다음과 유사하게 나타납니다.

~~~
UnboundLocalError: cannot access local variable 'counter' where it is not associated with a value
~~~

## 원인

Python은 함수 본문에 해당 변수로의 대입이 있으면 기본적으로 그 변수를 함수의 지역 변수로 취급합니다.

counter += 1은 기존 값을 읽고 새 값을 대입하는 연산입니다. increment() 내부에서 counter가 지역 변수로 분류되므로, 값이 대입되기 전에 읽으려 하면서 오류가 발생합니다.

## 해결 방법

바깥 함수의 지역 변수를 중첩 함수에서 다시 할당하려면 nonlocal을 선언합니다.

~~~python
def make_counter():
    counter = 0

    def increment():
        nonlocal counter
        counter += 1
        return counter

    return increment

next_count = make_counter()
print(next_count())  # 1
print(next_count())  # 2
~~~

nonlocal counter는 가장 가까운 바깥 함수 스코프에 있는 counter를 가리키고, 그 변수에 재할당하겠다는 뜻입니다.

## 다른 방법: 가변 객체 사용

단순히 객체 내부 상태를 변경하는 방식으로 구현할 수도 있습니다. 이 경우 바깥 변수 자체에 재할당하지 않기 때문에 nonlocal이 필요하지 않습니다.

~~~python
def make_counter():
    state = {"count": 0}

    def increment():
        state["count"] += 1
        return state["count"]

    return increment

next_count = make_counter()
print(next_count())  # 1
print(next_count())  # 2
~~~

다만 상태 표현을 위해 딕셔너리나 리스트를 사용하는 것보다, 변수 재할당이 목적이라면 nonlocal을 사용하는 편이 의도를 더 직접적으로 보여줍니다.

## global과 nonlocal의 차이

- nonlocal: 가장 가까운 바깥쪽 함수 스코프의 변수를 참조합니다.
- global: 모듈 최상위 스코프의 변수를 참조합니다.

중첩 함수의 상태를 관리할 때는 전역 변수를 늘리기보다 클로저와 nonlocal을 활용하는 편이 독립적인 함수를 만들기 쉽습니다.
