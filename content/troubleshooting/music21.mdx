## 한눈에 보는 프로젝트와 해결하려는 문제

`music21`은 컴퓨터를 활용한 음악 분석(Computer-Aided Musical Analysis)과 계산 음악학(Computational Musicology)을 위해 설계된 파이썬 라이브러리입니다. 이 프로젝트는 음악 악보 데이터를 단순히 재생하거나 출력하는 것을 넘어, 음악적 구조를 객체 지향적으로 모델링하여 복잡한 분석 알고리즘을 적용할 수 있도록 돕습니다.

음악학 연구자나 개발자는 악보 파일(MusicXML, MIDI 등)을 불러와 특정 음정의 빈도, 리듬 패턴, 화성 진행 등을 프로그래밍 방식으로 추출해야 하는 과제에 직면합니다. `music21`은 이러한 음악적 요소를 파이썬 객체로 추상화하여, 연구자가 수천 개의 악보를 일괄 처리하거나 통계적 분석을 수행할 수 있는 환경을 제공합니다. 2006년부터 시작된 이 프로젝트는 현재 `BSD-3-Clause` 라이선스로 배포되며, 학술 연구와 교육 분야에서 폭넓게 활용되고 있습니다.

## 이해에 필요한 핵심 개념

`music21`을 이해하기 위해서는 다음의 핵심 개념을 파악해야 합니다.

1. **Stream**: 음악적 요소(음표, 쉼표, 화음 등)를 담는 컨테이너입니다. 악보의 한 마디(Measure)나 전체 악장(Part)을 나타내며, 계층적 구조를 가질 수 있습니다.
2. **Offset**: `Stream` 내에서 요소가 시작되는 상대적 위치입니다. `music21`은 이 오프셋을 기반으로 시간 축에서의 음악적 사건을 관리합니다.
3. **AVL Tree 기반 검색**: 대규모 악보 데이터를 효율적으로 탐색하기 위해 `music21.tree.core`에서는 `AVLNode`와 `AVLTree`를 사용합니다. 이는 음악적 사건을 시간 순서대로 정렬하고, 특정 시간 범위 내의 요소를 `O(log n)`의 복잡도로 검색하기 위한 최적화된 자료구조입니다.

```python
# music21/tree/core.py의 AVLTree 구조 예시
class AVLNode[PayloadType](common.SlottedObjectMixin):
    r'''
    An AVL Tree Node, not specialized in any way, just contains positions.
    '''
```

## 저장소 구조와 실제 동작 흐름

저장소는 라이브러리의 핵심 로직과 문서화, 테스트 환경으로 명확히 구분되어 있습니다.

* `music21/`: 라이브러리의 핵심 소스 코드가 위치합니다. `stream/`, `meter/`, `tree/` 등 음악적 도메인 지식이 반영된 모듈로 나뉩니다.
* `documentation/`: `Sphinx`를 활용한 문서 빌드 시스템이 포함되어 있으며, 사용법과 개발자 가이드를 생성합니다.
* `.github/workflows/`: `maincheck.yml` 등을 통해 지속적 통합(CI) 환경을 구축하여 코드 품질을 관리합니다.

동작 흐름은 일반적으로 사용자가 악보 파일을 로드하면 `Stream` 객체가 생성되고, 이를 `asTimespans()` 메서드를 통해 `TimespanTree`로 변환하여 고속 검색 및 분석을 수행하는 과정을 거칩니다.

## 구체적인 예제로 보는 설계 선택

`music21`은 성능과 유연성 사이에서 정교한 설계 선택을 보여줍니다. 특히 `meter.core` 모듈에서는 박자 구조를 정의할 때 `MeterTerminal`과 `MeterSequence`를 사용하여 중첩된 리듬 구조를 효율적으로 처리합니다.

```python
# music21/meter/core.py의 MeterTerminal 초기화
def __init__(self, slashNotation: str|None = None, weight: int|float = 1):
    self._duration: Duration|None = None
    self._numerator: int = 0
    self._denominator: int = 1
    # ... (중략)
    self._ratioChanged()
```

위 코드에서 볼 수 있듯이, `MeterTerminal`은 박자 정보를 `numerator`와 `denominator`로 분리하여 관리하며, `_ratioChanged()`를 통해 내부 상태를 갱신합니다. 이는 복잡한 복합 박자를 계산할 때 불필요한 연산을 줄이고 데이터의 일관성을 유지하기 위한 설계입니다. 또한, `__deepcopy__`를 직접 구현하여 성능을 최적화한 점은 대규모 악보 데이터를 다룰 때의 오버헤드를 고려한 결과로 해석됩니다.

## 대안과 비교했을 때의 장단점

음악 분석 도구로서 `music21`은 다음과 같은 특징을 가집니다.

* **장점**: 음악학적 도메인 지식이 깊게 반영되어 있어, 단순히 MIDI 데이터를 다루는 라이브러리보다 훨씬 고차원적인 분석(예: 화성 분석, 대위법 규칙 검사)이 가능합니다. 또한, 방대한 문서화와 테스트 커버리지가 강점입니다.
* **단점**: 음악학적 추상화 수준이 높기 때문에, 단순히 오디오 신호를 처리하거나 실시간 연주를 위한 저지연(Low-latency) 처리가 필요한 경우에는 다소 무거울 수 있습니다. 이 경우 `mido`와 같은 경량 라이브러리가 더 적합할 수 있습니다.

## 보안·라이선스·도입 시 확인할 점

* **라이선스**: `BSD-3-Clause`를 따르며, 상업적 이용과 수정이 자유롭습니다. 단, 저장소 내 포함된 일부 외부 데이터셋이나 코퍼스는 별도의 라이선스를 가질 수 있으므로 주의가 필요합니다.
* **보안**: `CONTRIBUTING.md`에 명시된 바와 같이, AI를 활용한 코드 기여 시 반드시 이를 선언해야 합니다. 이는 코드의 출처와 책임 소재를 명확히 하기 위한 정책입니다.
* **도입 시 확인**: `pyproject.toml`에서 확인할 수 있듯이 파이썬 3.12 이상을 요구합니다. 기존 프로젝트에 도입 시 파이썬 버전 호환성을 반드시 점검해야 합니다.

## 한계와 추천 대상

`music21`은 음악학 연구자, 음악 이론을 프로그래밍으로 구현하려는 개발자, 그리고 음악 교육용 소프트웨어를 제작하는 이들에게 최적의 도구입니다. 그러나 실시간 오디오 합성이나 고성능 게임 음악 엔진 개발이 주 목적이라면 적합하지 않습니다. 

이 라이브러리는 '음악적 데이터의 구조적 이해'에 집중하고 있으므로, 데이터 과학적 접근으로 음악을 분석하고자 하는 사용자에게 강력한 기반을 제공할 것입니다. 도입 전, 공식 문서의 `User's Guide`를 통해 본인의 분석 목적이 `music21`의 추상화 모델과 일치하는지 확인하는 것을 권장합니다.
