## 현상

설정 파일이나 명령줄 인자로 모듈 이름을 문자열로 전달받아 실행 시점에 불러와야 하는 경우가 있습니다. 이때 문자열을 일반 `import` 문에 직접 넣을 수는 없습니다.

예를 들어 `myapp.commands.command1`이라는 이름을 설정에서 읽었다고 가정하겠습니다.

## 원인

일반적인 `import` 문은 소스 코드에 모듈 경로가 작성되어 있다는 전제로 동작합니다. 모듈 이름이 문자열 변수에 들어 있다면 문자열을 모듈 객체로 바꾸는 동적 import API가 필요합니다.

과거에는 내장 함수 `__import__()`를 사용하기도 했지만, 패키지의 루트 모듈과 실제 하위 모듈을 구분하는 `fromlist` 동작 등으로 코드가 복잡해질 수 있습니다.

## 해결 방법

모듈 이름이 문자열로 주어졌다면 표준 라이브러리의 `importlib.import_module()`을 사용하는 것이 가장 간단합니다.

~~~python
import importlib

module_name = "myapp.commands.command1"
command_module = importlib.import_module(module_name)

command_module.run()
~~~

하위 모듈을 가져오려는 경우에도 전체 점(.) 구분 경로를 전달하면 해당 모듈 객체를 반환합니다.

## 상대 모듈 이름 가져오기

현재 패키지 안에서 상대 모듈을 불러와야 한다면 `package` 인자를 함께 전달합니다.

~~~python
import importlib

# 현재 패키지가 myapp.commands인 모듈에서
plugin = importlib.import_module(".command1", package="myapp.commands")
~~~

상대 경로를 사용할 때는 기준이 되는 패키지 이름을 정확히 전달해야 합니다.

## __import__를 사용해야 하는 경우

기존 코드와의 호환 때문에 `__import__()`를 사용해야 한다면 `fromlist`에는 실제 하위 모듈에서 가져올 속성 또는 이름을 전달해야 합니다. 다만 새 코드를 작성할 때는 `importlib.import_module()`을 우선하는 편이 읽기 쉽습니다.

~~~python
module = __import__(
    "myapp.commands.command1",
    fromlist=["run"],
)
module.run()
~~~

## 보안 및 예외 처리

사용자 입력을 검증하지 않고 모듈 이름으로 곧바로 사용하면 의도하지 않은 모듈을 불러올 수 있습니다. 동적으로 불러올 모듈을 미리 허용 목록으로 제한하고, `ModuleNotFoundError` 등 import 실패를 명시적으로 처리하세요.

~~~python
import importlib

ALLOWED_COMMANDS = {
    "list": "myapp.commands.list_command",
    "build": "myapp.commands.build_command",
}

def load_command(name: str):
    module_name = ALLOWED_COMMANDS.get(name)
    if module_name is None:
        raise ValueError(f"지원하지 않는 명령: {name}")

    return importlib.import_module(module_name)
~~~
