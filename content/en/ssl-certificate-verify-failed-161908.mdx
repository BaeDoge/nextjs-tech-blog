## Symptom

A request to an HTTPS endpoint may fail with an error similar to:

```text
requests.exceptions.SSLError: [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed
```

This generally means the client cannot build a trusted certificate chain for the server. The cause may be in the operating system, Python environment, CA bundle, server configuration, or network proxy.

## Cause

Common causes include:

1. The CA bundle used by `requests` is missing or outdated.
2. An HTTPS-inspecting corporate proxy re-signs certificates, but its organization-managed CA is not trusted by the Python environment.
3. The server omits an intermediate certificate or has an expired or misconfigured certificate.
4. An old operating system or Python build does not have an up-to-date trust store or TLS support.

`requests` normally uses the CA bundle provided by `certifi`. A browser and Python may therefore behave differently if they use different certificate stores.

## Solution: Check and update the CA bundle

Check the certificate bundle paths used by `requests` and `certifi`.

```python
import certifi
import requests

print("requests CA bundle:", requests.certs.where())
print("certifi CA bundle:", certifi.where())
```

Update the packages in the same Python environment that runs the application.

```bash
python -m pip install --upgrade requests certifi
```

If your organization requires a private CA, obtain the CA bundle from your IT or security team and pass its path to `verify`.

```python
import requests

response = requests.get(
    "https://internal.example.com",
    verify="/path/to/organization-ca-bundle.pem",
    timeout=15,
)
response.raise_for_status()
```

You can also configure a persistent CA bundle path with `REQUESTS_CA_BUNDLE`.

```bash
# Linux/macOS
export REQUESTS_CA_BUNDLE=/path/to/organization-ca-bundle.pem

# Windows CMD
set REQUESTS_CA_BUNDLE=C:\certs\company-ca.pem
```

## pip Installation Errors

pip has its own certificate configuration. To use an organization-managed CA bundle for an installation, specify `--cert`.

```bash
python -m pip install --cert C:\certs\company-ca.pem package-name
```

Alternatively, set the `PIP_CERT` environment variable to the trusted CA bundle path. Do not download an arbitrary server certificate and treat it as a trusted CA.

## Methods to Avoid

`requests.get(..., verify=False)` disables server certificate verification. pip’s `--trusted-host` option bypasses normal host verification for the specified host. These options may make a connection succeed, but they remove important protection against man-in-the-middle attacks. Do not use them as a routine fix. Configure the correct CA certificate or have the server administrator repair the certificate chain.

## Additional Checks

- Call `ssl.get_default_verify_paths()` to inspect the default CA paths used by Python’s SSL module.
- If a browser also reports a certificate warning for the same endpoint, check the server certificate chain and expiration date.
- If an unsupported operating system cannot receive root-certificate updates, consider migrating to a supported OS and Python version.
- If the server certificate is expired or its chain is incomplete, the server operator must correct the server configuration.
