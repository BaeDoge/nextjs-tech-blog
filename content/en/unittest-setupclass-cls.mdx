## Symptom

When a `unittest.TestCase` subclass defines `setUpClass(cls)` without `@classmethod`, the test runner calls the function without binding the class object. The test fails during class setup.

```python
import unittest

class Config:
    fs = False

config = Config()

class TestDownload(unittest.TestCase):
    def setUpClass(cls):
        config.fs = True

    def test_download(self):
        self.assertTrue(config.fs)
```

The resulting error is similar to:

```text
TypeError: setUpClass() missing 1 required positional argument: 'cls'
```

## Cause

`unittest` calls `setUpClass` on the test class before creating individual test instances. Without `@classmethod`, the function is not bound to the class, so Python does not supply the `cls` argument.

## Solution

Add `@classmethod` above `setUpClass`. The class object is then passed automatically as the first argument.

```python
import unittest

class Config:
    fs = False

config = Config()

class TestDownload(unittest.TestCase):
    @classmethod
    def setUpClass(cls):
        config.fs = True

    def test_download(self):
        self.assertTrue(config.fs)
```

Run the test with `python -m unittest` or your project’s test command.

## Alternative Solution

If the setup is needed separately for every test method rather than once per class, use `setUp(self)`. A new test instance is created for each test method.

```python
import unittest

class Config:
    fs = False

class TestDownload(unittest.TestCase):
    def setUp(self):
        self.config = Config()
        self.config.fs = True

    def test_download(self):
        self.assertTrue(self.config.fs)
```

## Additional Notes

`tearDownClass` is also a class method and should be decorated with `@classmethod`. Keep shared resources isolated and release them in `tearDownClass` when appropriate.
