## Symptom

In Python 3, attempting to increment or decrement a variable from an enclosing function inside a nested function can raise `UnboundLocalError`.

```text
UnboundLocalError: local variable 'counter' referenced before assignment
```

```python
def foo():
    counter = 1

    def bar():
        counter += 1
        print("bar", counter)

    return bar

bar = foo()
bar()
```

## Cause

Python treats a name as local to a function when that function assigns to it, unless the name is declared `global` or `nonlocal`. Augmented assignment such as `counter += 1` also assigns to the name and behaves conceptually like `counter = counter + 1`.

The nested function therefore tries to read its own local `counter` before that local variable has been initialized.

## Solution

In Python 3, declare the enclosing variable with `nonlocal` before reassigning it.

```python
def foo():
    counter = 1

    def bar():
        nonlocal counter
        counter += 1
        print("bar", counter)

    return bar

bar = foo()
bar()  # bar 2
```

## Alternative Solutions

When supporting legacy Python 2 code, where `nonlocal` is not available, a mutable container can hold the state. Python 2 is end-of-life and should not be chosen for new projects.

```python
def foo():
    counter = [1]

    def bar():
        counter[0] += 1
        print("bar", counter[0])

    return bar

bar = foo()
bar()  # bar 2
```

A class can also make the state explicit.

```python
class Counter:
    def __init__(self, value=1):
        self.value = value

    def increment(self):
        self.value += 1
        return self.value

counter = Counter()
print(counter.increment())  # 2
```

## Additional Notes

- Use `nonlocal` when you need to reassign a variable in an enclosing function scope.
- Use `global` only when the name belongs to the module-level scope.
- A mutable container can avoid rebinding the outer name, but it should not be used as a substitute for clear state design in new code.
