## Symptom

Attempting to add a custom class inheriting from `list` to a `set` or use it as a key in a `dict` raises a `TypeError: unhashable type`.
According to the documentation, defining `__hash__` and `__eq__` methods makes a class hashable, but simply assigning `tuple.__hash__` does not work.

```python
class X(list):
    __hash__ = tuple.__hash__

x1 = X()
s = {x1}  # TypeError: unhashable type: 'X'
```

## Cause

The `list` class is a mutable data type, so `__hash__` is set to `None` by default, making it unhashable.
Simply copying `tuple.__hash__` to the `__hash__` attribute does not change the logic of the hashing algorithm.
The reason `tuple` is hashable is because it guarantees immutability. If an inherited class maintains mutability, it can compromise the stability of the hash value.
Therefore, you must explicitly define a `__hash__` method to specify how the class generates its hash value.

## Solution

Define the `__hash__` method directly to return a hash value based on the instance's content.
For mutable objects (such as lists), the standard approach is to convert them to an immutable object (tuple) and then calculate the hash value.

```python
class X2(list):
    def __hash__(self):
        return hash(tuple(self))

x2 = X2([1, 2, 3])
s = {x2}  # Success: {<__main__.X2 object at ...>}
```

## Alternative Solutions

You can also generate a hash value based on criteria other than the list's content (e.g., length, specific strings, etc.).
However, in this case, you must also redefine the `__eq__` method to clarify the comparison logic in case of hash collisions.
The example below generates a hash value based on the length of the list.

```python
class X3(list):
    def __hash__(self):
        return hash("foobar" * len(self))
    
    def __eq__(self, other):
        if not isinstance(other, X3):
            return NotImplemented
        return list(self) == list(other)
```

## Additional Notes

Since the hash value of a mutable object can change, hashable objects should not be modified after creation.
Mutable data types like `list` or `dict` cannot be used as keys in `set` or `dict`. To do so, you must convert them to `tuple` or implement custom hashing logic.
If you encounter an `unhashable type` error when using `drop_duplicates` in `pandas`, check if the target column contains list data and converting it to `tuple` can be a solution.

```python
# pandas example: Convert list column to tuple to remove duplicates
df['Like_Tuple'] = df['Like'].apply(tuple)
df.drop_duplicates(['Like_Tuple'])
```
