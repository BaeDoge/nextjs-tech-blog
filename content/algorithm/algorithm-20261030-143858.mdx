## 문제

서로 다른 denomination을 가진 `coins` 배열과 목표 금액 `amount`가 주어집니다. 각 동전은 무한히 사용할 수 있으며, `amount`를 만드는 데 필요한 최소 동전 개수를 반환해야 합니다. 만약 어떤 조합으로도 `amount`를 만들 수 없다면 -1을 반환합니다.

입력 조건은 다음과 같습니다. `coins`의 길이는 12 이하이며, 각 동전의 가치는 2^31 - 1 이하입니다. `amount`는 0 이상 10^4 이하입니다.

예를 들어 `coins = [1, 2, 5]`, `amount = 11`인 경우, 5 + 5 + 1 조합으로 최소 3개의 동전을 사용합니다. `coins = [2]`, `amount = 3`인 경우 2의 배수만 만들 수 있으므로 -1을 반환합니다.

## 접근 방법

이 문제는 부분 문제가 중첩되는 최적화 문제이므로 동적계획법(Dynamic Programming)을 적용할 수 있습니다. `dp[i]`를 금액 `i`를 만드는 데 필요한 최소 동전 개수라고 정의합니다.

초기 상태로 `dp[0]`은 0원일 때 0개의 동전이 필요하므로 0입니다. 나머지 `dp[i]`는 무한대(또는 불가능한 상태)로 초기화합니다.

상태 전이식은 각 동전 `c`에 대해 `dp[i] = min(dp[i], dp[i - c] + 1)`이 됩니다. 즉, 금액 `i`를 만들기 위해 마지막에 동전 `c`를 사용했다면, 금액 `i-c`를 만드는 최소 개수에 1을 더한 값과 현재 `dp[i]`의 최솟값을 취합니다.

## 풀이

`dp` 배열을 크기 `amount + 1`로 생성하고, 첫 원소를 0으로, 나머지를 `amount + 1`(불가능을 의미하는 값)로 초기화합니다.

외부 루프는 금액 `i`를 1부터 `amount`까지 증가시키며, 내부 루프는 각 동전 `c`를 순회합니다. 만약 `i - c`가 0 이상이고 `dp[i - c]`가 불가능한 상태가 아니면, `dp[i]`를 갱신합니다.

최종적으로 `dp[amount]`가 초기화 값보다 작으면 그 값을 반환하고, 그렇지 않으면 -1을 반환합니다.

```python
class Solution:
    def coinChange(self, coins: List[int], amount: int) -> int:
        # dp[i]는 금액 i를 만드는 최소 동전 개수
        # 초기값은 amount + 1 (불가능을 의미)
        dp = [amount + 1] * (amount + 1)
        dp[0] = 0
        
        for i in range(1, amount + 1):
            for c in coins:
                if i - c >= 0:
                    dp[i] = min(dp[i], dp[i - c] + 1)
                    
        return dp[amount] if dp[amount] <= amount else -1
```

시간복잡도: O(amount * n)입니다. 여기서 n은 `coins`의 길이입니다. 금액 1부터 `amount`까지 각 상태에 대해 모든 동전을 확인하므로 곱셈 형태가 됩니다.
공간복잡도: O(amount)입니다. `dp` 배열 하나만 사용하므로 선형 공간이 필요합니다.

## 다른 풀이 방법

Breadth-First Search(BFS)를 사용할 수도 있습니다. 각 노드를 현재 남은 금액으로 보고, 동전을 뺀 다음 금액으로 이동합니다.

BFS는 최단 경로를 찾는 알고리즘이므로, 첫 번째로 `amount`에 도달하는 단계가 최소 동전 개수가 됩니다. `visited` 배열을 사용하여 이미 방문한 금액은 다시 방문하지 않도록 최적화합니다.

시간복잡도는 최악의 경우 O(amount * n)으로 동적계획법과 유사하지만, 해답을 빨리 찾으면 조기 종료될 수 있어 평균적으로 더 빠를 수 있습니다. 공간복잡도는 큐와 방문 배열을 사용하므로 O(amount)입니다.

## 추가 참고사항

이 문제는 완전 배낭 문제(Complete Knapsack Problem)의 변형으로 볼 수 있습니다. 물건의 무게가 동전 가치, 가치가 1로 고정된 경우입니다.

`coins` 배열이 정렬되어 있지 않아도 동작하지만, 정렬하면 작은 동전부터 처리하여 일관된 순서를 가질 수 있습니다. 단, 알고리즘의 정확성에는 영향을 주지 않습니다.

`amount`가 0인 경우, 동전 개수는 0이므로 즉시 0을 반환해야 합니다. 코드에서는 `dp[0] = 0`으로 초기화되어 있으므로 자연스럽게 처리됩니다.

`coins`의 원소가 매우 크면 `i - c`가 음수가 되어 조건문에서 걸러지므로 안전합니다. 단, `amount`가 매우 크면 시간초과가 발생할 수 있으므로 제약 조건 내에서의 구현이 중요합니다.
