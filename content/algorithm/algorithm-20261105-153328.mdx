## 문제

이진 탐색 트리(BST)의 루트 노드와 삭제할 키(`key`)가 주어질 때, 해당 값을 가진 노드를 삭제한 후 업데이트된 루트 노드를 반환하는 함수를 작성해야 합니다. 삭제를 수행하는 과정은 크게 두 단계로 나뉩니다. 먼저 트리를 탐색하여 삭제 대상 노드를 찾아야 합니다. 만약 해당 값을 가진 노드가 발견되면, 이를 트리의 구조를 유지하면서 삭제해야 합니다. 만약 찾는 키가 트리에 존재하지 않으면, 원본 트리를 그대로 반환합니다.

주어진 이진 탐색 트리의 제약 조건은 다음과 같습니다. 노드의 개수는 최대 10,000개이며, 각 노드의 값은 음의 정수부터 양의 정수까지 범위가 넓습니다. 각 노드의 값은 고유하며, 입력된 루트는 유효한 이진 탐색 트리의 구조를 가집니다. 또한, 알고리즘의 시간 복잡도는 트리의 높이(`height`)에 비례하는 $O(height)$로 해결해야 합니다.

## 접근 방법

이진 탐색 트리의 성질을 이용하여 삭제 대상 노드를 탐색합니다. 탐색 과정은 이진 탐색 알고리즘과 동일합니다. 현재 노드의 값이 `key`보다 크면 왼쪽 서브트리로, 작으면 오른쪽 서브트리로 이동합니다.

삭제 대상 노드를 찾았을 때, 해당 노드의 자식 노드 개수에 따라 세 가지 경우로 나누어 처리합니다. 첫 번째로, 자식 노드가 없는 경우(리프 노드)에는 단순히 해당 노드를 제거하면 됩니다. 두 번째로, 하나의 자식 노드만 있는 경우, 자식 노드가 부모의 자리에 그대로 올라와 트리 구조를 유지하도록 연결합니다. 세 번째로, 두 개의 자식 노드가 모두 있는 경우입니다. 이 경우 삭제된 후에도 이진 탐색 트리의 정렬 순서가 깨지지 않도록, 해당 노드의 왼쪽 서브트리에서 가장 큰 값(직전 요소) 또는 오른쪽 서브트리에서 가장 작은 값(다음 요소)을 찾아 현재 노드의 값으로 대체합니다.

그 후, 중복된 값을 가진 노드가 발생하지 않도록 대체된 노드(직전 또는 다음 요소)를 다시 삭제해야 합니다. 이를 재귀적으로 구현하면 코드의 가독성과 유지보수성을 높일 수 있습니다.

## 풀이

다음은 재귀 함수를 사용하여 문제를 해결한 코드입니다.

```python
class Solution:
    def deleteNode(self, root: Optional[TreeNode], key: int) -> Optional[TreeNode]:
        # 1. 노드 탐색 및 재귀 호출 기반 삭제
        if root is None:
            return None
        
        if key < root.val:
            root.left = self.deleteNode(root.left, key)
        elif key > root.val:
            root.right = self.deleteNode(root.right, key)
        else:
            # 2. 삭제 대상 노드 찾음
            # case 1: 자식 노드가 없거나 하나의 자식만 있는 경우
            if root.left is None:
                return root.right
            elif root.right is None:
                return root.left
            
            # case 2: 두 개의 자식 노드가 모두 있는 경우
            # 오른쪽 서브트리에서 가장 작은 노드(최소값)를 찾아 현재 노드 값으로 대체
            min_val = self.find_min(root.right)
            root.val = min_val
            
            # 대체된 노드(오른쪽 서브트리의 최소값)는 다시 삭제해야 함
            root.right = self.deleteNode(root.right, min_val)
            
        return root

    def find_min(self, node: TreeNode) -> int:
        # 왼쪽으로 가장 많이 내려간 노드가 해당 서브트리의 최소값
        while node.left:
            node = node.left
        return node.val
```

**시간 복잡도:** $O(height)$
 BST의 높이는 노드 수 $N$에 대해 균형 잡힌 경우 $O(\log N)$, 기울어진 경우 $O(N)$입니다. 탐색과 삭제 과정에서 매 단계 상수 시간의 작업이 수행되므로, 시간 복잡도는 트리의 높이에 비례합니다.

**공간 복잡도:** $O(height)$
 재귀 호출의 깊이만큼 스택 공간을 사용합니다. 따라서 공간 복잡도 역시 트리의 높이에 비례합니다.

## 다른 풀이 방법

BST에서 두 개의 자식 노드를 가진 노드를 삭제할 때, 대체값으로 '오른쪽 서브트리의 최소값'을 선택하는 대신 '왼쪽 서브트리의 최대값'을 사용할 수 있습니다. 이는 BST의 정렬된 순서를 유지하기 위한 두 가지 논리적 방법입니다. 왼쪽 서브트리의 최대값을 사용하는 경우, 현재 노드의 값을 왼쪽 서브트리에서 가장 큰 값으로 바꾼 후, 해당 최대값을 가진 노드를 다시 삭제하면 됩니다. 이 방식은 앞서 설명한 오른쪽 서브트리의 최소값을 사용하는 방식과 원리가 동일하므로 시간 복잡도 $O(height)$와 공간 복잡도 $O(height)$에서 차이가 없습니다.

## 추가 참고사항

BST에서 노드 삭제를 구현할 때 주의할 점은, 값이 아닌 노드 참조(reference)의 연결 관계를 적절히 끊고 재연결해야 한다는 것입니다. 특히 두 자식 노드가 모두 있는 경우, 단순히 노드를 잘라내면 서브트리가 분리가 되므로, 대체된 노드를 다시 삭제하여 트리의 일관성을 유지해야 합니다. 또한, 입력 트리가 균형 잡히지 않은 skewed tree인 경우, 재귀 호출로 인한 스택 오버플로우가 발생할 수 있는 점을 염두에 두어야 합니다.
