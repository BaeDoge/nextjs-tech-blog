## 문제

Trie(접두사 트리)는 문자열 집합에서 키를 효율적으로 저장하고 검색하기 위한 트리 자료구조입니다. 이 문제는 `Trie` 클래스를 구현하는 것입니다. 클래스는 초기화 메서드, 문자열을 삽입하는 `insert`, 특정 문자열이 존재하는지 확인하는 `search`, 특정 접두사로 시작하는 문자열이 존재하는지 확인하는 `startsWith` 메서드를 포함해야 합니다. 제약 조건에 따르면 문자열과 접두사의 길이는 최대 2000이며, 총 호출 횟수는 30,000회 이내입니다. 모든 문자는 소문자 영어 알파벳으로 구성됩니다.

## 접근 방법

Trie는 각 노드가 문자를 나타내고, 루트에서 특정 노드까지의 경로가 문자열을 형성하는 구조입니다. 각 노드는 자식 노드들을 가리키는 포인터(또는 해시맵/배열)와 해당 문자열이 단어의 끝인지 여부를 나타내는 플래그를 가집니다.
1. `insert`: 루트에서 시작하여 문자열의 각 문자에 해당하는 자식 노드가 없으면 생성하며 이동합니다. 마지막 문자 노드에 '단어 끝' 플래그를 설정합니다.
2. `search`: 루트에서 시작하여 문자열의 각 문자에 해당하는 자식 노드가 존재하는지 확인하며 이동합니다. 마지막 문자까지 도달했을 때 '단어 끝' 플래그가 설정되어 있는지 확인합니다.
3. `startsWith`: `search`와 유사하게 동작하지만, 마지막 노드에 도달했을 때 '단어 끝' 플래그 여부는 확인하지 않고 단순히 해당 접두사를 가진 경로가 존재하는지만 확인합니다.

## 풀이

배열을 사용하여 자식 노드를 관리하면 공간 효율성과 접근 속도를 높일 수 있습니다. 알파벳 소문자 26개에 대응하기 위해 크기가 26인 배열을 각 노드에 포함시킵니다.

```python
class TrieNode:
    def __init__(self):
        self.children = [None] * 26
        self.is_end_of_word = False

class Trie:
    def __init__(self):
        self.root = TrieNode()
    
    def _index(self, char):
        return ord(char) - ord('a')

    def insert(self, word: str) -> None:
        node = self.root
        for char in word:
            index = self._index(char)
            if not node.children[index]:
                node.children[index] = TrieNode()
            node = node.children[index]
        node.is_end_of_word = True

    def search(self, word: str) -> bool:
        node = self.root
        for char in word:
            index = self._index(char)
            if not node.children[index]:
                return False
            node = node.children[index]
        return node.is_end_of_word

    def startsWith(self, prefix: str) -> bool:
        node = self.root
        for char in prefix:
            index = self._index(char)
            if not node.children[index]:
                return False
            node = node.children[index]
        return True
```

시간복잡도: `insert`, `search`, `startsWith` 모두 문자열의 길이 $L$에 비례하여 $O(L)$입니다.
공간복잡도: 삽입된 모든 문자의 최대 길이 합에 비례하여 $O(\sum L)$입니다. 각 노드는 26개의 포인터를 가지므로 상수 배수가 곱해집니다.

## 다른 풀이 방법

해시맵을 사용하여 자식 노드를 관리하는 방법이 있습니다. 배열 대신 `children = {}`로 초기화하면, 실제 존재하는 자식 노드만 저장하므로 빈 공간이 많을 때 메모리 절약 효과가 있을 수 있습니다. 다만, 인덱싱 연산($O(1)$) 대신 해시 연산($O(1)$ 평균)이 발생하며, 자식 노드 존재 여부를 확인할 때 키 존재 여부를 확인해야 하므로 구현이 다소 복잡해질 수 있습니다. 배열 방식은 고정된 크기를 가지지만 인덱스 접근이 매우 빠르므로, 알파벳 크기가 작고 고정된 이 문제에서는 배열 방식이 일반적으로 더 효율적입니다.

## 추가 참고사항

Trie는 접두사 기반 검색, 자동 완성, 사전_spell checker_ 등에 널리 사용됩니다. `startsWith` 메서드는 `search` 메서드와 로직이 거의 동일하지만, 최종 노드의 `is_end_of_word` 플래그를 체크하지 않는 점이 차이점입니다. 제약 조건에서 문자열 길이가 2000까지 가능하므로, 깊이 있는 재귀 호출 대신 반복문을 사용하는 것이 스택 오버플로우 위험을 줄이고 성능에 유리합니다.
