## 문제

주어진 문자열 배열 `words`에서 다른 문자열의 부분 문자열(substring)에 해당하는 모든 문자열을 찾아 반환해야 합니다. 반환 순서는 상관없으며, 각 문자열은 고유합니다.

예를 들어 입력이 `["mass","as","hero","superhero"]`일 때, "as"는 "mass"의 부분 문자열이고 "hero"는 "superhero"의 부분 문자열이므로 결과를 `["as", "hero"]`로 반환합니다. 입력이 `["blue","green","bu"]`일 경우, 어떤 문자열도 다른 문자열의 부분 문자열이 아니므로 빈 배열 `[]`을 반환합니다.

Constraints는 다음과 같습니다:
- 배열의 길이: 1 이상 100 이하
- 각 문자열의 길이: 1 이상 30 이하
- 문자열은 소문자 영문자로만 구성됨

## 접근 방법

문자열의 최대 길이가 30이고 배열의 최대 길이가 100으로 매우 작기 때문에, 모든 문자열 쌍을 비교하는 완전 탐색(All Pairs) 방식으로 충분히 문제를 해결할 수 있습니다.

각 문자열을 하나씩 선택하여, 배열 내 다른 모든 문자열이 해당 문자열을 부분 문자열로 포함하는지 확인하면 됩니다. 만약 다른 어떤 문자열에 포함된다면 결과 목록에 추가하면 됩니다. Python의 `in` 연산자는 부분 문자열 여부를 효율적으로 확인해 주므로, 이를 활용하여 이중 루프를 구현하면 됩니다.

## 풀이

두 개의 인덱스를 사용하여 중첩 루프를 돌며 비교합니다. 바깥 루프는 현재 확인하고 있는 대상 문자열을, 안쪽 루프는 비교 대상 문자열을 담당합니다. 같은 인덱스를 가진 문자열끼리는 비교하지 않습니다. 안쪽 루프에서 포함 관계가 하나라도 발견되면 즉시 결과에 추가하고 다음 문자열로 넘어갑니다.

```python
class Solution:
    def stringMatching(self, words: list[str]) -> list[str]:
        result = []
        n = len(words)
        
        # 모든 단어 쌍을 비교
        for i in range(n):
            for j in range(n):
                # 같은 인덱스는 제외하고, 다른 문자열에 현재 문자열이 포함되어 있으면
                if i != j and words[i] in words[j]:
                    result.append(words[i])
                    break # 이미 포함되는 것이 확인되었으므로 안쪽 루프 종료
        
        return result
```

- **시간 복잡도**: $O(N^2 \times M)$입니다. 여기서 $N$은 단어의 개수, $M$은 단어의 최대 길이입니다. 문자열 포함 확인(`in` 연산자)은 최대 $M$의 시간이 소요되며, 이를 $N \times N$개의 쌍에 대해 수행하기 때문입니다. 주어진 제약 조건($N=100, M=30$)에서는 연산 횟수가 매우 적어 매우 빠르게 동작합니다.
- **공간 복잡도**: $O(1)$입니다. 결과 리스트를 제외하면 추가적인 저장 공간을 사용하지 않습니다. 결과 리스트의 크기는 최대 $N$이므로 엄밀히 말하면 $O(N)$일 수 있으나, 부가적인 자료구조 사용이 아니므로 보조 공간 복잡도는 $O(1)$로 간주합니다.

## 다른 풀이 방법

**KMP 알고리즘 활용**: 부분 문자열 탐색을 $O(M)$에 수행할 수 있는 KMP 알고리즘을 사용할 수 있습니다. 시간 복잡도는 $O(N^2 \times M)$으로 동일하지만, 상수 시간에서 문자열 탐색 속도가 개선될 수 있습니다. 그러나 $M$이 작으므로 Python의 내장 함수가 일반적으로 더 빠릅니다.

**정렬 기반 접근**: 문자열의 길이를 기준으로 배열을 정렬합니다. 길이가 짧은 문자열은 길이가 긴 문자열의 부분 문자열일 수 있지만, 그 반대는 불가능합니다. 따라서 정렬된 배열에서 $i$ 번째 문자열과 $j$ ($j > i$) 번째 문자열만 비교하면 됩니다. 이는 비교 쌍의 수를 절반으로 줄여줍니다.

- **비교**: 완전 탐색은 코드가 가장 단순하고 구현 오류가 적습니다. 정렬 기반 접근은 비교 횟수를 줄여 효율성을 높일 수 있지만, 구현 난이도가 약간 높아지고 정렬 시간 $O(N \log N)$이 추가됩니다. 제약 조건이 작으므로 두 방법 모두 적합합니다.

## 추가 참고사항

이 문제는 문자열 매칭의 기본 개념을 묻는 문제입니다. Python, Java, C++ 등 대부분의 언어에서 `contains`, `in`, `find` 등의 내장 함수는 최적화된 문자열 검색 알고리즘(예: Boyer-Moore 또는 KMP의 변형)을 사용하기 때문에, 특별한 경우가 아니면 직접 알고리즘을 구현하지 않고 내장 함수를 사용하는 것이 효율적입니다.

문자열의 길이 차이가 클 경우, 부분 문자열 후보는 길이가 더 짧은 쪽임을 기억하면 비교 대상을 일부 필터링하는 데 도움이 됩니다.
