## 문제

정수 배열 `nums`가 주어졌을 때, 최장 증가 부분 수열(Longest Increasing Subsequence, LIS)의 길이와 그 길이로 만들 수 있는 수열의 경우의 수를 반환해야 합니다. 여기서 증가 부분 수열은 각 원소가 이전 원소보다 엄격하게 커야 합니다.
배열의 길이는 최대 2,000이며, 원소의 값은 -1,000,000에서 1,000,000 사이입니다. 결과 값은 32비트 정수 범위 내에 있음이 보장됩니다.

## 접근 방법

이 문제는 각 원소를 마지막 요소로 하는 증가 부분 수열의 길이와 경우의 수를 함께 관리해야 합니다.
배열을 순회하며 각 원소 `nums[i]`보다 작은 이전 원소 `nums[j]` (`j < i`)들을 탐색합니다.
만약 `nums[j]`를 마지막 원소로 하는 수열에 `nums[i]`를 이어붙여 더 긴 수열을 만들 수 있다면, 길이와 경우의 수를 업데이트합니다.
단순히 길이가 더 길어지면 길이를 갱신하고 경우의 수를 `counts[j]`로 초기화합니다.
길이가 기존 최장 길이와 같다면, 기존 경우의 수에 `counts[j]`를 누적하여 합산합니다.
이 과정을 모든 인덱스에 대해 수행한 후, 전체 최장 길이를 가진 경우의 수 합을 구하면 정답이 됩니다.

## 풀이

두 개의 배열 `lengths`와 `counts`를 사용합니다. `lengths[i]`는 `nums[i]`를 마지막으로 하는 LIS의 길이를, `counts[i]`는 그 길이를 만드는 경우의 수를 저장합니다.
초기화 시 모든 길이는 1, 모든 경우의 수는 1로 설정합니다.
중첩 루프를 통해 `j < i`인 모든 쌍에 대해 조건을 확인하고 값을 갱신합니다.
최종적으로는 `lengths` 배열에서 최대 길이 `max_len`을 찾은 후, 해당 길이를 가지는 모든 인덱스의 `counts`를 합산합니다.

시간 복잡도: 이중 루프를 사용하므로 $O(N^2)$입니다.
공간 복잡도: 두 가지 보조 배열을 사용하므로 $O(N)$입니다.

```python
def findNumberOfLIS(nums: list[int]) -> int:
    n = len(nums)
    if n == 0:
        return 0

    # lengths[i]: nums[i]를 마지막으로 하는 LIS의 길이
    lengths = [1] * n
    # counts[i]: nums[i]를 마지막으로 하는 LIS의 길이와 같은 경우의 수
    counts = [1] * n

    for i in range(n):
        for j in range(i):
            if nums[j] < nums[i]:
                # 더 긴 부분 수열을 찾은 경우
                if lengths[j] + 1 > lengths[i]:
                    lengths[i] = lengths[j] + 1
                    counts[i] = counts[j]
                # 기존 최장 길이와 같은 경우를 찾은 경우
                elif lengths[j] + 1 == lengths[i]:
                    counts[i] += counts[j]

    # 전체 최장 LIS 길이 찾기
    max_len = max(lengths)
    
    # 최장 길이인 경우의 수 합산
    ans = 0
    for i in range(n):
        if lengths[i] == max_len:
            ans += counts[i]
            
    return ans
```

## 다른 풀이 방법

$O(N \log N)$ 시간 복잡도를 요구하는 경우, Binary Indexed Tree(BIT) 또는 Segment Tree를 활용할 수 있습니다.
이 방법은 각 값을 압축한 후, Tree 구조를 이용해 현재 원소보다 작은 값 중 최장 길이를 가진 경우의 수를 빠르게 조회하고 업데이트합니다.
구현이 복잡하지만, 배열의 길이가 매우 큰 경우($N > 10^4$)에 유용합니다.
현재 문제의 제약 조건($N \le 2,000$)에서는 $O(N^2)$ 동적 계획법이 구현의 용이성 면에서 더 적합합니다.

## 추가 참고사항

동적 계획법 상태 전이 시, `lengths[j] + 1 == lengths[i]`인 경우에만 `counts`를 추가하는 것에 주의해야 합니다.
길이가 더 짧아지는 경우는 무시하고, 더 긴 경우에만 경로를 갱신해야 올바른 경우의 수를 계산할 수 있습니다.
이는 LIS 문제의 기본 구조와 동일하게, 각 인덱스에서의 최적 해 정보를 누적하여 전역 최적 해를 구하는 방식입니다.
