## 문제

주어진 `m x n` 크기의 행렬 `grid`는 행과 열 모두에서 내림차순(non-increasing)으로 정렬되어 있습니다. 이 행렬에 포함된 음수(negative number)의 총 개수를 반환하는 함수를 구현해야 합니다.

입력 예시에서 `grid = [[4,3,2,-1],[3,2,1,-1],[1,1,-1,-2],[-1,-1,-2,-3]]`일 때, 음수는 총 8개이므로 8을 반환합니다. 제약 조건으로 행렬의 크기는 최대 100x100이며, 원소의 값은 -100에서 100 사이입니다.

## 접근 방법

행렬이 행과 열 모두 정렬되어 있다는 특성을 활용해야 합니다. 가장 직관적인 접근은 모든 요소를 순회하며 음수인지 확인하는 것이지만, 문제의 Follow up에서는 `O(n + m)` 시간 복잡도를 요구합니다.

이 목표에 부합하는 접근법은 행렬의 오른쪽 위 모서리(`grid[0][n-1]`)에서 시작하는 것입니다.
1. 현재 위치의 값이 음수라면, 해당 열의 아래쪽 모든 요소도 음수입니다. 따라서 해당 열에 있는 음수의 개수(`m - 현재 행 인덱스`)를 카운트하고, 왼쪽 열로 이동합니다.
2. 현재 위치의 값이 음수가 아니면, 현재 행의 오른쪽에 있는 요소들은 모두 양수(또는 0)이므로, 아래쪽 행으로 이동하여 탐색을 계속합니다.

이 과정을 현재 위치가 행렬의 경계를 벗어나기 전까지 반복하면 전체 음수를 효율적으로 찾을 수 있습니다.

## 풀이

오른쪽 위에서 아래로 탐색하는 `O(m + n)` 알고리즘을 구현합니다.

```python
class Solution:
    def countNegatives(self, grid: list[list[int]]) -> int:
        m = len(grid)
        n = len(grid[0])
        
        count = 0
        row = 0
        col = n - 1
        
        # 오른쪽 위 모서리에서 시작
        while row < m and col >= 0:
            if grid[row][col] < 0:
                # 현재 위치가 음수이면, 이 열의 아래쪽 모든 값도 음수
                # 해당 열의 음수 개수: 현재 행 인덱스부터 마지막 행까지
                count += (m - row)
                # 왼쪽 열로 이동
                col -= 1
            else:
                # 현재 위치가 음수가 아니면, 이 행의 오른쪽 값들은 모두 양수
                # 아래쪽 행으로 이동
                row += 1
                
        return count
```

시간 복잡도: `O(m + n)`. 한 번의 이동마다 행 인덱스가 증가하거나 열 인덱스가 감소하므로, 최대 `m + n`번의 비교 연산이 수행됩니다.
공간 복잡도: `O(1)`. 추가적인 메모리를 사용하지 않습니다.

## 다른 풀이 방법

1. **이진 탐색 (Binary Search)**
   각 행마다 이진 탐색을 사용하여 첫 번째 음수가 나타나는 인덱스를 찾습니다. 한 행의 길이가 `n`이므로, 각 행당 `O(log n)`이 소요되고 총 `m`개의 행이 있으므로 전체 시간 복잡도는 `O(m log n)`입니다.
   
   

```python
   class Solution:
       def countNegatives(self, grid: list[list[int]]) -> int:
           count = 0
           for row in grid:
               # 이진 탐색으로 첫 번째 음수 인덱스 찾기
               left, right = 0, len(row)
               while left < right:
                   mid = (left + right) // 2
                   if row[mid] < 0:
                       right = mid
                   else:
                       left = mid + 1
               # left 인덱스부터 끝까지가 모두 음수
               count += (len(row) - left)
           return count
   
```

   이 방법은 `m`이 `n`에 비해 매우 클 때 유리할 수 있으나, 일반적으로 `O(m + n)` 접근법보다 상수 시간이 더 걸릴 수 있습니다.

2. **완전 탐색 (Brute Force)**
   모든 요소를 순회하며 음수인지 확인합니다. 시간 복잡도는 `O(m * n)`입니다. 제약 조건에서 `m, n <= 100`이므로 `10,000` 연산으로 충분히 통과할 수 있지만, 문제에서 요구한 최적화 기준에는 부합하지 않습니다.

## 추가 참고사항

- 문제의 핵심은 "정렬된 특성"을 얼마나 효율적으로 활용하느냐에 있습니다.
- `O(m + n)` 접근법은 행렬의 경계를 따라 이동하는 방식으로, 그리디한 성질을 가집니다.
- 이진 탐색 방식은 행이 독립적으로 처리되므로 병렬화나 특정 데이터 구조 최적화에 유리할 수 있는 구조를 가집니다.
- 제약 조건이 작을 경우 단순 순회도 허용되지만, 코딩 테스트에서는 항상 최적의 시간 복잡도를 고려하는 것이 좋습니다.
