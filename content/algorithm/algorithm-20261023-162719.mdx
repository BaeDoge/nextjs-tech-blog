## 문제

두 문자열 `s`와 `t`가 주어졌을 때, `s`가 `t`의 부분수열(subsequence)인지 확인하는 함수를 구현해야 합니다. 부분수열이란 원래 문자열에서 일부 문자를 삭제(또는 모두 삭제)하되, 남은 문자들의 상대적인 순서를 유지하여 만든 새로운 문자열을 의미합니다. 예를 들어, `"ace"`는 `"abcde"`의 부분수열이지만 `"aec"`는 아닙니다. 입력 문자열의 길이는 각각 최대 100과 10^4이며, 소문자 영문자로만 구성됩니다.

## 접근 방법

가장 직관적이고 효율적인 방법은 두 개의 포인터를 사용하는 투 포인터 기법입니다. `s`의 문자를 순서대로 찾아가며 `t`에서 일치하는 문자를 찾아 매칭시키는 방식입니다. `s`의 각 문자가 `t` 내에서 앞선 매칭 위치보다 뒤에 나타나야 하므로, `t`의 탐색 위치는 한 번 지나간 곳으로 되돌아가지 않고 계속 앞으로 나아가면 됩니다. `s`의 모든 문자가 `t`에서 순서대로 발견되면 `true`, `t`의 탐색이 끝나기 전에 `s`의 문자를 모두 찾지 못하면 `false`를 반환합니다.

## 풀이

```python
def isSubsequence(s: str, t: str) -> bool:
    # s가 빈 문자열이면 항상 부분수열입니다.
    if not s:
        return True
    
    # t가 s보다 짧으면 부분수열이 될 수 없습니다.
    if len(s) > len(t):
        return False

    s_idx = 0
    t_idx = 0
    
    # t의 모든 문자를 탐색하며 s의 현재 문자와 매칭 시도
    while t_idx < len(t):
        if s[s_idx] == t[t_idx]:
            s_idx += 1
            # s의 모든 문자를 찾았으면 종료
            if s_idx == len(s):
                return True
        t_idx += 1
        
    return False
```

시간복잡도: $O(N)$ (여기서 $N$은 `t`의 길이)
공간복잡도: $O(1)$

## 다른 풀이 방법

동적 프로그래밍(Dynamic Programming) 또는 사전 처리(preprocessing) 기법을 사용할 수 있습니다. 특히 Follow-up에서 언급된 것처럼 `t`에 대해 수많은 `s`를 체크해야 하는 경우 유용합니다. `t`의 각 인덱스에서부터 각 알파벳('a'~'z')이 처음으로 등장하는 위치를 미리 저장한 테이블을 구축합니다. 이후 `s`의 문자를 순회할 때, 현재 위치에서 다음으로 필요한 알파벳이 나타나는 최소 인덱스로 점프하며 탐색합니다. 이 방법은 초기 구축 비용 $O(M \times 26)$ ($M$은 `t`의 길이)이 발생하지만, 이후 각 `s`에 대한 쿼리는 $O(K)$ ($K$는 `s`의 길이)에 처리할 수 있어 다수의 쿼리 처리에 유리합니다.

## 추가 참고사항

Follow-up에서 제시된 다수의 `s`에 대한 최적화 관점에서, 투 포인터 방식은 각 `s`마다 $O(N)$의 시간이 걸리므로 총 $O(K \times N)$의 시간이 소요됩니다. 반면, 사전 처리된 인덱스 테이블을 사용하면 각 `s`당 $O(K)$ 시간이 걸려 총 $O(K \times K + M \times 26)$의 시간이 소요됩니다. `K`와 `M`의 관계 및 쿼리 횟수에 따라 적절한 전략을 선택해야 합니다. 또한, Python의 내장 메서드 `t.find(char, start)`를 활용하면 구현을 더 간결하게 작성할 수 있습니다.
