## 문제

두 개의 서로 다른 정수 배열 `nums1`과 `nums2`가 주어집니다. 여기서 `nums1`은 `nums2`의 부분 집합(subset)입니다. `nums1`의 각 원소 `x`에 대하여, `nums2`에서 `x`가 위치한 위치의 오른쪽에 존재하는 `x`보다 큰 첫 번째 원소를 찾아야 합니다. 만약 그러한 원소가 존재하지 않으면 해당 쿼리의 답은 `-1`이 됩니다. `nums1`의 각 원소에 대한 답을 순서대로 담은 배열 `ans`를 반환합니다. 제약 조건으로 `nums1`과 `nums2`의 길이는 각각 최대 1000이며, 배열 내의 모든 정수는 고유합니다.

## 접근 방법

먼저 `nums2`의 각 원소에 대해 '다음으로 큰 원소'를 모두 미리 계산해 두면, `nums1`의 원소에 대한 쿼리를 상수 시간에 처리할 수 있습니다. `nums2`를 순회하며 스택을 활용하여 다음 큰 원소를 찾는 알고리즘을 적용합니다. 스택에는 아직 다음 큰 원소를 찾지 못한 원소들의 인덱스(또는 값)를 오름차순으로 유지합니다. 현재 순회하는 원소가 스택의 최상단 원소보다 크다면, 스택에서 원소를 꺼내 해당 원소의 '다음 큰 원소'가 현재 원소임을 기록합니다. 이 과정을 반복하여 `nums2`의 모든 원소에 대한 다음 큰 원소를 해시맵에 저장한 후, `nums1`의 원소를 해시맵에서 조회하여 결과를 구성합니다.

## 풀이

`nums2`를 순회하며 스택을 사용하여 각 원소의 다음 큰 원소를 계산하고 해시맵에 저장합니다. 이후 `nums1`의 각 원소에 대해 해시맵에서 값을 조회하여 결과를 반환합니다.

```python
class Solution:
    def nextGreaterElement(self, nums1: List[int], nums2: List[int]) -> List[int]:
        # nums2의 각 원소에 대한 다음 큰 원소를 저장할 해시맵
        next_greater_map = {}
        # 스택: 아직 다음 큰 원소를 찾지 못한 원소를 저장
        stack = []
        
        for num in nums2:
            # 현재 원소가 스택의 최상단 원소보다 크면
            while stack and stack[-1] < num:
                # 스택에서 원소를 꺼내고, 그 원소의 다음 큰 원소는 현재 num
                prev_num = stack.pop()
                next_greater_map[prev_num] = num
            # 현재 원소를 스택에 추가
            stack.append(num)
            
        # 스택에 남아있는 원소들은 다음 큰 원소가 없으므로 -1 (해시맵에 기본값 처리 가능)
        
        # nums1의 각 원소에 대해 해시맵에서 값을 조회하여 결과 생성
        # 해시맵에 키가 없는 경우(다음 큰 원소가 없는 경우)는 -1로 처리
        result = [next_greater_map.get(num, -1) for num in nums1]
        
        return result
```

시간복잡도: `nums1`의 길이를 N, `nums2`의 길이를 M이라고 할 때, `nums2` 순회 시 각 원소는 스택에 한 번씩 push되고 한 번씩 pop되므로 O(M)입니다. `nums1`의 각 원소에 대해 해시맵 조회는 O(1)이므로 총 O(N)입니다. 따라서 전체 시간복잡도는 O(N + M)입니다.
공간복잡도: 해시맵과 스택은 최대 M개의 원소를 저장할 수 있으므로 O(M)입니다.

## 다른 풀이 방법

완전 탐색(Brute Force) 방법을 사용할 수 있습니다. `nums1`의 각 원소 `x`에 대해 `nums2`에서 `x`의 위치를 찾은 후, 그 위치부터 오른쪽으로 순차적으로 탐색하여 `x`보다 큰 첫 번째 원소를 찾습니다. 이 경우 `nums1`의 각 원소마다 `nums2`의 길이에 비례하는 시간이 걸리므로, `nums1`의 길이를 N, `nums2`의 길이를 M이라고 할 때 시간복잡도는 O(N * M)이 됩니다. 스택을 사용하는 방법(O(N + M))에 비해 성능이 떨어지지만, 구현이 간단하다는 장점이 있습니다.

## 추가 참고사항

스택을 사용하여 '다음 큰 원소'를 찾는 기법은 Monotonic Stack(단조 스택)의 대표적인 응용 사례입니다. 이 기법은 배열의 각 원소에 대해 오른쪽(또는 왼쪽)에 있는 첫 번째로 큰(또는 작은) 원소를 찾는 다양한 문제(예: Next Greater Element II, Daily Temperatures 등)에 적용할 수 있습니다. 해시맵을 사용하여 미리 계산된 결과를 저장하면 다수의 쿼리에 대해 효율적으로 응답할 수 있으므로, `nums1`이 `nums2`의 부분 집합이라는 조건을 적극 활용하는 것이 핵심입니다.
