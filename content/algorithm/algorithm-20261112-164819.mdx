## 문제

단일 스레드 CPU에서 `n`개의 함수가 실행되며, 각 함수는 `0`부터 `n-1`까지의 고유 ID를 가진다. 함수 시작과 종료 시 로그가 기록되고, 로그는 `"id:start|end:timestamp"` 형식이다. 배타적 시간은 각 함수의 모든 호출에서의 총 실행 시간을 의미하며, 재귀 호출도 포함한다. 주어진 로그 배열을 바탕으로 각 함수 ID의 배타적 시간을 배열로 반환해야 한다. 제약 조건으로 `n`은 1 이상 100 이하, 로그 길이는 2 이상 500 이하, 타임스탬프는 0 이상 10^9 이하이며, 시작과 종료 시각은 각각 중복되지 않고 각 시작에 대응하는 종료가 존재한다.

## 접근 방법

로그를 순차적으로 처리하면서 현재 실행 중인 함수를 스택에 저장한다. 각 로그를 파싱하여 시작 로그면 스택에 push하고, 이전에 실행 중이던 함수(스택 top)에 시간을 누적한다. 종료 로그면 해당 함수를 pop하여 종료 시점까지의 시간을 계산하고, 그 시간을 해당 함수의 배타적 시간에 더한다. 이때 종료 시점의 타임스탬프를 정확히 반영하기 위해 +1을 해준다. 이 과정은 로그를 한 번씩만 처리하므로 선형 시간에 완료된다.

## 풀이

```python
def exclusiveTime(n: int, logs: list[str]) -> list[int]:
    ans = [0] * n
    stack = []          # (function_id, start_time)
    prev_time = 0

    for entry in logs:
        fid, typ, ts = entry.split(':')
        fid, ts = int(fid), int(ts)

        if typ == 'start':
            if stack:
                # 이전 함수에 시작 전까지의 시간 추가
                ans[stack[-1][0]] += ts - prev_time
            stack.append((fid, ts))
            prev_time = ts
        else:  # 'end'
            # 종료 함수 팝
            cur_id, start = stack.pop()
            # 종료 시점의 시간 포함
            ans[cur_id] += ts - prev_time + 1
            prev_time = ts + 1   # 다음 시작을 위해 +1

    return ans
```

시간 복잡도: `O(L)` (L = logs.length)  
공간 복잡도: `O(n)` (스택에 최대 n개 저장)

## 다른 풀이 방법

- **재귀 시뮬레이션**: 로그를 파싱해 중첩된 호출을 재귀 함수로 모델링하고, 반환 시점에 배타적 시간을 누적한다. 직관적이지만 재귀 깊이 제한으로 인해 비효율적일 수 있다.
- **두 패스 파싱**: 먼저 시작/종료 이벤트를 시간 순으로 정렬한 후 스택을 활용해 구간을 병합한다. 동일한 시간 복잡도를 가지지만 정렬 오버헤드가 발생한다.

## 추가 참고사항

- 종료 로그는 항상 시작 로그 다음에 오므로 스택은 항상 유효한 상태 유지.
- 타임스탬프는 정수이며, 종료 시 +1을 더해 다음 시작과의 경계를 명확히 한다.
- 재귀 호출 시 같은 ID가 여러 번 스택에 나타날 수 있으며, 각 항목은 독립적인 호출을 나타낸다.
