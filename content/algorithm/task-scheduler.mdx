## 문제

주어진 배열 `tasks`는 대문자 영문자로 라벨링된 CPU 태스크들의 목록입니다. 정수 `n`은 동일한 라벨을 가진 두 태스크 사이에 반드시 존재해야 하는 최소 간격(인터벌)을 나타냅니다. 각 인터벌에서는 하나의 태스크를 실행하거나 대기(idle)할 수 있습니다. 모든 태스크를 완료하는 데 필요한 최소 인터벌 수를 반환해야 합니다.

예를 들어 `tasks = ["A","A","A","B","B","B"]`, `n = 2`인 경우, A를 실행한 후 2개의 간격이 필요하므로 `A -> B -> idle -> A -> B -> idle -> A -> B`와 같은 순서로 실행할 수 있으며, 이때 총 8개의 인터벌이 필요합니다.

## 접근 방법

가장 빈번하게 등장하는 태스크가 전체 실행 시간을 결정하는 주요 요인입니다. 가장 많은 횟수를 가지는 태스크를 `max_count`라고 할 때, 이 태스크를 기준으로 블록을 구성할 수 있습니다.

1. 각 태스크의 등장 횟수를 카운팅합니다.
2. 가장 많이 등장한 태스크의 횟수를 `max_count`로 설정합니다.
3. `max_count`와 같은 횟수를 가지는 태스크의 종류 수를 `block_count`로 셉니다.
4. 가장 빈번한 태스크를 기준으로 형성되는 전체 블록의 길이는 `(max_count - 1) * (n + 1) + block_count`입니다.
5. 그러나 태스크의 총 개수가 이 계산값보다 큰 경우, 대기 시간이 없이 태스크가 연속으로 배치될 수 있으므로 두 값 중 큰 값을 반환합니다.

## 풀이

해시 맵을 사용하여 각 태스크의 등장 횟수를 계산한 후, 가장 빈번한 태스크의 정보를 바탕으로 수식을 적용하여 최소 시간을 계산합니다.

```python
from collections import Counter

class Solution:
    def leastInterval(self, tasks: List[str], n: int) -> int:
        # 각 태스크의 등장 횟수 카운팅
        counts = Counter(tasks)
        
        # 가장 많이 등장한 횟수
        max_count = max(counts.values())
        
        # 가장 많이 등장한 횟수와 동일한 횟수를 가지는 태스크의 수
        block_count = sum(1 for count in counts.values() if count == max_count)
        
        # 가장 빈번한 태스크를 기준으로 계산한 최소 시간
        # (최대 횟수 - 1)개의 완전한 블록 + 마지막 블록의 태스크 수
        min_time_by_freq = (max_count - 1) * (n + 1) + block_count
        
        # 실제 태스크의 총 개수와의 비교
        # 태스크가 너무 많으면 idle 없이 연속으로 실행되므로 총 개수가 최소 시간이 됨
        return max(len(tasks), min_time_by_freq)
```

시간복잡도: O(N). 태스크 배열을 순회하며 카운팅하고, 최대 26개의 알파벳에 대해 정렬 또는 탐색을 수행하므로 상수 시간에 수렴합니다. 여기서 N은 `tasks`의 길이입니다.
공간복잡도: O(1). 알파벳 대문자가 최대 26개이므로 해시 맵의 크기는 상수입니다.

## 다른 풀이 방법

우선순위 큐(Priority Queue)와 데크(Deque)를 이용한 시뮬레이션 접근법이 있습니다.

1. 각 태스크의 빈도를 카운팅하여 최대 힙(Max Heap)에 삽입합니다.
2. 매 인터벌마다 힙에서 가장 빈도가 높은 태스크를 꺼내 실행하고, 실행한 태스크는 `n`개의 간격이 지날 때까지 임시 큐에 저장합니다.
3. 간격이 `n`만큼 지나면 임시 큐의 태스크를 다시 힙에 삽입합니다.
4. 모든 태스크가 처리될 때까지 이 과정을 반복하며 인터벌 카운터를 증가시킵니다.

이 방법은 greedy 전략을 직접 시뮬레이션하는 방식으로, 빈도 기반 수식 계산보다 구현이 복잡하고 시간복잡도가 O(N log K) (K는 고유 태스크 수)로 다소 비효율적일 수 있으나, 직관적인 이해에는 도움이 됩니다.

## 추가 참고사항

- `n = 0`인 경우, 간격 제약이 없으므로 모든 태스크를 연속으로 실행할 수 있으며, 최소 시간은 태스크의 총 개수와 같습니다.
- 태스크의 종류가 매우 많고 `n`이 작을 경우, idle 시간이 발생하지 않고 모든 태스크가 연속으로 배치될 수 있습니다. 이 경우 `len(tasks)`가 정답이 됩니다.
- 이 문제는 Greedy 알고리즘의 전형적인 예시로, 가장 급한(가장 많이 남은) 작업을 먼저 처리하는 전략이 최적해를 보장함을 알 수 있습니다.
