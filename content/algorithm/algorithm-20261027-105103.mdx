## 문제

주어진 `n`개의 도시와 `isConnected` 인접 행렬을 바탕으로 서로 직접 또는 간접적으로 연결된 도시들의 그룹인 '프로빈스(Province)'의 총 개수를 반환해야 합니다. 인접 행렬 `isConnected[i][j]`가 1인 경우 도시 `i`와 도시 `j`가 직접 연결되어 있음을 의미합니다. 대칭 행렬이며 자기 자신과의 연결은 1로 주어집니다. 도시의 수 `n`은 최대 200입니다.

## 접근 방법

이 문제는 그래프 이론에서 '연결 요소(Connected Component)'의 개수를 구하는 문제와 동일합니다. 모든 도시를 정점으로 보고 연결 관계를 간선으로 간주할 수 있습니다. 각 도시를 방문하지 않은 상태에서 시작하여 깊이 우선 탐색(DFS)이나 너비 우선 탐색(BFS)을 수행하면, 한 번의 탐색으로 하나의 프로빈스에 속한 모든 도시를 방문할 수 있습니다. 모든 도시를 순회하며 탐색을 시작한 횟수를 세면 최종적인 프로빈스의 개수를 알 수 있습니다.

## 풀이

DFS를 사용하여 각 도시를 루트로 삼아 탐색을 수행하는 방식을 구현합니다. 방문한 도시를 기록하기 위해 `visited` 배열을 사용합니다. `0`부터 `n-1`까지의 모든 인덱스에 대해 방문 여부를 확인하고, 아직 방문하지 않은 도시가 발견되면 프로빈스 카운터를 증가시킨 후 해당 도시를 시작점으로 DFS를 실행합니다. DFS 내부에서는 현재 도시와 연결된 모든 인접한 도시들을 재귀적으로 방문 처리합니다.

```python
class Solution:
    def findCircleNum(self, isConnected: list[list[int]]) -> int:
        n = len(isConnected)
        visited = [False] * n
        provinces = 0
        
        def dfs(city: int) -> None:
            visited[city] = True
            for neighbor in range(n):
                if isConnected[city][neighbor] == 1 and not visited[neighbor]:
                    dfs(neighbor)
        
        for i in range(n):
            if not visited[i]:
                provinces += 1
                dfs(i)
                
        return provinces
```

시간복잡도: $O(n^2)$입니다. 인접 행렬의 크기가 $n \times n$이며, 각 도시와 그 연결 상태를 확인하는 데 상수 시간이 걸리지만 전체 행렬을 참조할 수 있으므로 $n^2$에 비례합니다.
공간복잡도: $O(n)$입니다. 방문 상태를 저장하는 배열과 재귀 호출 스택의 깊이가 최대 $n$이므로 필요합니다.

## 다른 풀이 방법

BFS(너비 우선 탐색)를 사용할 수 있습니다. DFS와 달리 재귀 호출 대신 큐(Queue)를 사용하여 연결된 도시들을 순차적으로 방문합니다. 스택 오버플로우 위험이 있는 매우 깊은 그래프에서는 BFS가 더 안정적일 수 있습니다. 또한, Union-Find(서로소 집합) 자료구조를 활용하여 연결된 도시들을 병합하는 방법도 있습니다. Union-Find는 각 도시를 초기에 서로 다른 집합으로 두고, 연결된 두 도시의 루트를 합치는 과정을 반복한 후, 최종적으로 루트 노드의 개수를 세어 해답을 구합니다. Union-Find의 경우 시간복잡도는 거의 $O(n^2 \alpha(n))$에 가깝고, 구현이 다소 길어질 수 있으나 그래프 구조가 동적으로 변하는 경우 유용합니다.

## 추가 참고사항

문제에서 주어진 제약 조건 `isConnected[i][j] == isConnected[j][i]`는 그래프가 무방향 그래프임을 보장합니다. 또한 `isConnected[i][i] == 1`이므로 모든 도시는 자기 자신과 연결되어 있어 탐색 시작점으로 항상 유효합니다. `n`의 범위가 작아(최대 200) DFS/BFS/Union-Find 모두 충분히 효율적으로 동작합니다. 인접 행렬 대신 인접 리스트로 그래프를 표현하면 간선의 수 $E$에 따라 $O(V+E)$로 최적화할 수 있으나, 문제 입력이 행렬 형태이므로 행렬을 그대로 사용하는 것이 자연스럽습니다.
