## 문제

주어진 문자열 `s`와 정수 `k`가 입력으로 제공됩니다. 문자열 내의 임의의 문자를 다른 대문자 영어 문자로 변경할 수 있으며, 이 작업은 최대 `k`번 수행할 수 있습니다. 변경 작업을 통해 얻을 수 있는 동일한 문자로만 구성된 부분 문자열의 최대 길이를 반환해야 합니다.

예를 들어, `s`가 "ABAB"이고 `k`가 2인 경우, 두 개의 'A'를 'B'로 변경하거나 그 반대로 변경하면 전체 문자열 "BBBB"가 되어 길이가 4가 됩니다. `s`가 "AABABBA"이고 `k`가 1인 경우, 중간에 있는 'A'를 'B'로 변경하면 "AABBBBA"가 되며, 이때 부분 문자열 "BBBB"의 길이는 4가 됩니다.

문자열 `s`의 길이는 10^5 이하이며, 대문자 영어 문자로만 구성됩니다. `k`는 0 이상 `s`의 길이 이하의 정수입니다.

## 접근 방법

이 문제는 "최대 k개의 다른 문자를 포함하는 가장 긴 부분 문자열"을 찾는 것과 동일합니다. 슬라이딩 윈도우 기법을 사용하여 부분 문자열의 시작점과 끝점을 이동하며 조건을 만족하는 최대 길이를 구할 수 있습니다.

윈도우 내의 가장 빈번하게 등장하는 문자의 개수를 `max_freq`라고 합시다. 현재 윈도우의 크기가 `window_size`일 때, 나머지 `window_size - max_freq`개의 문자를 모두 가장 빈번한 문자로 변경하는 데 필요한 비용이 `k` 이하인지 확인합니다. 만약 필요한 비용이 `k`를 초과한다면, 윈도우의 크기를 유지하거나 줄이기 위해 시작점을 오른쪽으로 이동시켜야 합니다. 조건을 만족하는 동안 윈도우의 끝점을 오른쪽으로 이동시키며 최대 길이를 업데이트합니다.

이 방식은 윈도우 크기가 줄어들 필요가 없으므로, 끝점이 문자열의 끝까지 이동하는 동안 최대 길이를 효율적으로 찾을 수 있습니다.

## 풀이

문자열을 순회하며 슬라이딩 윈도우를 유지합니다. 해시맵(또는 배열)을 사용하여 현재 윈도우 내 각 문자의 등장 횟수를 기록합니다. 윈도우의 끝점을 하나씩 늘려가며 가장 흔한 문자의 등장 횟수를 갱신합니다. 만약 현재 윈도우에서 변경이 필요한 문자 수(`window_size - max_freq`)가 `k`를 초과하면, 시작점을 오른쪽으로 이동시켜 윈도우 크기를 일정하게 유지하거나 줄입니다. 이 과정에서 기록된 최대 윈도우 크기가 정답이 됩니다.

```python
def characterReplacement(s: str, k: int) -> int:
    count = {}
    max_freq = 0
    start = 0
    
    for end in range(len(s)):
        # 현재 문자의 등장 횟수 증가
        count[s[end]] = count.get(s[end], 0) + 1
        # 윈도우 내 가장 빈번한 문자의 등장 횟수 갱신
        max_freq = max(max_freq, count[s[end]])
        
        # 현재 윈도우 크기에서 가장 흔한 문자를 제외한 나머지 문자의 수가 k보다 크면
        # 윈도우의 시작점을 오른쪽으로 이동시켜야 함
        if (end - start + 1) - max_freq > k:
            count[s[start]] -= 1
            start += 1
            
    return len(s) - start
```

시간복잡도: O(N)입니다. 여기서 N은 문자열 `s`의 길이입니다. 끝점 `end`가 한 번만 순회하며, 시작점 `start`도 최대 N번까지 이동합니다.
공간복잡도: O(1)입니다. 대문자 영어 문자의 종류가 26개로 고정되어 있으므로 해시맵의 크기는 상수입니다.

## 다른 풀이 방법

완전탐색(Brute Force) 방식으로 모든 가능한 부분 문자열에 대해 변경 비용을 계산할 수 있습니다. 각 시작점 `i`와 끝점 `j`에 대해 해당 부분 문자열의 문자 빈도수를 계산하고, `k`번 변경으로 모두 동일한 문자로 만들 수 있는지 확인합니다. 이 경우 부분 문자열의 빈도수 계산을 매번 수행하므로 시간복잡도가 O(N^3) 또는 O(N^2)이 되어 제한 시간 내에 실행되지 않을 수 있습니다.

또한, 시작점을 고정하고 끝점을 늘려가며 조건을 만족하는 최대 길이를 찾는 방식(O(N^2))도 가능합니다. 하지만 슬라이딩 윈도우 기법은 윈도우 크기가 감소하지 않는 성질을 이용해 한 번의 순회로 해결하므로 O(N)의 시간복잡도를 가지며 훨씬 효율적입니다.

## 추가 참고사항

이 문제의 핵심은 "변경이 필요한 문자의 수"를 효율적으로 추적하는 것입니다. 슬라이딩 윈도우에서 시작점을 이동시킬 때 `max_freq`를 다시 계산하지 않고 현재 값을 유지하는 것이 중요합니다. 왜냐하면 윈도우 크기가 줄어들더라도 가장 빈번한 문자의 등장 횟수는 절대 증가하지 않으며, 오히려 감소하거나 유지되기 때문입니다. 최대 길이를 구하는 데에는 `max_freq`의 정확한 현재값보다는 과거에 기록된 최대값이 더 유용한 하한선 역할을 합니다.

문자열의 길이가 10^5로 크므로 O(N^2) 이상의 알고리즘은 시간 초과(TLE)가 발생할 수 있습니다. 따라서 O(N) 시간복잡도를 갖는 슬라이딩 윈도우 접근이 필수적입니다. 또한, 입력 문자열이 대문자 영어로만 구성되어 있으므로 해시맵 대신 크기가 26인 배열을 사용하여 구현할 수도 있습니다.
