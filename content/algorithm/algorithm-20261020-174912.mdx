## 문제

정수 배열 `nums`가 주어집니다. 한 번의 연산으로 배열의 요소를 1만큼 증감시킬 수 있습니다. 모든 배열 요소의 값을 동일하게 만들기 위해 필요한 최소 연산 횟수를 반환해야 합니다. 테스트 케이스의 답은 32비트 정수 범위 내에 있습니다.

예를 들어, 입력이 `[1, 2, 3]`일 때, `[1, 2, 3]` -> `[2, 2, 3]` -> `[2, 2, 2]`로 두 번의 연산이 필요합니다. 입력이 `[1, 10, 2, 9]`일 경우, 최소 16번의 연산이 필요합니다.

배열의 길이는 `1` 이상 `10^5` 이하이며, 각 요소의 값은 `-10^9` 이상 `10^9` 이하입니다.

## 접근 방법

모든 요소를 어떤 값 `x`로 같게 만들 때의 총 이동 비용은 $\sum |nums[i] - x|$입니다. 이 절댓값 합의 최솟값을 구하는 문제는 일차원 공간에서 여러 점까지의 거리의 합을 최소화하는 문제와 동일합니다.

수학적으로, 주어진 점들까지의 거리의 합이 최소가 되는 지점은 해당 점들의 **중앙값(Median)**입니다. 정렬된 배열에서 중앙값은 배열의 중간에 위치한 원소입니다. 따라서 배열을 정렬한 후 중앙값을 찾고, 모든 원소와의 차이의 절댓값을 합산하면 최소 이동 횟수를 구할 수 있습니다.

## 풀이

배열을 정렬하고 중앙값을 찾은 후, 각 원소와의 차이를 누적하여 계산합니다.

```python
class Solution:
    def minMoves2(self, nums: List[int]) -> int:
        nums.sort()
        median = nums[len(nums) // 2]
        moves = 0
        for num in nums:
            moves += abs(num - median)
        return moves
```

시간복잡도: 배열 정렬에 $O(N \log N)$이 소요되고, 이후 순회하며 차이를 계산하는 데 $O(N)$이 소요되므로 전체 $O(N \log N)$입니다.
공간복잡도: 정렬 알고리즘의 구현에 따라 다르나 일반적으로 $O(1)$ 또는 $O(\log N)$입니다.

## 다른 풀이 방법

빠른 선택 알고리즘(Quickselect)을 사용하여 정렬 없이 중앙값만 찾을 수 있습니다. Quickselect은 평균 시간복잡도 $O(N)$으로 k번째 작은 원소를 찾을 수 있습니다.

이 방법을 사용하면 정렬 단계의 $O(N \log N)$을 제거하고 $O(N)$으로 중앙값을 찾을 수 있습니다. 이후 중앙값을 기준으로 차이를 계산하는 과정은 동일하게 $O(N)$이므로, 전체 시간복잡도는 평균 $O(N)$이 됩니다. 최악의 경우 $O(N^2)$이지만, 랜덤 피벗 선택 등을 통해 이를 방지할 수 있습니다.

```python
import random

class Solution:
    def minMoves2(self, nums: List[int]) -> int:
        def quickselect(arr, k):
            pivot = random.choice(arr)
            left = [x for x in arr if x < pivot]
            mid = [x for x in arr if x == pivot]
            right = [x for x in arr if x > pivot]
            
            if k < len(left):
                return quickselect(left, k)
            elif k < len(left) + len(mid):
                return pivot
            else:
                return quickselect(right, k - len(left) - len(mid))
        
        n = len(nums)
        median = quickselect(nums, n // 2)
        return sum(abs(num - median) for num in nums)
```

## 추가 참고사항

이 문제와 유사하게 모든 요소를 1씩 증가시키는 연산만 허용하는 문제(LeetCode 453)가 있습니다. 두 문제는 연산의 제약 조건이 다르므로 해법이 완전히 다릅니다. 453번은 "전체 요소 중 최솟값을 제외한 나머지 요소를 1씩 증가"시키는 것이 "전체 요소를 1씩 증가"시키는 것과 동일하므로, 모든 요소를 최솟값으로 맞추는 것이 최소 이동 횟수가 됩니다. 반면, 본 문제(462번)는 증감 모두 허용하므로 중앙값을 기준으로 합니다.

참고 자료의 범위 내에서, 답이 32비트 정수 내에 들어감은 보장되지만, 중간 계산 과정에서 64비트 정수(파이썬은 기본 정수형이 무한 정밀도이므로 문제없음)가 필요할 수 있는 다른 언어에서는 주의가 필요합니다.
