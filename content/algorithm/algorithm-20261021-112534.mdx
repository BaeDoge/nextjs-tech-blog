## 문제

각 아이는 만족할 최소 쿠키 크기인 욕구 지수 `g`를 가지며, 각 쿠키는 고유한 크기 `s`를 가집니다.
한 아이에게는 최대 하나의 쿠키만 할당할 수 있습니다.
쿠키의 크기 `s[j]`가 아이의 욕구 지수 `g[i]`보다 크거나 같을 때, 해당 아이는 만족하게 됩니다.
목표는 만족하는 아이의 수를 최대화하여 그 값을 출력하는 것입니다.
입력 배열 `g`와 `s`의 길이는 최대 30,000이며, 요소 값은 정수 범위 내입니다.

## 접근 방법

문제를 만족하는 아이의 수를 최대화하는 것이므로, 가능한 한 많은 아이를 만족시켜야 합니다.
작은 욕구 지수를 가진 아이부터 작은 쿠키로 채워나가는 것이 효율적입니다.
즉, 욕구 지수 배열 `g`와 쿠키 크기 배열 `s`를 모두 오름차순으로 정렬합니다.
두 개의 포인터를 사용하여 `g`의 현재 아이와 `s`의 현재 쿠키를 비교합니다.
현재 쿠키가 현재 아이의 욕구 지수보다 크거나 같다면, 그 쿠키를 아이에게 할당하고 두 포인터를 모두 앞으로 이동합니다.
현재 쿠키가 아이의 욕구 지수보다 작다면, 그 쿠키는 현재 아이를 만족시킬 수 없으므로 다음 더 큰 쿠키를 보기 위해 쿠키 포인터만 이동합니다.
이 과정을 쿠키나 아이 중 하나가 끝날 때까지 반복합니다.

## 풀이

정렬 후 두 포인터를 이용한 그리디 매칭을 구현합니다.
시간 복잡도는 정렬에 $O(N \log N + M \log M)$이 소요되며, 매칭 과정은 $O(N + M)$입니다.
공간 복잡도는 정렬 알고리즘의 구현에 따라 다르나 일반적으로 $O(1)$ 또는 $O(\log N)$입니다.

```python
class Solution:
    def findContentChildren(self, g: list[int], s: list[int]) -> int:
        # 욕구 지수와 쿠키 크기를 오름차순으로 정렬
        g.sort()
        s.sort()
        
        child_idx = 0
        cookie_idx = 0
        n = len(g)
        m = len(s)
        
        # 두 배열의 끝까지 탐색
        while child_idx < n and cookie_idx < m:
            # 현재 쿠키가 현재 아이의 욕구 지수를 만족시킬 수 있다면
            if s[cookie_idx] >= g[child_idx]:
                # 아이를 만족시켰으므로 다음 아이로 이동
                child_idx += 1
            # 쿠키는 사용되었든 사용하지 않았든 다음 쿠키로 이동
            cookie_idx += 1
            
        return child_idx
```

- 시간 복잡도: $O(N \log N + M \log M)$ (정렬 비용이 주를 이룸)
- 공간 복잡도: $O(1)$ 또는 $O(\log N)$ (정렬 구현에 따라 다름, 추가 배열 사용 안 함)

## 다른 풀이 방법

이 문제는 그리디 성질과 최적 부분 구조를 가지므로, 다른 접근법으로는 완전 탐색이 가능합니다.
모든 가능한 쿠키 할당 조합을 시도하여 만족하는 아이의 최대 수를 찾는 방식입니다.
하지만 조합의 수가 지수적으로 증가하므로 시간 복잡도가 $O(2^{\min(N, M)})$ 이상이 되어 실용적이지 않습니다.
또한 우선순위 큐(Priority Queue)를 사용하여 최소 욕구 지수와 최소 쿠키 크기를 계속 추출할 수도 있으나,
정렬과 동일한 $O(N \log N)$ 시간 복잡도를 가지며 구현이 더 복잡해집니다.
따라서 정렬과 두 포인터 기법이 가장 효율적이고 간단한 해결책입니다.

만약 큰 욕구를 가진 아이부터 처리한다면, 작은 쿠키를 낭비할 가능성이 높아져 최적해를 보장할 수 없습니다.
